# gdd-write

## 触发时机

用户说"帮我写 XX 系统的 GDD"、"帮我起一个 XX 的设计文档"，或者提供了玩法方向、体验目标草稿需要展开成完整 GDD 时。

## 边界

- 本 Skill 只负责写新文档；审核已有文档请用 `gdd-review`
- 本 Skill 按四层框架推导，每步暂停确认后再继续，不一次性输出全文
- 本 Skill 不替代策划的判断；AI 推导的结果需要策划逐步确认

## 执行步骤

### Step 0：读取标准 + 确认输入

1. 读取 `/Users/mt/Documents/Codex/reference/部门标准/策划/gdd/GDD写作标准.md`，理解四层框架、禁止行为和 Self-Review 判据
2. 读取 `/Users/mt/Documents/Codex/reference/部门标准/策划/gdd/GDD输出模板.md`，确认输出格式
3. 向用户确认以下输入（已有的直接采用，未给的简短问）：
   - 系统名称
   - 玩法方向（这个系统是做什么的）
   - 体验目标草稿（如果有）
   - 目标文档路径（写到哪里）
4. 从目标文档路径推断项目根目录（取 `workspace/projects/{项目类型}/{项目名}/` 层级），查找 `项目标准.md`：
   - 找到：读取，后续步骤中规则层约束优先，项目标准在此基础上叠加（术语、接口边界、额外章节、特殊约束均纳入）
   - 找不到：跳过，纯走规则层

### Step 1：体验目标（暂停确认）

按格式"玩家在[场景]应感受到[具体情绪/认知状态]，因为[设计理由]"写出所有体验目标句。

输出体验目标后停下，等待用户确认或修改，再继续。

禁止使用"有趣""好玩""爽"作为情绪/认知状态描述。

### Step 2：流程图（暂停确认）

1. 画整体流程图（Mermaid flowchart，覆盖所有顶层阶段，标注循环条件和数据流）
2. 画各主要阶段子流程图（每个包含玩家操作的阶段独立一张）
3. 对每个阶段做删除测试：删掉它，Step 1 的体验目标还能实现吗？
4. 同步写出功能模块概述（2.1.5），作为节点定义的目录

流程图完成后暂停，等待用户确认结构再继续。

每个节点必须在流程图中标注所有退出路径（正常完成 / 主动中断 / 失败 / 异常）。

### Step 3：节点定义（暂停确认）

按 2.1.5 功能模块概述的列表顺序，逐模块用自然小节描述：
- 开头一句话说明谁在何时操作、频率
- 配置项用参数表（配置项 / 推荐默认 / 可配置范围 / 强制规则）
- 执行逻辑写入 `> 系统自动执行` 块（面向可读性）
- 框架字段不出现在标题或表头

含类型枚举节点（如"战斗房/精英房/事件房"），每种类型必须独立定义触发操作、内容规格、所有退出路径。

委托子系统的节点只写接口边界（传入什么 → 返回什么 → 外层如何恢复），不重写子系统内部规则。

节点定义完成后暂停，等待用户确认再继续。

### Step 4：规则层（暂停确认）

写三类规则（集中在规则层，不分散在节点定义中）：
- a) 操作规则：格式"当[触发条件]时，系统必须/禁止[行为]"，按系统阶段分组
- b) 规则优先级：多条规则冲突时的处理顺序，或声明"各规则独立生效，无优先级冲突"
- c) 异常处理：系统级异常（网络中断/服务端报错）的恢复策略，不含节点内的默认值兜底

对每条操作规则问删除测试："删掉这条规则，系统行为还有明确定义吗？"无法定义 → 保留。

规则层完成后暂停，等待用户确认再继续。

### Step 5：拼装示例 + 自检

1. 写覆盖第一层所有体验目标的拼装示例（至少 2 个，每个含决策理由）
2. 对照写作标准 Self-Review 五项判据做自检：
   - 判据一：体验目标存在
   - 判据二：流程图与功能模块概述存在且完整
   - 判据三：节点定义与规则层完整
   - 判据四：拼装示例存在且可操作
   - 判据五：内容配置区合规（若有）
3. 输出自检结论：每项"通过 / blocking issue（含位置）"
4. 有 blocking issue → 返回对应 Step 修改，不输出最终文档

### Step 6：输出最终文档

自检全部通过后，按 GDD 输出模板格式输出完整文档，写入用户指定路径。

## 质量检查

- [ ] 体验目标句格式合规（含场景/情绪/设计理由，无"有趣好玩爽"）
- [ ] 流程图为 Mermaid flowchart，包含整体图和各主要阶段子流程图两层
- [ ] 每个节点标注了所有退出路径（正常 / 中断 / 失败 / 异常）
- [ ] 节点定义未使用"字段/内容"二列表格
- [ ] 所有强制规则集中在规则层，未分散在节点描述中
- [ ] 规则层与节点定义 `系统自动执行` 块对同一规则的描述不矛盾
- [ ] 拼装示例覆盖所有体验目标，含决策理由
- [ ] Self-Review 五项判据全部通过后才输出最终文档
