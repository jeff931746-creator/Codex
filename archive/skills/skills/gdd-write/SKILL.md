# gdd-write

## 这套入口如何工作

本 Skill 是执行入口，不拥有标准解释权或策划决策权。

- 用户决策权以 `reference/部门标准/策划/策划决策权规则.md` 为准。

- 状态、返回、checkpoint 和上下文装配以 `多Agent设计文档调度规则.md` 为准。
- Agent 阶段质量检查和用户确认材料以当前节点原则为准。
- `GDD输出模板.md` 只提供正文占位结构。

## 执行流程

1. 读取必读标准，只用路由上下文确认任务包。
2. G1/G2 产出目的材料和质询，主 Agent 整理选项、影响和推荐后停在 U1。
3. 用户明确确认 U1 后，记录用户原话，再执行 G3。
4. G3 产出候选，停在 U2 等用户选择。
5. 用户确认 U2 后执行 G4，停在 U3 等用户确认功能、规则、状态和 UE 方向。
6. 用户确认 U3 后执行 G5；如启用 G5-D，只生成候选稿。
7. C4 报告正文差异和风险，停在 U4。用户确认具体版本并授权写入后，才能进入 G6 或覆盖正式文档。
8. G6 只输出交付状态检查报告。正式 GDD 再调用非生产者 `gdd-review` 输出独立审核报告。
9. 停在 U5，由用户决定交付、带风险接受、指定返回阶段、继续补充或停止。
10. 只执行用户明确决定，不自行打回、选择或宣布通过。

## 权限边界

- Agent 只产材料、候选、正文、检查结果和建议。
- U1-U5 只能由用户确认；任何 Agent 或模型不能代签。
- 用户说“继续”不自动确认尚未明确选择的策划内容。
- Agent 可以指出标准不符合或事实冲突，但只能把处理选项交给用户。
- 写作 Agent 不重新设计；审核 Agent 不修改正文、不作最终交付决定。
