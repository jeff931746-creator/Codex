# gdd-review

## 这套入口如何工作

本 Skill 是独立检查入口，不拥有策划决策权、文档修改权或正式通过权。

- 用户决策权以 `策划决策权规则.md` 为准。
- 流程职责以 `多Agent设计文档工作流.md` 为准。
- 检查维度以 `子Agent/独立审核原则.md` 为准。
- `GDD输出模板.md` 只用于确认交付结构。

## 必读内容

1. `reference/部门标准/策划/策划决策权规则.md`
2. `reference/部门标准/策划/gdd/多Agent设计文档工作流.md`
3. `reference/部门标准/策划/gdd/多Agent设计文档判断原则/子Agent/独立审核原则.md`
4. `reference/部门标准/策划/gdd/GDD输出模板.md`
5. 目标文档及 U1-U4、G6 证据。

## 执行步骤

1. 确认审核者未参与当前版本的 G5、G5-D 或问题修复。
2. 检查用户确认记录、目的与手段承接、功能聚焦、关系表达、功能完整性和正文边界。
3. 每个问题标注位置、证据、违反原则、影响和建议处理阶段。
4. 给出风险等级和推荐，但不得宣布“正式通过”“打回”或自行修改正文。
5. 把报告交给 U5，由用户决定交付、带风险接受、指定返回阶段或停止。

## 输出

```markdown
## [功能名称] 独立审核报告

**审核类型**：Self-Review / 过程检查 / 正式独立审核
**检查摘要**：未发现问题 / 存在问题（不具有交付决定效力）

### 问题与风险

- [文档位置]：[问题]；依据：[节点原则]；影响：[影响]；建议处理阶段：[阶段]

### 推荐

- 推荐动作及理由

### 等待用户决定

- 交付 / 带风险接受 / 指定返回阶段 / 停止
```

## 边界

- 只审核，不修改文档，不补设计。
- 不自定义判据，不让其他专业标准覆盖 GDD 协作原则。
- 不把审核报告写回 GDD。
- 不输出具有决定效力的“通过”“不通过”或“打回”。
- 用户最终决定必须另行记录为 U5。

- [ ] 已读取策划决策权规则、工作流、独立审核原则和输出模板。
