# gdd-review

## 触发时机

用户要求审核 GDD、设计文档、功能方案或“案子”，或者正式 GDD 在 G6 后进入独立审核时使用。

## 执行定位

本 Skill 是审核执行入口，不拥有 GDD 标准解释权。

- 流程和阶段职责以 `多Agent设计文档工作流.md` 为准。
- 审核判断以 `多Agent设计文档判断原则/子Agent/独立审核原则.md` 为准。
- 发现具体上游问题时，读取对应 M1-M4、G5 或 G6 判断原则确认归属。
- `GDD输出模板.md` 只用于确认交付结构，不提供判断标准。

不得在本 Skill 中复制或另建节点判断标准。

## 必读内容

1. `/Users/mt/Documents/Codex-codex-work/reference/部门标准/策划/gdd/多Agent设计文档工作流.md`
2. `/Users/mt/Documents/Codex-codex-work/reference/部门标准/策划/gdd/多Agent设计文档判断原则/子Agent/独立审核原则.md`
3. `/Users/mt/Documents/Codex-codex-work/reference/部门标准/策划/gdd/GDD输出模板.md`
4. 目标文档和对应的 M1-M4、G6 流程证据。

如独立审核原则要求确认某个阶段问题，再读取该阶段判断原则；不要一次性加载全部原则。

## 执行步骤

1. 确认本次是 Self-Review、过程自检还是正式独立审核。
2. 正式独立审核先确认审核者未参与当前版本的 G5 写作、G5-D 文本优化、候选稿修改或 blocking issue 修复。
3. 按独立审核原则检查流程证据、目的与手段承接、功能聚焦、关系表达、功能完整性和正文边界。
4. 每个问题标注具体位置、违反的节点原则、问题所属阶段和打回目标。
5. 输出独立审核报告，不修改目标 GDD，不把报告追加到正文。

## 输出

```markdown
## [功能名称] 审核报告

**审核类型**：Self-Review / 过程自检 / 正式独立审核
**结论**：正式通过 / 需打回修改 / 已完成自检，未完成正式独立验收

### Blocking issues

- [文档位置]：[问题]；依据：[节点原则]；打回：[目标阶段]

### 非阻塞项

- [文档位置]：[问题]
```

没有 blocking issue 时明确写“未发现 blocking issue”。Self-Review 或过程自检不得输出“正式通过”。

## 边界

- 只审核，不修改文档，不补设计。
- 不自定义判据，不让其他专业标准覆盖 GDD 协作原则。
- 不把审核报告写回 GDD。
- 非生产者身份无法确认时，不输出“正式通过”。

## 自检

- [ ] 已读取工作流、独立审核原则和输出模板。
- [ ] 已按需读取问题所属阶段的判断原则。
- [ ] 已确认审核身份。
- [ ] 每条 blocking issue 都有位置、原则依据和打回目标。
- [ ] 审核报告与 GDD 正文分离。
