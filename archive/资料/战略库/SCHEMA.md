## 一、库的定位

战略库收集游戏行业战略情报——买量策略、市场趋势、产品动态、立项参考、行业方法论。

用途：
- 可检索的情报沉淀（按主题/时间/标签查找历史信息）
- 趋势追踪与决策支撑（观察行业变化，辅助立项和运营判断）

**主数据**：每篇文章/报告一份 `.md` 文件，带 YAML frontmatter，放在 `条目/` 下。
**索引**：从主数据派生，不手工维护。

---

## 二、YAML Frontmatter

继承通用标准的必填字段，叠加战略库专有字段。

```yaml
---
# === 身份（继承通用）===
entry_id: INTEL-2026-06-03-001   # 格式：INTEL-{日期}-{序号}
title: ""
date: ""
source_name: ""
url: ""

# === 文章级专属（从通用标准 v1-v2 下放）===
source_author: ""          # 作者
content_type: ""           # 见 §三（枚举从通用标准继承）
core_thesis: ""            # 核心论点，1-3 句
actionable_insights: []    # 可行动洞察，0-3 条

# === 质量评估（继承通用）===
source_credibility: ""
bias_note: ""

# === 筛选（仅战略库适用）===
value_score: 0             # 1-5，≤2 不入库

# === 战略库专有：分类 ===
category: ""               # 必填，单选，见 §四
tags: []                   # 必填，2-5 个

# === 战略库专有：关联 ===
related_entries: []        # 选填
related_libraries: []      # 选填

# === 反馈（继承通用）===
user_rating: null           # 5=极有用 ... 1=误收
user_note: ""

# === 元数据（继承通用）===
collected_date: ""
---
```

### 正文结构（文章级专属）

1. **核心论点**（必须）：展开 core_thesis
2. **关键信息**（必须）：结构化要点，5-10 条
3. **评估**（推荐）：信息质量、偏见、局限性
4. **可行动洞察**（推荐）：展开 actionable_insights

## 二-bis、入库质量标准

### 收录（满足任一即入库，且 value_score ≥ 3）

| # | 条件 | 说明 |
|---|---|---|
| S1 | **含一手数据** | 有原始数据表格、具体数字、明确口径（非"据了解"） |
| S2 | **平台政策/规则变化** | 微信/抖音/Google/Apple 等平台的政策、算法、规则变更 |
| S3 | **买量/投放策略洞察** | 可直接用于调整投放策略的方法、案例、数据 |
| S4 | **赛道级趋势判断** | 某品类/赛道的增长/衰退/竞争格局变化，有数据支撑 |
| S5 | **重大商业事件** | 影响行业格局的融资、收购、上市、倒闭（金额过亿或头部公司） |

### 排除（命中任一则不入库）

| # | 条件 | 说明 |
|---|---|---|
| E1 | **纯新闻转述** | 只是转述已知事件，无新数据、无分析、无洞察 |
| E2 | **大厂八卦/人事** | 高管变动、公司文化等不影响市场格局的新闻 |
| E3 | **单产品软文** | 明显为某产品推广目的撰写，信息选择性呈现 |
| E4 | **无数据的观点文** | 纯个人看法，无数据支撑，无可验证的结论 |
| E5 | **PC/主机/3A 行业新闻** | 与手游/小游戏/IAA 赛道无直接关联的 PC/主机行业动态 |

### 判定示例

| 文章 | 收录？ | 原因 |
|---|---|---|
| "5月抖音小游戏畅销榜Top100" | ✅ S1 | 一手榜单数据 |
| "腾讯IAA小游戏投放洞察"(演讲实录) | ✅ S1+S3 | 平台方一手数据+投放方法论 |
| "GDC 2026 趋势报告" | ✅ S4 | 行业趋势+数据 |
| "王者荣耀世界S1畅销榜排名" | ❌ E5 | 大厂手游动态 |
| "任天堂被偷家联想G02掌机" | ❌ E5 | PC/主机硬件新闻 |
| "阅文收购艺画开天" | ❌ E2 | IP/资本新闻，不影响游戏市场格局 |
| "独立游戏开发者赚了多少" | ❌ E4 | 个人故事集锦，无可行动洞察 |

## 三、内容类型枚举（content_type，从通用标准继承）

| 值 | 含义 |
|---|---|
| 数据报告 | 以数据为主体的报告、白皮书 |
| 行业分析 | 基于数据或案例的趋势分析 |
| 演讲实录 | 会议/峰会的演讲内容 |
| 案例复盘 | 具体项目/产品的复盘 |
| 政策公告 | 平台政策、法规变化 |
| 观点评论 | 个人观点为主 |
| 产品软文 | 推广目的的内容 |
| 方法论 | 可复用框架或方法 |

## 四、分类体系（category）

| 值 | 覆盖内容 | 判定线索 |
|---|---|---|
| 买量与投放 | 广告投放策略、素材趋势、平台算法变化、ROI 优化、投放工具 | 文章主体讨论广告投放、素材制作、获客成本 |
| 市场与趋势 | 品类数据、平台政策、大盘变化、用户行为趋势 | 文章主体是市场数据或行业宏观趋势 |
| 产品与设计 | 玩法创新、变现模型、留存策略、系统设计思路 | 文章主体讨论具体产品的设计或商业化 |
| 立项参考 | 赛道分析、竞争格局、团队适配、立项判断框架 | 文章内容可直接用于立项决策 |
| 方法论 | 行业方法论、框架、可复用的思维模型 | 文章提出可复用的框架或结构化方法 |

**判定规则**：
- 一篇文章只选一个主分类，取占比最大的主题
- 跨分类的次要主题通过 `tags` 覆盖
- 无法归类时写 `市场与趋势`（最宽泛的兜底分类）

## 四、标签（tags）

半开放标签体系。首批种子标签：

| 分类 | 种子标签 |
|---|---|
| 买量与投放 | 副玩法、素材策略、平台算法、AI投放、IAA、IAP、混合变现、投放自动化、创意优化 |
| 市场与趋势 | 小游戏、出海、品类数据、用户增长、平台政策、微信生态、iOS、Google Play |
| 产品与设计 | SLG、RPG、放置、卡牌、塔防、肉鸽、休闲、留存、付费设计、社交系统 |
| 立项参考 | 赛道选择、团队规模、题材选型、风险评估、蓝海、红海 |
| 方法论 | 数据分析、用户研究、A/B测试、漏斗模型、生命周期 |

新增标签自由添加，后续通过索引脚本统计合并。

## 五、分类专项校验

在通用质量判据（5 条）基础上，按分类叠加专项检查。

### 买量与投放

| # | 判据 | 通过 | 不通过 |
|---|---|---|---|
| B1 | 数据口径标注 | 文中涉及的投放数据（CPM/ROI/CPI 等）已标注口径（平台/时间/品类/地区） | 有数据无口径，无法判断适用范围 |
| B2 | 平台方 vs 第三方区分 | 数据来自平台官方还是第三方估算已标注 | 混为一谈 |

### 市场与趋势

| # | 判据 | 通过 | 不通过 |
|---|---|---|---|
| M1 | 时间范围明确 | 市场数据标注了统计时间范围 | 无时间范围的数据 |
| M2 | 数据来源标注 | 数据来自哪个平台/报告/机构已标注 | "据了解"、"行业数据显示"无具体来源 |

### 产品与设计

| # | 判据 | 通过 | 不通过 |
|---|---|---|---|
| P1 | 信息层级区分 | 区分了一手体验、官方信息、二手转述 | 把二手转述当成一手信息 |

### 立项参考

| # | 判据 | 通过 | 不通过 |
|---|---|---|---|
| L1 | 结论推理链 | 立项相关结论有推理过程，假设显式 | 结论直给无推理，或隐含未声明的假设 |

### 方法论

| # | 判据 | 通过 | 不通过 |
|---|---|---|---|
| F1 | 适用边界 | 方法论标注了适用条件和局限 | 框架描述为万能，无边界说明 |

## 六、文件命名与目录

```
战略库/
├── README.md
├── SCHEMA.md              本文件
├── 条目/
│   └── {YYYY-MM-DD}_{简称}.md    每篇文章一个文件
└── 索引/
    ├── 按时间.md           按月倒序，最新在前
    ├── 按分类.md           按 category 分组
    └── 按标签.md           按 tag 聚合
```

文件命名规则：
- 日期取 `collected_date`
- 简称取文章核心主题的 2-6 个字，如 `2026-06-03_IAA小游戏投放破局.md`
- 特殊字符替换：`/ \ : * ? " < > |` 替换为下划线

## 七、索引派生规则

索引从 `条目/` 下所有 `.md` 文件的 YAML frontmatter 派生，不手工编辑。

**按时间索引**：按 `collected_date` 倒序，每月一个段落，每条格式：
```
- [{title}](../条目/{filename}) — {source_name} | {category} | {tags 前 3 个}
```

**按分类索引**：按 `category` 分组，组内按 `collected_date` 倒序。

**按标签索引**：按 `tags` 聚合，同一条目可出现在多个标签下。

初期条目少时，索引手动更新（由 Skill 自动完成）。条目超过 50 条后考虑写派生脚本。
