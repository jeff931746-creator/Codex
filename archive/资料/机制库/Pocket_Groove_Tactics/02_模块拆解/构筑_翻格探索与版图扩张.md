# 构筑_翻格探索与版图扩张

## 主问题

为什么该游戏的翻格必须以 HQ 连通地块为中心，而不能做成任意点图或底部按钮？

## 机制描述

玩家在地图上点击未翻开的候选地块。候选地块不是全图任意存在，而是由己方 HQ 连通网络边缘生成：系统从 HQ 出发，找出所有已翻开、己方归属、可通行且能连回 HQ 的地块，再扫描它们相邻的未翻开地块，为这些地块显示成本或问号。玩家金币足够时，点击候选地块扣金币并揭示内容。

翻开结果至少包含三类：

| 结果 | 直接效果 | 后续影响 |
|---|---|---|
| 空地 | 接入 HQ 连通网络 | 扩大下一圈可翻候选范围 |
| 矿 | 接入 HQ 连通网络并周期产金币 | 缩短下一次翻格等待，支撑更贵地块 |
| 兵营 | 接入 HQ 连通网络并周期产兵 | 增加出兵点，让战斗路线不只来自 HQ |

## 存在理由

HQ 连通翻格把“探索”变成空间构筑。玩家不是简单清问号，而是在决定版图从基地往哪里长：往矿走会提高经济恢复，往兵营走会提高前线压力，往空地走则可能只是扩大边界。若删掉 HQ 连通约束，玩家可以直接点远处关键资源，空间路线失去意义；若改成底部按钮，玩家会失去“这个地块为什么现在能翻”的地图反馈。

## 不负责什么

- 不负责金币产出数值；那是经济系统职责。
- 不负责矿和兵营的周期收益；那是建筑系统职责。
- 不负责单位寻路和战斗；那是战斗推进职责。
- 不负责敌方目标策略；敌方 AI 只复用同一套候选生成规则。

## 可重现规则

| 规则 | If-Then 表达 |
|---|---|
| 连通根 | 若地块是己方 HQ，则它天然属于己方连通网络 |
| 连通扩展 | 若已翻开地块与己方连通网络相邻、归属己方且可通行，则加入己方连通网络 |
| 候选生成 | 若未翻开地块与己方连通网络相邻且不是障碍，则生成付费候选状态 |
| 点击支付 | 若玩家点击候选地块且金币余额大于等于该地块成本，则扣金币并翻开 |
| 金币不足 | 若金币不足，则地块保持未翻开，只给不足反馈 |
| 空地揭示 | 若翻开结果为空地，则只接入网络并刷新下一圈候选 |
| 矿揭示 | 若翻开结果为矿，则接入网络，并从下一次经济 tick 开始产金币 |
| 兵营揭示 | 若翻开结果为兵营，则接入网络，并从下一次产兵 tick 开始出兵 |
| 未连通限制 | 若地块不能经已翻开地块连回 HQ，则不得成为可翻候选 |

## 失效条件

- 翻格没有已翻开/未翻开状态：玩家看不出探索进展，地块只剩背景色。
- 候选不依赖 HQ 连通：会出现孤岛、越级翻资源、空间路线失效。
- 使用底部按钮翻格：交互焦点离开地图，用户无法建立“点哪个地块、开哪条路”的因果。
- 没有空地：每次翻格都给收益，路线风险消失。
- 没有矿：金币恢复只靠 HQ，经济成长不足。
- 没有兵营：翻格不能改变战斗来源，战斗会退化为 HQ 单点出兵。

## 证据等级

地块状态、HQ 连通、矿/兵营/空地来自用户明确纠偏，证据等级 A。具体成本曲线和内容概率当前未确认，证据等级 C，demo 阶段只做可配置假设。
