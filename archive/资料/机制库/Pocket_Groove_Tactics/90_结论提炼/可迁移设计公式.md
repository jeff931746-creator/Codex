# 可迁移设计公式

## 结论 1：未知地块要有行动成本

If 一个游戏希望“翻开未知空间”成为策略，而不是清屏操作，Then 每次翻开都必须消耗会影响下一步选择的资源。

evidence_grade: A。依据：用户明确指出翻开地块消耗不同金币，且金币不是无限点。

太宽测试：不是所有探索都需要成本；只适用于探索行为高频、且探索结果会改变局内收益结构的游戏。

## 结论 1b：翻格输入源必须绑定空间对象

If 一个游戏的核心决策是“从基地网络向外扩张”，Then 翻格输入必须绑定到地图上的候选地块，而不能抽象成脱离地图的按钮。

evidence_grade: A。依据：用户明确纠正 `FLIP` 应在地块上，且候选地块只能由已翻开连通地块相邻生成。

太宽测试：不适用于纯列表抽卡或非空间探索；这里限定为以空间连通和版图扩张为核心的玩法。

## 结论 2：空结果要服务边界扩张

If 翻开结果可能为空，Then 空地也必须至少扩大可行动边界，否则空结果只会被玩家感知为惩罚。

evidence_grade: B。依据：用户确认翻开可能为空；空地扩大边界是基于相邻翻格结构的实现推断。

太宽测试：该结论不适用于纯抽奖，因为抽奖空结果可以服务概率回收；这里限定为空间探索。

## 结论 3：经济建筑要改变操作频率

If 局内经济建筑是翻格奖励，Then 它的收益应让玩家更快执行下一次关键操作，而不是只增加结算分数。

evidence_grade: A。依据：用户确认主基地和矿会产出金币，金币用于翻开地块。

太宽测试：不是所有经济建筑都要加快操作；适用于经济直接购买行动许可的玩法。

## 结论 4：自动战斗要把注意力让给构筑

If 一个玩法的主要乐趣来自地图扩张和资源发现，Then 战斗执行应尽量自动化，让玩家把注意力放在扩张路线和收益判断上。

evidence_grade: B。依据：视频表现为单位自动推进；“注意力让给构筑”是从复刻目标推导。

太宽测试：不适用于强调微操的 RTS；这里限定为移动端轻策略局内循环。

## 结论 5：双方结构要服务战线感

If 游戏核心是两方基地互推，Then 地图布局应让双方方向关系在第一屏内可读，避免用斜向或散点布局削弱推进线。

evidence_grade: A。依据：用户明确纠正为上下结构，视频也呈现上下对抗。

太宽测试：不适用于开放探索地图；这里限定为短局对抗和基地摧毁目标。

## 结论 6：兵营奖励要转化为可见压力

If 翻格可能翻出兵营，Then 兵营必须在短时间内产生可见单位或推进压力，否则它和普通地块的差异不够。

evidence_grade: A。依据：用户确认翻开可能是兵营，且缺失“出兵”会导致复刻不成立。

太宽测试：不适用于长期经营建筑；这里限定为单局即时反馈玩法。
