## 一、库的定位

竞品库记录外部游戏产品信息——新品发现、产品数据、玩法拆解。

**核心原则：只收符合关注范围的新产品，不做 value_score 筛选，但有明确的收录/排除标准。**

主数据：每个产品一份 `.md` 文件（YAML frontmatter + 正文），同一产品多次出现时更新同一文件而非新建。

---

## 一-bis、新品收录标准

### 收录（满足任一即入库）

| # | 条件 | 说明 |
|---|---|---|
| N1 | **海外未上线产品** | 处于公布/预约/测试阶段，尚未正式上线的海外产品 |
| N2 | **海外已上线，国内无同类** | 海外已上线但国内市场没有类似玩法/品类的产品 |
| N3 | **国内 IAA 新品** | 国内 IAA（广告变现）赛道的新产品 |

### 排除（命中任一则不收录）

| # | 条件 | 说明 |
|---|---|---|
| X1 | **大厂已知项目** | 腾讯/网易/米哈游/字节等大厂的公开项目（原神、王者荣耀、和平精英等） |
| X2 | **主流手游** | 已广为人知的手游，非新品 |
| X3 | **三消类** | 传统三消及其变体 |
| X4 | **过于轻度的休闲** | 打螺丝、撕封条、解压类等纯消磨时间无深度的超休闲 |
| X5 | **PC/主机 3A** | 大型 PC/主机 3A 项目 |

### 判定示例

| 产品 | 收录？ | 原因 |
|---|---|---|
| 某海外刚公布的 Roguelite 手游 | ✅ | N1: 海外未上线 |
| 某海外放置卡牌，国内没有类似 | ✅ | N2: 海外有国内无 |
| 某微信小游戏 IAA 放置塔防 | ✅ | N3: 国内 IAA |
| 原神新版本 | ❌ | X1: 大厂已知项目 |
| 某打螺丝小游戏 | ❌ | X4: 过于轻度 |
| 某三消+装修游戏 | ❌ | X3: 三消类 |
| 战神新作 | ❌ | X5: PC/主机 3A |

## 二、YAML Frontmatter

继承通用标准字段，叠加产品级专有字段。

```yaml
---
# === 身份（继承通用）===
entry_id: PROD-2026-06-04-001   # 格式：PROD-{首次发现日期}-{序号}
title: ""                       # 产品名称
date: ""                        # 首次发现/上线日期
source_name: ""                 # 首次发现来源
url: ""                         # 首次发现来源 URL

# === 产品基础信息 ===
platform: []               # 平台：微信小游戏/iOS/Android/Steam/Switch/多平台
category_primary: ""        # 主品类：SLG/RPG/卡牌/塔防/放置/休闲/模拟/射击/动作/解谜/肉鸽/其他
category_tags: []           # 次级标签：2-5 个，如 [放置, 肉鸽, 挂机]
developer: ""               # 开发商，未知写 "未知"
publisher: ""               # 发行商，未知写 "未知"
release_status: ""          # 已上线/测试中/预约中/已公布/待确认
release_date: ""            # 上线日期，待确认写 "待确认"
region: []                  # 上线地区：国内/东南亚/日韩/欧美/全球/待确认

# === 产品特征（按可获取信息填写，未知留空）===
core_gameplay: ""           # 核心玩法一句话描述
monetization: ""            # IAA/IAP/混合/买断/免费+内购
art_style: ""               # 画风描述
target_audience: ""         # 目标用户画像

# === 市场数据（按可获取信息填写，未知留空）===
revenue_tier: ""            # 收入规模：头部/腰部/长尾/待确认
chart_info: ""              # 榜单信息（如"畅销榜 Top10"），无数据留空
download_estimate: ""       # 下载量估算，无数据留空
ad_activity: ""             # 买量活跃度：高/中/低/无数据

# === 质量评估（继承通用）===
source_credibility: ""
bias_note: ""

# === 反馈（继承通用）===
user_rating: null
user_note: ""

# === 元数据 ===
collected_date: ""          # 首次收集日期
last_updated: ""            # 最后更新日期（有新信息时更新）
update_sources: []          # 更新信息来源 URL 列表
---
```

### 字段填写原则

- **能填就填，不确定就留空**。不伪造数据。
- 同一产品来自多篇文章时，取最权威来源的信息。
- `update_sources` 记录所有贡献过信息的文章 URL。

## 三、正文结构（产品级）

```markdown
## 产品概述
（一段话描述：这是什么游戏，核心卖点）

## 信息时间线
- [YYYY-MM-DD] [来源] 信息内容
- [YYYY-MM-DD] [来源] 信息内容
（每次有新信息时追加，按时间倒序）

## 玩法/系统（如有拆解信息）
（结构化描述，来自产品拆解类文章）

## 市场表现（如有数据）
（榜单、收入、买量数据，标注来源和口径）
```

**信息时间线是核心**——同一产品从首次发现到后续所有更新，全部追加到时间线。

## 四、去重与合并规则

**同一产品不建多个文件。** 判定标准：

1. 产品名完全相同 → 同一产品，更新已有文件
2. 产品名略有差异（如《占城大师》vs《Occupy Master》）→ 查开发商/玩法确认是否同一产品
3. 同一产品不同平台版本 → 同一文件，`platform` 字段加入新平台

合并时：
- YAML 字段取最新/最权威的值
- `update_sources` 追加新来源 URL
- `last_updated` 更新为当天
- 正文"信息时间线"追加新条目

## 五、产品级专项校验

| # | 判据 | 通过 | 不通过 |
|---|---|---|---|
| P1 | 产品名有值 | title 非空 | 无法识别产品名 |
| P2 | 平台有值 | platform 至少有一个值 | 完全未知 |
| P3 | 主品类有值 | category_primary 非空 | 无法判断品类 |
| P4 | 信息来源可追溯 | url 非空，指向具体文章 | 无来源 |

校验宽松（只要求核心身份字段），因为很多新品首次出现时信息不完整，**不能因为信息不全就不入库**。

## 六、文件命名与目录

按**轻中重度**分档，文件名带日期。

```
竞品库/
├── README.md
├── SCHEMA.md          本文件
├── 轻度/              休闲、放置、益智（有深度的）
│   └── {YYYY-MM-DD}_{产品名}.md
├── 中度/              塔防、卡牌、模拟经营、Roguelite、策略
│   └── {YYYY-MM-DD}_{产品名}.md
├── 重度/              SLG、MMO、ARPG、开放世界、竞技
│   └── {YYYY-MM-DD}_{产品名}.md
└── 索引/
    ├── 按时间.md       按 collected_date 倒序
    └── 按重度.md       按 weight 分组
```

重度分档标准：

| 档位 | 典型品类 |
|---|---|
| 轻度 | 休闲、放置、超休闲（有深度的）、益智 |
| 中度 | 塔防、卡牌、模拟经营、Roguelite、策略、合成 |
| 重度 | SLG、MMO、ARPG、开放世界、竞技、射击 |

文件命名：`{重度}/{YYYY-MM-DD}_{产品名}.md`，如 `中度/2026-06-04_占城大师.md`。
