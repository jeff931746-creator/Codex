# GameFlow 知识库

## 状态

资料库草稿。

本目录用于沉淀 GameFlow 原模型知识，不升格为方法论、部门标准或正式评审流程。后续如果要接入六张牌、`N/T/A/F/THM` 或其他立项评审框架，应另开接入方法论文档。

## 模型定位

GameFlow 是 Sweetser & Wyeth 在 2005 年提出的“玩家享受感 / 心流体验评估模型”。它的核心用途是评估游戏游玩过程中是否具备持续专注、适配挑战、技能成长、控制感、清晰目标、有效反馈、沉浸和社交互动等体验条件。

GameFlow 不是用户需求模型。它不直接回答用户为什么需要某类体验、某个题材是否适合买量、产品是否具备 ROI 承接能力，也不直接替代商业游戏研发管理框架。

## 主要来源

- Sweetser, P., & Wyeth, P. (2005). `GameFlow: A Model for Evaluating Player Enjoyment in Games`
- DOI: `10.1145/1077246.1077253`
- 参考 PDF: https://www.valuesatplay.org/wp-content/uploads/2007/09/sweetser.pdf

## 文件索引

- `GameFlow模型卡.md`：模型来源、理论定位、8 个元素、适用场景。
- `GameFlow_8元素评审表.md`：把 8 个元素转为可观察、可提问的评审字段。
- `GameFlow_适用边界.md`：说明 GameFlow 与 SDT/PENS、MDA、六张牌、题材/买量/ROI 评估的边界。

## 使用顺序

1. 先读 `GameFlow模型卡.md`，确认模型是什么、不是什么。
2. 再用 `GameFlow_8元素评审表.md` 做原型、竞品或玩法段落的体验诊断。
3. 最后用 `GameFlow_适用边界.md` 判断结论是否越界，避免把过程体验评估误用为用户需求、题材获量或商业化判断。

## 当前约束

- 不把 8 个元素机械要求为全部高分；不同游戏类型可以存在不适用项。
