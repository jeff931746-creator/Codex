# 提示词 04:失败复检

> 用于:处理 `已知问题/FAILURES.md` 中跑批失败的样本
> 配套:[SCHEMA.md](../SCHEMA.md) / [录入工作流.md](../录入工作流.md)
> 更新日期:2026-05-15

---

## 用途

任务 1 / 任务 2 跑批中可能因以下原因失败:

| 失败类型 | 现象 |
|---|---|
| yaml 解析失败 | DeepSeek 输出非 yaml 格式,或字段名拼写错 |
| 字段缺失 | 必填字段为空 |
| 枚举值错 | n_main / media_type 等取值不在枚举范围 |
| 内容空洞 | 字段都填了但全是泛泛之谈,无实际信息 |
| 信息不足 | 作品本身资料过少,DeepSeek 无法判定 |

本提示词用于对失败样本做**针对性重判**。

---

## 处理流程

```
1. 读取 已知问题/FAILURES.md 中的失败记录
2. 按失败类型分类(yaml 错 / 字段缺 / 枚举错 / 空洞 / 信息不足)
3. 对每类失败,使用本提示词调用 DeepSeek 重判
4. 第二次仍失败的:
   - 信息严重不足 → 标 review_status: disputed,evidence_level: D,人工处理
   - yaml 或字段问题 → 标 disputed,工程介入
```

---

## 系统提示

```
你是游戏题材分析师。上一次对某部作品的字段提取失败了,失败原因和上次的输出我会一并给你。请你针对性修正,输出合格的 yaml frontmatter。

修正原则:
- yaml 解析失败:严格按模板格式,不要加 markdown 代码块标记,不要加额外解释
- 字段缺失:补全所有必填字段,即使信息不足也给出最佳推断,confidence 调到 low
- 枚举值错:从给定枚举值中重选,绝对不要造词
- 内容空洞:每个字段给出有信息量的描述,不要写"主角变强对抗反派"这种空话
- 信息不足:work_name + media_type + year 一定能填,其他字段尽力推断,evidence_level 调到 C
```

## 用户提示模板

```
[上一次失败信息]
失败类型:{yaml_parse_error | field_missing | enum_invalid | content_empty | info_insufficient}
失败字段:{字段名列表}
上次输出(可能是部分输出或错误格式):
{上次 DeepSeek 输出原文}

[作品信息]
- 名称:{name}
- 媒介:{media_type_display}
- 首发年份:{year}
- 已知信息:{existing_data}
- 可补充信息:{如能从外部检索到的简介、维基片段}

[请重新输出完整 yaml frontmatter]
{使用 01_单作品打标.md 的输出 yaml 模板}

[额外要求]
- 如果上次失败是 enum_invalid,在输出末尾的 core_emotion_note 字段写"修正自 {上次错值}"
- 如果上次失败是 info_insufficient,evidence_level 调到 C,review_status 保持 auto 但跑批日志标记
- 如果本次仍判断信息严重不足,在 core_emotion_note 写"信息不足,建议人工复检",输出 review_status: disputed
```

---

## 失败两次后的处理

- 同一样本失败两次进入"永久 disputed 队列"
- 写入 `已知问题/FAILURES.md` 的 `permanent_disputed` 段
- 每月人工 review 一次,决定:
  - 找到外部资料后重判
  - 标记为"信息不足,跳过该样本"(不进入主样本目录)
  - 拆分为多个候选条目(同 IP 的不同作品被误合并时)

---

## 失败率报警

- 单批失败率 > 5% → 自动暂停跑批,需要审查 01_单作品打标.md 的提示词
- 累计失败率 > 10% → 全库暂停,需要审查 SCHEMA.md 的字段定义合理性
- permanent_disputed 数 > 100 → 人工集中处理,可能需要新增枚举值或调整判据
