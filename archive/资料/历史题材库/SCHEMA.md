## 一、库的定位

历史题材库收录 1999-2026 年的日漫/欧美影视/韩国电影/欧美电影/海外文学作品,作为**游戏立项的题材选型样本池**,反向支撑三位一体框架中的 [02-题材母题标准](../../../reference/部门标准/立项/三位一体框架/current/02-题材母题标准.md)。

**主数据**:每部作品一份 `.md` 文件,带 yaml frontmatter,放在 `样本/按媒介/{媒介编号}_{媒介名}/` 下。
**索引**:从主数据派生,不手工维护,见 `样本/索引/`。
**母题归并**:把作品聚合到 THM-* 母题,见 `母题归并/`。

---

## 二、文件命名

```
样本/按媒介/{媒介编号}_{媒介名}/{作品名}.md
```

- 作品名清洗规则:
  - 去除"第 X 季"后缀(季作品合并到主作品,季信息写入 yaml `season_count`)
  - 同名不同媒介加后缀:《辐射》小说 → `辐射_LIT.md`,《辐射》美剧 → `辐射_TVW.md`
  - 特殊字符替换:`/ \ : * ? " < > |` 替换为下划线
  - 中英文标题任选其一作主名,另一个进 `work_name_alt`

### 跨媒介同 IP 的处理

同一 IP 跨多个媒介(如《沙丘》小说 + 电影 + 剧集)时:

- 各媒介**独立条目**,各填一份样本文件(用媒介后缀区分)
- 必须在 `work_name_alt` 字段互相引用(便于交叉校验)
- 在 `core_emotion_note` 注明媒介差异(如"2021 电影更突出视觉冲击,小说更突出哲学/政治深度")
- 跑批后必须用 [提示词/03_交叉校验.md](提示词/03_交叉校验.md) 做"同 IP 多媒介"专项一致性校验
- N/T 判定在不同媒介可能不同(电影 vs 小说的承接重点会有差异),但 environment 类底层字段应基本一致

## 三、YAML Frontmatter(必填字段)

```yaml
---
# === 身份 ===
work_id: WORK-ANI-00001              # 自动分配,WORK-{媒介}-{编号},永不修改
work_name: 进击的巨人                  # 主名称
work_name_alt: [Attack on Titan, Shingeki no Kyojin]   # 选填,别名/外文名
media_type: ANI                       # 媒介编号,见枚举值
year_first: 2013                      # 首发年份
year_range: [2013, 2023]              # 选填,系列跨度
season_count: 4                       # 选填,季数(动画)或卷数(漫画)

# === 三要素(对齐 02-题材母题标准的 theme_elements)===
environment: 19世纪欧洲风奇幻世界 + 巨墙城邦         # 环境/时代,一句话,≤45字
cultural_paradigm: 军事化抵抗 + 调查兵团体系          # 文化范式/战斗体系,一句话
narrative_core: 在末日威胁中守护城墙与揭开世界真相    # 叙事核心,一句话

# === SDT 心理需求 ===
n_main: N-Comp                        # 必填,N-Comp / N-Auto / N-Rel 三选一
n_others: []                          # 选填,0-2 个副需求
rel_object: null                      # n_main 或 n_others 含 N-Rel 时必填(virtual/real/mixed),否则 null
t_can_carry: [T2, T1]                 # 选填,作品承接的玩家任务态(引用 06-基础维度定义);仅备用,不进主检索路径
core_emotion_note: "求生压力为主,后期转 N-Comp 成长复仇"   # 选填,解释
core_conflict: 人类对抗巨人 + 内部权力博弈            # 必填,核心冲突一句话

# === 三层标签(主检索路径,见 TAGS.md)===
theme_primary: 末日                   # 必填,L1 主题大类,单选,30 个枚举
theme_secondary: [丧尸, 后启示录, 政治权谋]   # 必填,L2 子题材,2-5 个,严格从 TAGS.md 候选选
visual_tags: [巨墙城邦, 立体机动, 末日紧张] # 必填,L3 视觉标签,2-5 个,半开放(候选优先,允许新增)

# === 获量(评分)===
acquisition_score: 5                  # 1-5,IP 知名度 × 视觉钩子强度(评分细则见下)

# === 素材与玩法 ===
material_hooks: [巨人压迫感, 立体机动战斗, 城墙崩塌]   # 必填,3-5 个素材钩子,每个≤10字。视觉钩子优先,视觉薄弱时填概念钩子,同一作品内不要混填
existing_games: [进击的巨人2, 进击的巨人 自由之翼]    # 选填,已有改编游戏
recommended_playstyles: []            # 选填,推荐玩法 ID(PLY-*)
risk_notes: [题材沉重不适合下沉, IP 授权门槛高]      # 选填,1-3 个风险,每个≤15字

# === 元数据 ===
source: deepseek-v4-flash             # 数据来源
source_run_id: 2026-05-15-batch01     # DeepSeek 跑批批次
evidence_level: B                     # S/A/B/C/D,LLM 推断默认 B
review_status: auto                   # auto / human-reviewed / disputed
last_updated: 2026-05-15
---
```

### 正文(选填)

YAML 之后可写 Markdown 正文,用于补充:

- **题材独特性**:这部作品比同母题其他作品多了什么
- **市场表现**:发行成绩、口碑、IP 衍生
- **改编潜力**:适合做成什么品类的游戏、为什么
- **同类作品**:同母题或相邻母题的 3-5 部对比

正文是"人类可读的扩展",**yaml 字段是机器可消费的唯一真相源**。DeepSeek 跑批默认不填正文,后续重点作品由人工补。

## 四、枚举值定义

### 4.1 media_type(媒介类型)

| 编号 | 显示名 | 说明 |
|---|---|---|
| ANI | 日本动漫 | 日本动画 + 漫画原作 |
| TVW | 欧美电视 | 欧美剧集(含 Netflix 等流媒体) |
| MVW | 欧美电影 | 欧美院线 + 流媒体电影 |
| MVK | 韩国电影 | 韩国院线电影 |
| LIT | 海外文学 | 海外小说/漫画原著(不含改编) |
| TVK | 韩国电视 | 选填,扩展用 |
| TVC | 华语影视 | 选填,扩展用 |

`work_id` 前缀使用编号(如 `WORK-ANI-00001`)。**编号永不修改**。

### 4.2 n_main / n_others(SDT 心理需求)

引用 [03-玩法承接标准](../../../reference/部门标准/立项/三位一体框架/current/03-玩法承接标准.md) 章节 3。

| 代码 | 名称 | 判定线索 |
|---|---|---|
| N-Comp | 胜任感 | 看作品获得"我能做到/我变强/我看懂了/我掌控了"的代入 |
| N-Auto | 自主性 | 看作品获得"我能自己选/我的节奏/我自由探索"的代入 |
| N-Rel | 关系感 | 看作品获得"我和谁(虚拟角色/真人/组织)有连接"的代入,**包括温和归属(乙女/公会/宠物)和权力关系(支配/被支配/政治结盟)两种形态** |

规则:
- `n_main` 必填,1 个
- `n_others` 选填,0-2 个,允许跨需求
- **n_others 添加门槛**:副 N 必须能从作品中观察到至少 20% 的核心爽点来自该 N,否则不填。**宁可少填,不要凑数**。
- `rel_object` 当 `n_main = N-Rel` 或 `n_others` 含 `N-Rel` 时必填:
  - `virtual` — 关系对象是虚拟角色 / NPC / 宠物
  - `real` — 关系对象是真人
  - `mixed` — 两者并存
- **rel_object 只看作品内提供的关系对象**,不计作品引发的现实社交、粉丝社群、UGC 创作等周边关系

**DeepSeek 判定要点**:
- 作品核心爽点是"主角变强/破解世界/掌控局面" → N-Comp
- 作品核心爽点是"自由探索/无目标漫游/随心所欲" → N-Auto
- 作品核心爽点是"和某个/某群对象的情感纽带 或 在某个组织里支配/被支配" → N-Rel

**N-Rel 的两种形态(都属于 N-Rel,不要漏判)**:

| 形态 | 特征 | rel_object | 典型作品 |
|---|---|---|---|
| 温和归属 | 情感纽带、陪伴、嗑组合、家族羁绊 | virtual / real / mixed | 乙女游戏、海贼王、MMO 公会 |
| 权力关系 | 在组织/政治结构中的支配、结盟、博弈位置 | real(权力对象都是人) / mixed | 权力的游戏、纸牌屋、大明王朝、SLG 霸服 |

**易混判**:
- 纯智斗破解(《名侦探柯南》《死亡笔记》)= N-Comp(认知胜任),不是 N-Rel
- 权力博弈作品(《权力的游戏》)= N-Rel(权力型),因为驱动是"对其他角色的支配/结盟/敌对",不是"我个人变强"
- 同一作品同时含智斗和权力时,看主驱动:智斗为主 → N-Comp,权力关系为主 → N-Rel

**团队类作品的 N-Comp vs N-Rel 边界**(团队 + 战斗 双驱动时常用):

- 团队是"赢比赛/过关的工具" → N-Comp(王者荣耀、行尸走肉)
- 团队是"归属/嗑组合的目的" → N-Rel(MMO 公会、海贼王角色向粉)
- 同一作品两种用户都有时,按"长期付费最核心驱动"决定主 N

### 4.3 t_can_carry(任务态承接)

引用 [06-基础维度定义.md](../../../reference/部门标准/立项/三位一体框架/current/06-基础维度定义.md) 的 T1-T6 + T7-candidate。

| T | 任务态 | 用户在处理什么 |
|---|---|---|
| T1 | 状态调节 | 缓解负面状态(疲惫、压力、无聊) |
| T2 | 价值/能力确认 | 确认"我变强、我有价值、我没掉队" |
| T3 | 对象亲密 | 和角色/宠物/虚拟对象建立情感连接 |
| T4 | 群体位置 | 在组织/队伍/关系网里找位置 |
| T5 | 规则理解 | 理解、破解、看懂复杂规则 |
| T6 | 秩序掌控 | 把系统/世界/资源变得可控、有序 |
| T7-candidate | 习惯维持(候选) | 维持已有习惯不中断 |

规则:
- `t_can_carry` 是数组,**0-2 个**(主 T 在前,副 T 只在能明显观察到时才填)
- 主 T 必须能解释作品的核心粘性
- **副 T 只填占 20%+ 观众的任务态**,不要填理论上可能的
- 不强制必填(部分作品任务态不明显时可空)

**主 T 判定原则**:按"长期留存 + 付费最核心驱动"决定,**不按"看的人最多"决定**。如果出货大的群体和长期粘性高的群体不一致,以后者为主 T。

例:《老友记》大众观众是 T1 下饭剧,但核心 IP 粉是 T3 角色亲密;立项推演时应以 T3 为主 T(因为 T3 用户才会为 IP 游戏付费),T1 为副 T。

### 4.4 旧 core_emotion 与 SDT 的换算表

原 SCHEMA 草案使用 SUR/POW/EXP/HEA/GRO/BRE 6 大情绪。**v1.0 SCHEMA 改为 SDT 三需求**。已有数据迁移时按下表换算为 N + T:

| 旧 core_emotion | 推荐 N + T | 备注 |
|---|---|---|
| SUR 求生压力 | N-Comp / T1 或 T2 | 看作品是处理负面状态(T1)还是追求变强(T2) |
| POW 爽感释放 | N-Comp / T1 | 高频泄压,T1 主 |
| EXP 敬畏探索 | N-Comp / T5 | 规则理解任务 |
| HEA 治愈放松 | N-Rel / T1(陪伴向)或 N-Auto / T1(放空向) | 看是治愈陪伴还是自由放空 |
| GRO 成长满足 | N-Comp / T2 | 变强确认 |
| BRE 紧张破局 | N-Comp / T5 | 规则破解 |

**换算不是机械映射**,DeepSeek 重判时要看作品具体细节,这个表只作判定起点参考。

### 4.4-bis material_hooks(素材钩子)

3-5 个素材钩子,每个 ≤ 10 字。用于立项时反向推导可做素材的卖点。

**选填优先级**:
1. **视觉钩子优先**:画面、场景、角色形象、特效、动作场面(如"巨人压迫感"、"立体机动战斗")
2. **视觉钩子薄弱时填概念钩子**:主题、隐喻、结构反转、世界观设定(如"阶级反差"、"预言弥赛亚")
3. **同一作品内不要混填**:要么全视觉,要么全概念,避免不在同一抽象层的钩子混在一起

### 4.5 acquisition_score(有效获量,1-5)

| 分数 | 含义 |
|---|---|
| 1 | 作品本身无法形成第一眼买量素材 |
| 2 | 作品需要长解释,素材难做差异化 |
| 3 | 作品有标准素材模板,但竞争激烈 |
| 4 | 作品有多种差异表达,市场仍有空间 |
| 5 | 作品素材力天然强,能立即吸引点击 |

判定:**IP 知名度(主)× 视觉钩子强度**。
- IP 知名度:全球破圈 / 本地高热度 / 中等知名度 / 小众 / 无 IP
- 视觉钩子强度:看 `material_hooks` 中视觉钩子的具象度 + 画面冲击力
- 不依赖外部豆瓣/IMDb 评分,以 LLM 综合判断为准

### 4.6 theme_primary(L1 主题大类,单选)

引用 [TAGS.md §二](TAGS.md) 30 个枚举。**严格从枚举选,不允许自创**。

判定:取作品最主要的题材轴(占核心叙事 50%+),其他题材进 L2。

### 4.7 theme_secondary(L2 子题材,多选 2-5 个)

引用 [TAGS.md §三](TAGS.md) ~100 个候选。**严格从候选选,不允许自创**。

判定:多选 2-5 个,主子题材在前,可跨 L1 大类选(如《银魂》L1=喜剧 + L2=[日常喜剧, 江湖, 异种入侵])。

如发现候选不够用,反向推动 TAGS.md 增补,不在样本中自造。

### 4.8 visual_tags(L3 视觉标签,多选 2-5 个)

引用 [TAGS.md §四](TAGS.md) ~100 个候选。**半开放**:候选优先,LLM 可新增。

判定:
- 优先选场景符号(让人一眼联想到画面)
- 视觉钩子薄弱的作品选氛围风格
- 同一作品的 L3 标签应在同一抽象层(都场景或都氛围,不混填)

新增的标签后续脚本统计合并到候选库。

### 4.9 evidence_level(证据等级)

| 等级 | 含义 |
|---|---|
| S | 有自有投放/留存/付费数据 |
| A | 多产品商业成功 + 榜单证据 |
| B | LLM 推断 + 有公开元数据支持(IP 名 + 年份 + 简介可查证)— 任务 1 默认值 |
| C | 单一来源推断 / 信息不完整 / N 判定摇摆需 review |
| D | 缺少证据,仅占位 / 永久 disputed |

DeepSeek 跑批默认 B(基于"有公开元数据支持"的推断);信息不足时调到 C;失败两次或 N 完全无法判定时调到 D。

### 4.10 review_status(校验状态)

| 取值 | 含义 |
|---|---|
| auto | DeepSeek 自动跑批,未经人工 review |
| human-reviewed | 人工 review 过,字段已确认 |
| disputed | 字段有争议,等待重判 |

## 五、质量门禁(校验脚本必查)

每批 DeepSeek 输出归档前,必须通过:

1. **YAML 合法性**:必填字段齐全(work_id 除外,首次自动分配)
2. **枚举值合法性**:media_type / n_main / n_others 元素 / rel_object / t_can_carry 元素 / theme_primary / theme_secondary 元素 / evidence_level / review_status 全部在枚举范围内
3. **rel_object 一致性**:n_main 或 n_others 含 N-Rel 时,rel_object 必须非 null;否则必须为 null
4. **评分范围**:acquisition_score 在 1-5
5. **theme_primary 合法性**:必须是 TAGS.md §二 30 个 L1 枚举之一
6. **theme_secondary 合法性**:全部元素必须在 TAGS.md §三 的 L2 候选中(自创则失败)
7. **去重检查**:`work_name + media_type` 唯一
8. **字段长度限制**:environment / cultural_paradigm / narrative_core / core_conflict ≤ 45 字;material_hooks 元素 ≤ 10 字;risk_notes 元素 ≤ 15 字;visual_tags 元素 ≤ 12 字
9. **material_hooks 数组长度**:必须 3-5 个元素(少于 3 或多于 5 → 校验失败)
10. **theme_secondary 数组长度**:2-5 个元素
11. **visual_tags 数组长度**:2-5 个元素
12. **t_can_carry 数组长度**:0-2 个元素(超过 2 → 校验失败)
13. **n_others 数组长度**:0-2 个元素(超过 2 → 校验失败)
14. **单批失败率**:DeepSeek 输出无法解析 yaml 或字段缺失的样本比例 > 5% 时报警

通不过校验的样本进 `已知问题/FAILURES.md`,人工或下一轮 DeepSeek 复检。

## 六、与三位一体框架的引用关系

```
历史题材库(本库,样本池)
   ├── 单作品 SCHEMA  ←─ 引用  06-基础维度定义.md(T 字段)
   │                  ←─ 引用  03-玩法承接标准_v1.1_draft.md(N 字段)
   │                  ←─ 引用  02-题材母题标准.md(THM-* 母题 ID)
   │
   └── 母题归并  ←─ 反向喂给  02-题材母题标准.md(代表作清单)
                ←─ 关联  人群簇 v1.2(audience_ids)
                ←─ 关联  玩法承接 v1.1(playstyle_ids)
```

**禁止反向**:本库不自定义 N / T / 母题分类,如出现枚举缺口,反向推动上游标准增补,不在本库自造。
