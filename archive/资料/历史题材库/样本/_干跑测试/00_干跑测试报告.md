# 干跑测试报告 — SCHEMA v1 可执行性验证

> 测试日期:2026-05-15
> 测试模式:人工按 SCHEMA + 提示词 01 模板填写 6 部作品,模拟 DeepSeek 跑批
> 测试样本:进击的巨人 / 行尸走肉 / 老友记 / 寄生虫 / 海贼王 / 沙丘_LIT

---

## 一、测试目的

验证 SCHEMA v1 + 提示词 01 在真实样本上的可执行性:

1. 字段是否齐全可填(必填项不能填的概率)
2. 枚举值是否覆盖典型情况(出现"我想选但没这个选项"的频率)
3. 判定标准是否清晰(N / T / rel_object 判定卡壳的频率)
4. 跨媒介、跨人群、跨年代样本是否都能容纳

## 三、测试结果总结

### 3.1 字段完整性

✅ **6 个样本全部可填完整 yaml**,无字段缺失
✅ 必填字段(work_name / media_type / N / T / 三要素 / 评分)都能给出有信息量的值
✅ 选填字段(work_name_alt / season_count / existing_games / risk_notes)按需填写

### 3.2 枚举值覆盖

✅ **未出现"想选但没枚举"的情况**

✅ N 三需求 + T1-T6 都用到了

## 四、暴露的规范问题(改进项)

### 改进 1:N-Comp vs N-Rel 在团队类作品上的边界判据(高优)

**问题**:团队作品(行尸走肉、海贼王、原神)都有"团队 + 战斗"双驱动,N 容易摇摆。

**改进方向**:在 `提示词/01_单作品打标.md` 的 "N 判定详则" 加一条:

> **团队是工具还是目的判据**:
> - 团队是"赢比赛/过关的工具" → N-Comp(王者荣耀、行尸走肉)
> - 团队是"归属/嗑组合的目的" → N-Rel(MMO 公会、海贼王角色向粉)
> - 同一作品两种用户都有时,按"长期付费最核心驱动"决定主 N

### 改进 2:T 任务态判定的"长期粘性优先"原则(高优)

**问题**:老友记和海贼王都暴露了"大众观众 T 不等于核心粉丝 T"的纠结。

**改进方向**:在 SCHEMA §4.3 的 t_can_carry 定义 + 提示词 01 加:

> **t_can_carry 主 T 判定**:按"长期留存 + 付费最核心驱动"决定,**不按"看的人最多"决定**。如果出货大的群体和长期粘性高的群体不一致,以后者为主 T。

### 改进 3:t_can_carry 数组收紧到 0-2 个(中优)

**问题**:SCHEMA 当前定义 0-3 个,海贼王样本暴露"容易填满"倾向,降低区分度。

**改进方向**:把 SCHEMA §4.3 改为"0-2 个,主 T 在前,副 T 只填占 20%+ 观众的"。

### 改进 4:rel_object 只看作品内,不计周边社群(中优)

**问题**:沙丘样本暴露 rel_object 容易过度解读(把读者社群归属当 N-Rel)。

**改进方向**:在 SCHEMA §4.2 的 rel_object 定义 + 提示词 01 加:

> **rel_object 只看作品内提供的关系对象**,不计作品引发的现实社交、粉丝社群、UGC 创作等周边关系。

### 改进 5:material_hooks 视觉/概念区分(中优)

**问题**:寄生虫样本暴露 material_hooks 字段定义模糊(视觉素材钩子 vs 概念钩子混淆)。

**改进方向**:在 SCHEMA §3 的 material_hooks 字段说明加:

> **material_hooks 优先填视觉钩子**(画面、场景、特效);视觉钩子薄弱时填概念钩子(主题、隐喻、结构反转),但**同一作品内不要混填**。

### 改进 6:跨媒介同 IP 的交叉引用规则(中优)

**问题**:沙丘 IP 跨小说/电影/剧集,各媒介独立条目可能字段不一致。

**改进方向**:在 SCHEMA §2 文件命名 + 录入工作流 任务 3 加:

> 跨媒介同 IP 时各媒介独立条目,但需在 `work_name_alt` 互相引用,在 `core_emotion_note` 注明媒介差异(如"2021 电影更突出视觉,小说更突出哲学")。
> 跑批后必须用提示词 03 做"同 IP 多媒介"专项交叉校验。

### 改进 7:N-Rel 的 n_others 不要轻率添加(中优)

**问题**:沙丘样本一开始把 N-Rel 加进 n_others,后来意识到核心是认知胜任,关系驱动弱。**这种过度添加副 N 在大批量跑批时会很常见**。

**改进方向**:在提示词 01 加一条:

> **n_others 添加门槛**:副 N 必须能从作品中观察到至少 20% 的核心爽点来自该 N,否则不填。**宁可少填,不要凑数**。

## 五、判定速度

| 作品 | 字段填写时长(估) | 卡壳次数 |
|---|---|---|
| 进击的巨人 | 2 分钟 | 0 次 |
| 行尸走肉 | 4 分钟 | 2 次(N + T) |
| 老友记 | 3 分钟 | 2 次(rel_object + T) |
| 寄生虫 | 3 分钟 | 1 次(material_hooks) |
| 海贼王 | 3 分钟 | 1 次(T 数组长度) |
| 沙丘_LIT | 5 分钟 | 3 次(媒介后缀 + rel_object + n_others) |

**人工平均**:3.3 分钟/部 + 1.5 次卡壳/部
**DeepSeek 预估**:5-10 秒/部,但卡壳点会变成"判定一致性低 + 跨样本不可比",所以**改进 1-7 必须在跑批前落到提示词里**。

## 六、SCHEMA 整体评估

| 维度 | 评分 | 说明 |
|---|---|---|
| 字段完整性 | ★★★★★ | 必填字段全覆盖,无字段空缺 |
| 枚举值覆盖 | ★★★★★ | 6 个典型样本未出现枚举不够用 |
| 判定清晰度 | ★★★☆☆ | N-Rel / T / rel_object 判定门槛偏高,需要改进 1-7 |
| 跨媒介一致性 | ★★★☆☆ | 跨 IP 交叉引用规则需要补充(改进 6) |
| DeepSeek 友好度 | ★★★★☆ | 主流程清晰,但需要先把改进 1-7 加到提示词 01 |

**结论**:SCHEMA v1 整体可执行,**但改进 1-7 必须先落到 SCHEMA.md + 提示词 01 + 提示词 03**,然后再做 10-20 部更广覆盖的二轮干跑,达到 90%+ 一次填准率后再启动 DeepSeek 全量跑批。
