# LLM 事实性信息处理规则

LLM（包括 DeepSeek、Claude、GPT 等）的训练数据不等于事实。本规则定义何时必须联网验证、何时可以使用 LLM 通识。

## 核心原则

**先搜后整，不能反过来。**

任何事实性判断都必须有可追溯的信息来源支撑，不能用 LLM 的通识知识填补事实空缺。

## 什么是"事实性判断"

需要联网验证的（事实性）：
- 某个产品/游戏是否有某个功能或系统
- 某个机制的具体参数、数值、触发条件
- 某个产品的市场表现、用户评价、发行信息
- 某个公司/团队的背景信息
- 某个时间点之后发生的事件

不需要联网的（分析性）：
- 基于已确认事实的逻辑推导
- 设计模式的识别和分类（如"这是路线件还是底盘件"）
- If-Then 格式的可迁移结论提炼
- 已有数据的结构化整理

## 执行规则

### 使用 LLM API（DeepSeek 等）做分析时

1. **先联网收集原始素材**：用 WebSearch 搜索相关信息
2. **把素材作为上下文喂给 LLM**：让 LLM 基于提供的素材分析，不依赖自身训练数据
3. **要求 LLM 标注信息来源**：每条事实性陈述必须指向上下文中的具体素材

prompt 模板：
```
以下是关于 {主题} 的资料（来自联网搜索）：
{搜索结果}

请基于以上资料进行分析。只使用以上资料中的信息，不要补充你自己知道的内容。
如果资料中没有覆盖某个方面，请明确标注"资料未覆盖"，不要自行填补。
```

### Claude 自身做分析时

同样适用。当 Claude 需要做事实性判断时：
- 有 WebSearch 工具 → 先搜索再回答
- 无 WebSearch 工具 → 明确告知用户"此信息未经联网验证，基于训练数据，可能不准确"
- 绝不能把未验证的 LLM 通识包装成确认事实

### 信息来源标注规范

| 来源类型 | 标注格式 | 置信度 |
|---|---|---|
| 第一手游玩 | "第一手：实际游玩" | 最高 |
| 联网搜索 | "搜索：{URL 或来源名称}" | 高 |
| 用户提供 | "用户提供" | 高（信任用户） |
| LLM 通识 | "LLM通识（未验证）" | 低，不可用于事实性判断 |
| 推断 | "推断：基于{已确认事实}推导" | 中，必须说明推断依据 |

禁止的标注：
- ❌ "玩家攻略"（没有具体来源）
- ❌ "官方介绍"（没有 URL）
- ❌ "第一手游玩反馈"（LLM 不能游玩）

## 失败模式

| 失败模式 | 表现 | 对策 |
|---|---|---|
| LLM 编造来源 | DeepSeek 标注"玩家攻略"但实际是训练数据 | prompt 中明确禁止，只允许引用上下文素材 |
| 通识当事实 | 直接问 LLM"这个游戏有PVP吗"并信任回答 | 先搜索，把搜索结果作为上下文 |
| 搜索不充分 | 只搜了一个来源就下结论 | 每个维度至少搜 2-3 个不同来源交叉验证 |
| 推断不标注 | 从已知信息推导但不标注推断 | 所有非直接观察的结论必须标注推断链 |

## 适用范围

本规则适用于所有需要事实性信息的工作场景，包括但不限于：
- 游戏机制拆解（阶段一系统穷举）
- 产品收集和竞品分析
- 市场信息调研
- 任何需要确认"某个东西是否存在/是什么样"的任务
