# 工作流链路规则

工作流层级架构与能力查找协议。详细流程文档见 [`workflow-chain-reference.md`](workflow-chain-reference.md)。

---

## 一、层级架构

```
reference/    规则层（AI 不得擅改）— 固化的标准与模板
archive/      沉淀层（经审批才入库）— 积累的知识与工具
workspace/    执行层 — 产出跟项目走，项目沿生命周期向下流动
```

知识流向（单向升格，需审批）：`workspace/` → `archive/经验/` → `archive/方法论/` → `reference/`

---

## 二、能力查找协议（硬规则）

在执行任何需要专项能力的工作前（写策划文档、写代码、出美术需求等）：

```
1. 先查 reference/部门标准/{能力}/
2. 有标准 → 严格按标准执行，不得自行发挥或补充未经确认的内容
3. 无标准 → 立即停止，告知用户：
   "需要 [X] 能力的标准，当前 reference/部门标准/{能力}/ 下暂无，是否建立？"
4. 禁止在无标准的情况下自行创作任何能力性文档
```

**当前已有标准：**

| 能力域 | 路径 | 内容 |
|---|---|---|
| 立项流程 | `reference/部门标准/立项/立项流程机制/` | 六闸门评审、补证支线、纸面原型执行模板 |
| 系统策划 | `reference/部门标准/策划/系统策划/` | 资深系统策划 Prompt 母版、工作流与优化方案 |
| GDD 写作与审核 | `reference/部门标准/策划/gdd/GDD写作标准.md` | 需求 GDD 框架（需求目的 / 需求概述 / 功能概述 / UE 交互）、Self-Review 判据、**设计层/技术层边界（GDD 只写功能行为与功能级契约，不写技术实现）**；写或审核功能需求文档时必读 |
| 数值评审 | `reference/部门标准/策划/数值评审/` | 数值评审判据（经济5+养成4+战斗3基础结构判据）、数值评审模板（经济体系7维度详细评审） |
| 策划文档规范 | `reference/部门标准/策划/` | 思路文档模板、功能需求文档模板 |
| 开发 | `reference/部门标准/开发/` | 开发部门标准（持续扩充） |
| 美术 | `reference/部门标准/美术/` | 美术部门标准（预留，暂无内容） |

## 三、框架沉淀规则

主对话中达成下列任一类共识时，**必须在继续下一步工作前**沉淀：

- 新的概念框架（公分母、第一性维度、基础结构）
- 第一性推演结论（维度定义、易混判据）
- 跨任务复用的判据 / 方法
- 用户多次反复纠正后形成的定义
- 新建的层次结构 / 接口规则

| 类型 | 位置 |
|---|---|
| 标准 / 规则 / 字段定义 | `reference/部门标准/` |
| 方法论 / 推导过程 / 判据集 | `archive/方法论/` |

禁止：先做事、事后再沉淀。框架必须先于数据存在。

---

## 四、三位一体框架引用规则

引用 `reference/部门标准/立项/三位一体框架/` 下任何标准时：

- **必须从 `current/` 读取**：`reference/部门标准/立项/三位一体框架/current/{标准名}.md`
- **禁止裸路径**（升级后路径失效）
- **`history/` 仅作历史追溯**，不在业务流程或 Skill 中引用

修订时：复制到 `history/{标准名}/v{X}_{日期}.md` → 覆盖 `current/` → 更新 yaml 元数据 → 更新 README 索引。
