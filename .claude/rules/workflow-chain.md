# 工作流链路规则

工作流层级架构与能力查找协议。详细流程文档见 [`.claude/references/workflow-chain-reference.md`](../references/workflow-chain-reference.md)。

---

## 一、层级架构

```
reference/    规则层（AI 不得擅改）— 固化的标准与模板
archive/      沉淀层（经审批才入库）— 积累的知识与工具
workspace/    执行层 — 产出跟项目走，项目沿生命周期向下流动
```

知识流向（单向升格，需审批）：`workspace/` → `archive/经验/` → `archive/方法论/` → `reference/`

---

## 二、能力查找协议（硬规则）

在执行任何需要专项能力的工作前（写策划文档、写代码、出美术需求等）：

```
1. 先查 reference/部门标准/{能力}/
2. 有标准 → 严格按标准执行，不得自行发挥或补充未经确认的内容
3. 无标准 → 立即停止，告知用户：
   "需要 [X] 能力的标准，当前 reference/部门标准/{能力}/ 下暂无，是否建立？"
4. 禁止在无标准的情况下自行创作任何能力性文档
```

**当前已有标准：**

| 能力域 | 路径 |
|---|---|
| 立项流程 | `reference/部门标准/立项/` |
| 策划 | `reference/部门标准/策划/` |
| 开发 | `reference/部门标准/开发/` |
| 美术 | `reference/部门标准/美术/` |

---

## 三、框架沉淀规则

主对话中达成下列任一类共识时，**必须在继续下一步工作前**沉淀：

- 新的概念框架（公分母、第一性维度、基础结构）
- 第一性推演结论（维度定义、易混判据）
- 跨任务复用的判据 / 方法
- 用户多次反复纠正后形成的定义
- 新建的层次结构 / 接口规则

| 类型 | 位置 |
|---|---|
| 标准 / 规则 / 字段定义 | `reference/部门标准/` |
| 方法论 / 推导过程 / 判据集 | `archive/方法论/` |

禁止：先做事、事后再沉淀。框架必须先于数据存在。

---

## 四、飞书访问回退规则

访问飞书资源时，按优先级尝试：

```
1. MCP 工具可用 → 直接调用
2. MCP 不可用 / 超时 / 报错 → 立即切对应 lark-* Skill 或 lark-cli Bash 命令
3. 禁止因 MCP 断连就报"无法访问飞书"——lark-cli 是独立于 MCP 的本地工具，永远可用
```
