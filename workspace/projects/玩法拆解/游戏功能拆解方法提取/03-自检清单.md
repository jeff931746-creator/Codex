# 自检清单

## 是否还停留在功能清单

- [ ] 有没有只列“入口、规则、奖励、次数、排行榜”，但没有解释为什么存在？
- [ ] 有没有把“赛季、商店、排行榜、体力、活动”这些机制名直接当成目的？
- [ ] 有没有只写玩家能获得什么，没有写资源从哪里来、怎么消耗、怎么影响后续行为？
- [ ] 有没有只写“多人”“社交”“竞争”，但没有写玩家之间到底能互相影响什么？

## 行为是否成立

- [ ] 玩家为什么第一次进入功能？
- [ ] 玩家为什么重复进入功能？
- [ ] 玩家在过程中是否有真实选择，而不是只领一次奖励？
- [ ] 功能结果是否会改变玩家下一次行动？
- [ ] 输、赢、损失、收益是否都会产生后续行为？

## 资源是否讲清楚

- [ ] 关键资源的来源是否明确？
- [ ] 关键资源的消耗或清理是否明确？
- [ ] 资源是否有保存期、赛季期或失效期？
- [ ] 资源是否会被他人影响？
- [ ] 资源职责是否写清，而不是只写成奖励包装？

## 玩家关系是否讲清楚

- [ ] 个人收益是否会变成他人可见的信息？
- [ ] 他人是否能影响我的收益或损失？
- [ ] 损失是否能定位到具体对象？
- [ ] 临时合作是否有机会转为稳定组织？
- [ ] 组织是否需要承担管理、分配、协调或成本？

## 玩家分层是否有效

- [ ] 是否只按战力分层？
- [ ] 是否补充了时间、操作、资源、组织、认知门槛？
- [ ] 强玩家有什么上限？
- [ ] 中等玩家有什么稳定位置？
- [ ] 低活跃玩家是否有可接受入口？
- [ ] 哪类玩家会被排除，原因是什么？

## 失效条件是否写出

- [ ] 太弱时，玩家为什么不在乎？
- [ ] 太强时，玩家为什么被迫参与或产生挫败？
- [ ] 缺失时，系统哪一段会断？
- [ ] 是否能根据失效条件反推修正方式？

## 结论是否可迁移

- [ ] 结论是否只对当前游戏成立？
- [ ] 是否写了适用前提？
- [ ] 是否写了不适用边界？
- [ ] 是否能指导另一个项目做取舍？
