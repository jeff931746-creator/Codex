# DeepSeek GDD 优化提示词：模板降噪版

## 使用目的

用于让 DeepSeek 优化玩法 / 系统 GDD 时，保留其中文表达和文档完整度，同时避免把 GDD 模板直接写成正文结构。

本提示词适用于以下情况：

- 现有文档内容基本正确，但措辞、结构或标题有模板腔。
- 需要让文档从“规则表单”变成“正式可交付 GDD”。
- 需要保留功能范围、边界和待确认项，不希望模型重新发明玩法。

## 根因修复

上一次输出中出现“开放与参与口径”这类不自然标题，根因不是 DeepSeek 理解错内容，而是提示词把“口径 / 流程 / 规则 / 边界”作为可直接使用的小标题示例给了模型。

后续提示必须区分三层：

1. **模板是检查清单**：用于确认功能是否覆盖入口、判断、结算、反馈和边界。
2. **正文是交付文档**：标题和段落要按功能职责命名，不直接照抄模板栏位。
3. **标题是读者导航**：标题必须让读者立刻知道本节解决什么业务问题。

## 标题规则

模块标题应使用“业务对象 + 功能职责 / 设计动作”，避免内部评审词。

优先使用：

- 阶段开启与参与资格
- 阶段开放与资格判定
- 成员行为计入
- 军团积分与贡献记录
- 排行与追赶反馈
- 结算与奖励领取
- 结果保留与后续预告

避免作为正文标题使用：

- 开放与参与口径
- 计入口径与流程
- 操作与响应
- 触发条件
- 规则与结算
- 边界与异常
- 处理流程

“口径”只适合用于规则解释或待确认项，不适合作为读者导航标题。  
“参与方式”只适合用于说明玩家通过哪些玩法参与；如果本节主要判断阶段状态、军团归属、中途加入、换团和结算资格，应使用“参与资格”或“资格判定”。

## 模块结构规则

不要让每个模块都套同一套五段式结构。先判断模块性质，再选择自然结构。

### 阶段 / 资格类模块

适合结构：

- 阶段状态
- 参与资格
- 中途加入与换团
- 结算后资格

不适合强行写成：

- 触发条件
- 操作与响应
- 规则与结算
- 边界与异常

### 行为计入类模块

适合结构：

- 可计入行为来源
- 计入条件
- 不计入情况
- 协助计入

### 积分 / 贡献类模块

适合结构：

- 积分计算
- 贡献记录
- 普通成员贡献位置
- 展示规则

### 排行 / 追赶类模块

适合结构：

- 排行规则
- 刷新规则
- 追赶提示
- 异常展示

### 结算 / 奖励类模块

适合结构：

- 结算锁定
- 奖励资格
- 奖励发放
- 未领取处理

### 结果展示 / 后续预告类模块

适合结构：

- 结果保留
- 阶段回顾
- 后续预告
- 展示边界

## 表格降噪规则

保留必要表格，但不要用表格替代正文判断。

优先顺序：

1. 每个模块先用 1 段正文说明它解决什么问题。
2. 条件、来源、状态枚举适合表格。
3. 简单规则优先用短段落或列表。
4. 同一条规则不要在多个表格里重复出现。
5. 配置项表格保留，但配置项必须挂回所属模块。

## DeepSeek 系统提示词

```text
你是资深游戏系统策划与中文 GDD 编辑。你擅长把系统规则稿优化成正式可交付 GDD：表达清晰、机制因果明确、边界干净、读感顺滑。请严格基于给定上下文，不新增未被上下文支撑的玩法、数值、奖励或后续系统规则。

重要要求：模板只能作为完整性检查清单，不能作为正文小标题来源。正文标题必须按功能职责命名，避免“口径 / 操作与响应 / 触发条件 / 规则与结算 / 边界与异常”等模板腔标题。
```

## DeepSeek 用户提示词模板

```text
请基于下面的 GDD 文档做“交付版降噪优化”，输出完整 Markdown 正文。

这份文档内容基本正确。你的任务不是重新设计，也不是缩写，而是在保留完整度和规则边界的前提下，让它更像正式可交付 GDD。

优化目标：
1. 保留原有功能范围，不新增玩法规则、具体数值、奖励内容或排期。
2. 保留核心章节：需求目的、需求概述、整体流程、功能设计、UE 交互、附属规则与配置、待定项。
3. 模板只作为检查清单，不要照抄模板标题。
4. 小标题必须按功能职责命名，例如“阶段开启与参与资格”“成员行为计入”“军团积分与贡献记录”“排行与追赶反馈”“结算与奖励领取”“结果保留与后续预告”。
5. 不要使用“开放与参与口径”“操作与响应”“触发条件”“规则与结算”“边界与异常”等模板腔标题。
6. 每个模块先用 1 段正文说明它解决什么问题，再给规则、表格或列表。
7. 合并重复内容，同一条规则不要同时出现在多个表格里。
8. 保留普通成员贡献路径：低战力、低活跃、晚加入或非高竞争玩家，仍应能通过基础目标、协助、防守或共同任务获得贡献。
9. 后续 GVG、沙盘、战役、威望只可作为方向性预告，不得写成本文完整规则。
10. 不输出解释，不输出代码围栏，只输出完整 Markdown 正文。

【待优化文档】
{{目标文档全文}}

【项目上下文】
{{必要上下文摘录}}

【模板检查清单，仅用于完整性校验，不得照抄为正文标题】
{{GDD模板摘录或检查项}}
```

## 输出自检

输出后必须检查：

- 标题是否都是业务职责，而不是模板栏位。
- 是否出现“开放与参与口径”等不自然标题。
- 是否把“参与方式”和“参与资格”混用。
- 是否保留阶段状态、无军团、中途加入、换团、重复计入、上限、结算锁定、未领取奖励、后续预告边界。
- 是否把后续 GVG / 沙盘 / 战役 / 威望写成了本文规则。
- 是否保留待确认项，且待确认项不承载主功能成立性。
