# 项目标准 — 这只怪能养吗

与 `reference/部门标准/策划/gdd/GDD写作标准.md` 配合使用。本文件只在规则层基础上增加约束或扩展章节，不替换规则层定义。

---

## 一、项目背景

微信小游戏端即时地牢肉鸽抓宠游戏。核心机制：在地牢里遇到的怪都能养成宠物；每次进地牢的 Build（局内技能组合）都不一样。

三层爽点：
1. 肉鸽 Build 爆发（临时技能组合成型时高伤害爽感）
2. 抓到新宠物（稀有宠物强化收集欲）
3. 养成突破（宠物解锁新技能，技能池扩展）

---

## 二、术语表

| 术语 | 定义 |
|---|---|
| 肉鸽 Build | 每局内积累的临时技能组合；局结束后不保留 |
| 局内 Build | 同上（简称） |
| 战斗房（⚔️） | 进入自动触发战斗，战斗系统返回胜负，胜利后结算；含普通（3 选购买）/ 精英（4 选高品质购买）/ Boss（退出循环+通关结算）三个子类型，逻辑一致、配置区分 |
| 随机事件房（❓） | 无战斗；系统自动抽取事件并直接触发结果 |
| 自选节点（🎁） | 进入自动触发挑战；完成后免费 3 选 1 技能，不消耗货币 |
| 配方 | 策划配置的各类型房间数量组合（战斗N / 精英N / 事件N / 自选N / Boss1） |
| 约束随机 | 按排列约束随机生成房间序列的默认模式 |
| 纯随机 | 关闭所有约束直接随机，仅用于测试和验证配方 |
| 购买池 | 战斗房（普通/精英子类型）胜利后可选的物品列表；各池独立配置 |
| 技能来源池 | 当前局可用技能全集，由战斗系统提供 |
| 排列约束 | 连续上限 / 早期保护 / 事件分布 / Boss 锚定 / 自选位置 五类约束开关 |
| 局外大厅 | 进入地牢前的主界面；队伍选择和关卡入口在此 |

## 三、模块边界（与战斗系统的接口）

战斗类房间委托战斗系统接管，以下为接口边界定义。

| 节点 | 传入战斗系统 | 战斗系统返回 | 本系统后续处理 |
|---|---|---|---|
| 战斗房（普通/精英/Boss 子类型） | 敌人配置 ID（Boss 额外传最终 Build） | 胜利 / 失败 | 胜利 → 按子类型结算（普通3选/精英4选购买，Boss 通关结算返回大厅）；失败 → 死亡流程，保留死亡前奖励 |
| 自选节点 | 自选挑战配置 | 完成 / 失败 | 完成 → 展示 3 选 1 技能界面；失败 → 死亡流程 |

## 五、特殊约束

以下约束比规则层更严格，本项目所有 GDD 必须遵守：

1. **接口边界必须定义**：所有委托战斗系统的节点必须明确定义接口边界（传入什么 → 返回什么 → 本系统如何处理），不得仅写"战斗系统接管"。
2. **离线场景必须覆盖**：异常处理（规则层 c）必须包含玩家离线场景的系统响应和兜底行为；微信小游戏断网概率高，不可省略。
3. **正式关卡禁用纯随机**：正式发布关卡的配方必须使用约束随机模式；纯随机只用于测试，必须在文档中标注"仅用于测试"。

## 六、系统扩展约束

以下系统具有特殊特征，在主标准基础上叠加额外约束。

### 关卡设计系统（含程序化生成）

关卡序列由系统按配方和排列约束随机生成，属于程序化生成系统。操作流程须额外满足：

- 必须说明使用的**生成模式**（约束随机 / 纯随机）
- 必须说明**生成逻辑**：配置输入 → 约束检查步骤 → 输出结构（不可只写"约束随机模式"）
- 必须覆盖系统支持的**所有主要模式**（约束随机和纯随机均须描述）
- 对多路线结构（分叉 / 混合），须分别说明各段的配方和约束配置差异

**Self-Review 补充判据**（在主标准判据三基础上叠加）：

| 判据 | 通过标准 | 不通过标准 |
|---|---|---|
| 程序化生成模式覆盖 | 操作流程说明了生成模式和生成逻辑；覆盖了约束随机和纯随机两种主要模式 | 操作流程只写了配方参数，未说明生成模式和逻辑；只覆盖一种模式 |
