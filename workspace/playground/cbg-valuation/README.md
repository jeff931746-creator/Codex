# 藏宝阁估价工作台

独立的本地网页实验，当前实现第一步：角色录入、分类行情样本管理、常规/精确匹配、分项报告与历史记录。没有调用估宝侠或浮游泡泡的付费接口，没有复制其服务端算法。

## 运行

在此目录运行 `python3 server.py`，访问 http://127.0.0.1:8765 。Python 3.10+，不需要额外依赖。仅监听本机。

## 阶段

1. 可视化工作台：录入 → 样本筛选 → 估价 → 报告；本地数据库可持久化。
2. 采集器：数据接入模块已增加逐条校验、时区标准化、重复去重、冲突保护、批次回执和分类覆盖统计。当前仅支持本地导入；受当前工具站点安全策略限制，未接入藏宝阁联网采集，不执行虚假的任务。
3. 实时分类估价：目标角色解析与按需刷新尚未接入。现有查询基于导入的数据库快照，不代表全服实时行情。

## 估价口径

- 当前标准模型为 `175-listing-v3`，目标是175级整号的合理挂牌参考，不冒充成交价。每条原始快照都会派生一份带模型版本、解析器版本和完整度的标准特征；原快照仍是数据真相源，派生特征可随时重建。
- 常规估号：同等级、同门派、同境界使用全服样本；把样本的人物修炼、宠修、师门技能、强壮和神速逐项校正到目标配置，再输出校正价格的加权中位点。该点位由时间前推A/B回测选择，不是手工追随单个目标价格。
- 精确估号：使用相同的逐项配置校正，采用加权20%低位挂牌。精确表示字段读取和价格校正更严格，不表示已经获得真实成交价。样本少于3条仍不出价。
- 报告同时输出有效样本量、目标/样本完整度、相似度综合置信等级和15%—75%挂牌观察区间。区服热度系数和成交价层保持关闭，直到存在可验证数据。
- 当前分项规则版本为 `2026-10-video-v1`：人物修炼和175师门技能使用2026年9月公开估价表的可核对档位；宠修使用15/20/25级公开参考档位；强壮、神速仅使用已核对的10至41级区间。未核对档位不会伪装成永久市场真值，后续应由采集行情和成交回测校准。
- 角色样本必须标记 `empty_verified: true`，表明不含装备、宝宝及外观的价值。不得把整号售价直接当空号价格。
- 当前只估挂牌参考价。状态仅接受 `listed`；失踪或下架不作为成交。报价默认排除超过7天快照，同一商品使用最后一条快照。
- 未估到的分项不是零元。任何缺项都会阻止整号总价生成。外观计价可选，默认关闭。
- 观察区间是样本分位数，不是经过校准的统计置信区间。

## 标准模型与回测

- `snapshots` 保存不可覆盖的原始商品观察；同一商品不同时间形成价格与状态历史。
- `model_features` 保存可重建的标准化特征，绑定 `model_version` 和 `parser_version`，未知字段保留为 `null`，不会当作零。
- `POST /api/backtest` 运行时间前推回测：每个被估样本只能看到更早的快照，并报告人民币绝对误差中位数、百分比误差中位数、方向偏差和高估比例。
- 回测同时保存“同等级、同门派、同境界原始挂牌中位数”基线。新规则只有误差低于基线时才有证据表明改动有效。
- 资产组只有在官方详情字段实际出现时才能记录为0；未返回的装备、召唤兽或外观字段保持未知，避免把采集缺失当作空资产。
- 回测结果写入 `model_backtests`。在可靠的成交/售出标签出现前，回测对象仍是后续挂牌价，因此只能衡量挂牌模型一致性。

## 导入格式

行情数据库中粘贴 JSON 数组或 `{ "samples": [...] }`。单条格式：

```json
{
  "listing_id": "你的真实商品编号",
  "category": "role",
  "name": "175女儿村空号",
  "server": "状元坊",
  "price": 8000,
  "observed_at": "2026-10-27T10:00:00+08:00",
  "status": "listed",
  "empty_verified": true,
  "source_url": "https://xyq-m.cbg.163.com/cgi/mweb/equip/705/真实编号",
  "features": { "level": 175, "school": "女儿村", "realm": "渡劫", "cultivation": 76, "pet_cultivation": 43, "qianyuan": 7 }
}
```

类别：`role` 空号、`equipment` 装备/灵饰、`pet` 召唤兽、`item` 物品、`appearance` 外观。示例仅为格式说明，不随程序入库，也不视为市场数据。

后续应把修炼和技能从总和细化为各项等级、上限、技能组合等，精确匹配才有足够区分度。JSON属性允许自行补充。

## 校验

`PYTHONDONTWRITEBYTECODE=1 python3 -m unittest -v test_engine.py`

入库测试：`PYTHONDONTWRITEBYTECODE=1 python3 -m unittest -v test_ingestion.py`。

导入会返回新增、重复、冲突、拒收数量。合法记录入库，不合法记录显示行号和原因；原文本在有错误时保留，修正后可重新提交。相同商品与采集时间的冲突不会覆盖原快照。入库批次记录保存在 `ingestion_runs` 表，刷新页面后仍可查看。失败数据修正后重提，不对确定性的校验错误自动重试。

## 用户提供的角色响应

链接录入区域展开“导入角色响应，自动填写属性”，粘贴 `get_equip_detail` 响应正文，调用本机 `/api/parse-role-response`。目前解析 `equip.other_info`、`card_style` 等字段，保留各项修炼/上限、宠修和原始技能编号。技能名称映射、乾元丹、锦衣祥瑞仍待验证，不按未知字段猜测。价格单位未确认，原始 `price` 不换算、不作为市场样本入库；历史已取走商品也不会冒充当前在售。

这只打通手动提供响应后的解析，不代表已实现粘贴藏宝阁链接自动联网读取。HAR 导入同时支持手机版 JSON 接口和桌面版角色详情页；完整 HAR 只在浏览器本地扫描，只将提取的响应字段发给本机 `127.0.0.1` 解析，不使用 Cookie、Token 或请求头。已解析的资料保存在本机数据库 `offline_profiles` 表，与市场快照分开；刷新或换用本机其他浏览器会恢复最近一份资料。粘贴同一商品链接时优先查本机离线资料，明确显示响应时间及“未联网更新”。陌生商品链接会清空旧表单，不会沿用上一个账号数据。初始等级、门派、境界均为空，避免示例默认值被误当作读取结果。

## 离线详细属性解码

“离线详细资料解析”中选择 `get_equip_detail` 和 `equip_desc` 两份 JSON/TXT 文件，点击“解码并核对资料”。本机服务使用已验证的版本前缀/Base64/异或格式还原描述，再用受限 LPC 数据语法解析器读取映射和数组；不使用 eval，不执行上传文件的代码。校验两份响应的版本、角色编号及等级，任一不符则拒绝合并。

支持装备、召唤兽、坐骑、锦衣及外观、祥瑞分组。保留原始属性与编号，未知名称显示未映射。外观按条目而非套装计数。可导出结构化资料，未将附带资产自动转换成市场样本或估价。乾元丹、机缘等语义未核实字段仍不映射，原始字段保留在导出中。

也支持 Chrome 开发者工具导出的 HAR：在 Network 中保存 `HAR with content` 后，页面会在本机扫描 JSON 响应，自动寻找包含 `equip.other_info` 的商品响应和包含 `equip_desc` 的属性响应，再复用上述版本、角色编号和等级校验。完整 HAR、Cookie 和请求头不会发送到服务端或写入数据库；只有识别出的两段响应正文会提交给本机 `127.0.0.1` 解析接口。

验证命令：`PYTHONDONTWRITEBYTECODE=1 python3 -m unittest -v test_desc_parser.py`。用户提供的配套文件已通过实际离线验证：5件装备、0条召唤兽、3条坐骑、12条锦衣/外观、5条祥瑞；这反映文件内容，不代表当前实时资产。

## Chrome 一键同步扩展

`chrome-extension/` 是本地 Manifest V3 扩展，用于取代重复导出 HAR。安装方法：

1. 确保本机已运行 `python3 server.py`。
2. Chrome 打开 `chrome://extensions/`，开启右上角“开发者模式”。
3. 点击“加载已解压的扩展程序”，选择本目录下的 `chrome-extension/`。
4. 在 Chrome 登录藏宝阁并打开角色详情页，点击扩展图标后选“同步当前角色”。

扩展仅对 `xyq.cbg.163.com` 当前激活页生效，只返回隐藏角色属性、商品编号、区服和页面挂牌信息。它不读取 Cookie、Token 或浏览器历史，只发送到 `http://127.0.0.1:8765/api/parse-desktop-bundle`。本地服务只为该扩展路由开放受限跨域请求，不允许扩展调用行情导入或估价写入接口。

扩展同步时也会携带当前页面的官方装备、召唤兽、坐骑、锦衣、祥瑞以及召唤兽/坐骑技能枚举。资产卡片优先显示官方名称和技能，完整原始属性收在折叠区域中供核对。

在全服搜索结果页可选择连续采集1至20页。扩展保持当前搜索条件，依次读取当前页和“下一页”链接，列表页和详情请求均会限速；单次采集任务最多1000件商品。遇到无下一页、重复页面、空页面、登录验证或用户点击停止时立即结束，不会自行改变搜索条件。

扩展 2.1 支持每1小时、6小时、12小时或每天定时采集。启用时会绑定当前已设置筛选条件的全服搜索标签页；每次执行前回到结果第1页，再按所选页数采集。扩展弹窗和工作台网页可以关闭，但 Chrome、绑定的搜索标签页及藏宝阁登录状态需要保留。

扩展不会保存 Cookie、Token 或账号密码。每轮启动前会检查登录页；采集中连续两次无法读取角色详情时，会停止本轮、进入“等待登录”，在扩展图标显示“登录”徽标并发送 Chrome 系统通知。重新登录后点击“立即执行一次”即可恢复，后续定时任务也会继续按原计划运行。标签页缺失或出现验证时不会盲目重试。

召唤兽卡片按官方页面的信息层级展示详细属性、属性点与六项资质、技能、赐福技能、三件召唤兽装备和内丹。坐骑保留等级、成长、主属性和技能；锦衣与祥瑞使用紧凑图鉴网格。

同步成功后，扩展会将已打开的工作台切换到带 `listing_id` 的精确资料地址。后续刷新会继续读取该商品，不再依赖“数据库最近一条”的顺序。

## 技能展示

通过 Chrome 扩展或包含 `game_auto_config.js` 的 HAR 同步时，页面会同时读取藏宝阁当前官方的完整 `school_skill`、`life_skill`、`ju_qing_skill` 及剧情描述枚举。因此可覆盖全部当前门派的师门技能，不再依赖手写的单门派映射。`skill_catalog.py` 中的旧映射只作为没有官方配置时的备用。

`all_skills` 还包含藏宝阁官方前端本身不会当作技能展示的内部状态编号。这些项不再显示为“尚未映射的技能”，而是单独放在“官方未公开名称的内部编号”中，保留原值但不猜测名称。强壮230和神速237仍会回填基础表单。

这份账号文件实际包含7项师门技能、17项生活技能、7项剧情等已映射技能和35项未映射编号。已经在localhost浏览器中验证两份文件导入后的名称、等级、分组及强壮40/神速30的回填；控制台未观察到相关错误。

资料保存/查找测试：`PYTHONDONTWRITEBYTECODE=1 python3 -m unittest -v test_profiles.py`。浏览器已验证：空库不预填、导入保存、刷新恢复、陌生链接清空、原链接恢复。当前共27项核心测试。

数据存在本目录 `data/market.sqlite3`，不上传云端。当前工具用于开发验证；缺少真实采集和留出样本回测，不能声称已经实现精确市场估价。
