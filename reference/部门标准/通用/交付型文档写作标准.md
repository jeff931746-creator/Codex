# 交付型文档写作标准

本标准约束交付型 Markdown / 文本文档的表达方式。

交付型文档的第一目的，是帮助读者完成判断、形成决策、推进下一步动作。文档不以展示推理过程、铺陈解释、证明作者理解问题为目的。

## 第一性原理

当内容发生冲突时，优先保护决策价值。

判断内容是否保留，只看它是否改变读者的判断、决策或执行动作。不能改变上述三者的内容，应压缩、改写或删除。

## 表达优先级

默认按以下顺序组织内容：

1. 结论
2. 机制
3. 边界
4. 流向
5. 必要证据

过程痕迹、解释性铺陈、类比展开、无执行消歧价值的例子，不应进入交付正文。

## 示例化表达约束

交付型文档默认不写示例化内容。

只有满足以下条件之一时，才允许保留示例化内容：

- 用户明确要求提供样本。
- 不提供样本会导致执行歧义。
- 标准、模板、测试材料本身需要承载样本。

如果示例化内容不能改变判断或执行动作，应改写为判断、机制、边界、流向，或直接删除。

允许保留时，必须在需要保留内容的上一行写入隐藏标记，并声明原因：

`<!-- delivery-writing:allow-example reason="execution-disambiguation" -->`
