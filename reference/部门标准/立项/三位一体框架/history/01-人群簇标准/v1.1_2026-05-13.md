## 这是什么

人群簇是在半意识心理任务上具有稳定共性的用户群体。本文档定义人群簇的字段、命名规则、boundary、主副簇规则和填库流程。

详细的推演过程、验证逻辑、哲学基础请见 [人群簇分析方法论](../../../../archive/方法论/立项/人群簇分析方法论_2026-05-13.md)。

## 一句话定义

```text
人群簇 = 在半意识心理任务上具有稳定共性的用户群体，
       通过承接偏好选择不同内容/游戏形态进行任务处理。
```

人群簇的公分母是**用户在用内容处理什么半意识的心理任务**，不是年龄、性别、品类、题材或玩法。

## 公分母：心理任务（一级维度，6 个）

| 编号 | 任务 | 处理的状态/缺口 | 典型外显行为 |
|---|---|---|---|
| T1 | 情绪调节 | 处理焦虑、压抑、疲惫、无聊 | 刷爽文、玩消除、看治愈剧 |
| T2 | 自我确认 | 确认"我是谁、我有价值、我没掉队" | 看战神文、PVP上分、晒收藏 |
| T3 | 亲密连接 | 获得被看见、被需要、虚拟亲密 | 看乙女、养角色、追恋综 |
| T4 | 协作归属 | 在群体中有位置、有职责、被依赖 | SLG联盟、公会副本、社群协作 |
| T5 | 认知扩展 | 理解世界、解码规则、满足好奇 | 玩解谜、读悬疑、看科普 |
| T6 | 控制感重建 | 在不可控生活中建立可控小世界 | 玩模拟经营、SLG霸服、建造类 |

### 任务划分原则

- **互斥**：每个簇必须有 1 个主任务，不能"两个都是主"
- **可识别**：必须能通过用户行为反推（留存、付费、评论）
- **稳定**：跨媒介出现，不依赖单一品类或题材

### 任务边界提醒

| 易混对 | 判据 |
|---|---|
| T2 自我确认 vs T6 控制感重建 | T2 是"我个体强/有价值"（向内），T6 是"我让系统按我规则运转"（向外） |
| T3 亲密连接 vs T4 协作归属 | T3 是情感关系（亲密/陪伴），T4 是任务关系（协同/依赖） |
| T1 情绪调节 vs T2 自我确认 | T1 是处理状态（缓解负面），T2 是获取意义（确认存在） |
| T5 认知扩展 vs T6 控制感重建 | T5 是被未知吸引，T6 是给秩序加诸于世界 |

### 潜伏待定（暂不立任务，演进观察清单）

- **价值秩序校准**（看打脸/审判/伦理剧的核心驱动）：暂归入 T2 自我确认 或 T6 控制感重建
- **习惯维持/仪式延续**（棋牌、麻将、社交习惯）：暂归 T1 情绪调节，副任务标 T4

演进条件见 [人群簇分析方法论](../../../../archive/方法论/立项/人群簇分析方法论_2026-05-13.md) 的"待演进路径"。

## 承接偏好（二级维度，4 个）

| 编号 | 偏好 | 处理方式 | 典型内容/玩法 |
|---|---|---|---|
| P1 | 强刺激覆盖 | 用爽、笑、吓、爆发压过原状态 | 爽文、爆装、割草、搞笑、恐怖 |
| P2 | 情感共鸣 | 用相似情绪疏导原情绪 | 治愈、恋爱、剧情、陪伴 |
| P3 | 低负荷转移 | 用简单重复、低反馈把注意力挪走 | 消除、放置、美食、日常 |
| P4 | 系统模拟 | 进入一个可计算、可反馈、可优化的小系统 | SLG、经营、建造、解谜、策略 |

### P4 系统模拟的内部收益（必填）

| 编号 | 系统收益 | 核心满足 | 典型承接 |
|---|---|---|---|
| Y1 | 竞争排名 | 我比别人强 | PVP、榜单、战力、联盟战 |
| Y2 | 协作分工 | 我在组织里有位置 | 公会、团队副本、联盟协作 |
| Y3 | 秩序优化 | 我能把系统变高效 | 经营、建造、资源链路 |
| Y4 | 规则解码 | 我能理解复杂规则 | 解谜、构筑、策略 |

### 承接偏好划分原则

- 4 个偏好**不要求严格正交**，是处理方式的分类，不是数学维度
- 每簇必须有 1 个主承接偏好；不允许两个并列
- 系统模拟（P4）下必须指定一个系统收益（Y1-Y4）

## 现实约束（筛选器，不进命名）

现实约束**不是第一性维度**，不进人群簇命名。但它决定承接形态和付费深度，每个簇必须在"承接条件"字段中标注。

| 约束 | 影响 |
|---|---|
| 时间结构 | 碎片时间 → 小游戏、放置；整块时间 → SLG、主机 |
| 认知带宽 | 低带宽 → 强反馈、少规则；高带宽 → 策略、构筑 |
| 经济能力 | 高ARPU → 排名/稀缺资源；低ARPU → IAA、轻订阅 |

## boundary 规则（核心防呆）

boundary 字段不是可选说明，是 12 簇能稳定区分的关键机制。每个新增条目必须填 boundary，至少说清楚与**最相邻的 1-2 个簇**的差异。

**v1.1 共有 13 对 boundary 判据**：5 对继承自 v1.0（作用域类），8 对在 v1.1 新增（基于 230 真实样本验证的错归案例）。

### v1.1 新增 8 对硬判据

| 边界 | 判据 |
|---|---|
| **C01 vs C03** | C01 是高唤醒、短时情绪冲击；C03 是低唤醒、低负荷注意力转移。跑酷/消除/找茬默认 C03，除非核心卖点是爆炸/暴力/恐怖/速度压迫 |
| **C01 vs C10** | 恐怖如果核心是"被吓/释放紧张"归 C01；如果核心是"探索未知/解谜/理解真相"归 C10 |
| **C03 vs C04-C** | 低操作不等于 C03。若长期目标是战力/境界/数值膨胀/碾压别人 → C04（标 C04-C 数值碾压）；若只是消磨时间/重复轻反馈 → C03 |
| **C04 vs C05** | C04 是战胜内容/怪/关卡后确认自己；C05 是战胜真人/排名/竞技系统后确认自己。PvP 撤离/竞技/排位优先判 C05 |
| **C04 vs C05 (PvPvE)** | PvPvE 类产品按"用户最终验证场景"判断：高光时刻是"PvP 中干掉真人" → C05；高光是"刷到稀有装备" → C04-B |
| **C04 vs C10** | ARPG 默认不归 C10。**显式机制歧义判据**：若两个产品都有"构筑"机制（如杀戮尖塔 vs 暗黑），用"最终满足来源"区分——构筑通向"我破解了规则"（解读完整后退场） → C10；构筑通向"我变强了，下一关需要更强的我"（持续追求下一目标） → C04 |
| **C04 vs C11** | 修仙若核心是境界压制/战力膨胀 → C04；若核心是经营门派/资源秩序/生产链 → C11 |
| **C07 vs C08** | C07 是我和角色/对象的亲密关系；C08 是我和团体的情感归属。武侠 MMO 不因有剧情情感就归 C07 |
| **C08 vs C09** | C08 是团魂/陪伴/情义；C09 是职责/分工/组织任务。临时合作和工具协作优先 C09 |
| **C10 vs C11** | C10 是破解规则；C11 是优化系统。文明/4X 如果满足来自"理解复杂规则" → C10；如果满足来自"把国家/城市/资源链经营起来" → C11 |

### v1.0 继承的 5 对作用域 boundary

#### 一对：C05 vs C12（个体勇武 vs 系统统治）

| 维度 | C05 个体排名证明 | C12 系统统治支配 |
|---|---|---|
| 满足来源 | "我比对手强"（个体勇武感） | "我让服务器按我规则运转"（系统统治感） |
| 付费动机 | 个人战力、武器、皮肤 | 联盟资源、地图控制、规则话语权 |
| 主战场 | PVP 1v1 / 排位 | 联盟战、跨服争霸、统治区域 |
| 典型 | 王者荣耀、和平精英、传奇老用户 | SLG 大R、权游、宫斗深度玩家 |

**判据**：满足感的指向是"个体"还是"系统"。

#### 一对：C06 vs C11（个体炫耀 vs 系统自洽）

| 维度 | C06 系统流派炫耀 | C11 秩序经营掌控 |
|---|---|---|
| 满足来源 | "我比别人更懂这个系统"（向外炫耀） | "我让世界井然有序"（向内自洽） |
| 行为 | 晒阵容、晒流派、攻略输出 | 自我消费、不主动展示 |
| 付费动机 | 强度、外观、稀有资源 | 扩展、解锁、内容深度 |
| 典型 | 修仙凡人流、小红书穿搭、晒阵容 | 星露谷、Factorio、动物森友会 |

**判据**：满足感是否需要"被看见"。

#### 一对：C03 vs C10（低负荷 vs 高认知）

| 维度 | C03 低负荷转移 | C10 规则解码 |
|---|---|---|
| 操作负担 | 极低（点点/挂机） | 中高（思考/构筑） |
| 认知投入 | 极低（注意力转移） | 高（解码规则） |
| 付费 | 广告/小额 | 内容/解锁/挑战 |

**易混样本**：羊了个羊（低负荷但极难）、保卫向日葵（看似低负荷但有解谜）
**判据**：用户进入的目的是"消磨" → C03；是"破解" → C10。两者都强时按主留存归簇。

#### 一对：C07 vs C04（拟亲密 vs 自我确认）

| 维度 | C07 拟亲密关系 | C04 逆袭爆发确认 |
|---|---|---|
| 主体投射 | 我和角色的关系（你/Ta 视角） | 我成为这个角色（我视角） |
| 情感方向 | 双向情感（被爱/被需要） | 单向爽感（碾压/逆袭） |
| 典型 | 乙女、霸总短剧女主、原神角色 | 战神短剧、赘婿、斗罗大陆 |

**易混样本**：复仇/打脸甜宠类短剧（女主复仇）
**判据**：用户视角是"主角化身"还是"关系参与者"。

#### 一对：C09 vs C12（协作 vs 统治）

| 维度 | C09 组织协作分工 | C12 系统统治支配 |
|---|---|---|
| 满足核心 | "我有位置，被组织依赖" | "我让组织按我规则运转" |
| 角色定位 | 团队中的工具/职能位 | 团队的领导者/支配者 |
| 典型 | 三国志战略版中下层玩家 | SLG 大R盟主、跨服霸主 |

**判据**：满足感来自"参与"还是"主导"。同一款 SLG 内不同玩家可能分属不同簇。

### boundary 填写规则

每个人群簇正式条目必须包含：

```yaml
boundary:
  - "与 C-XX 的区别：[具体差异点]，依据是 [可观察的行为/付费特征]"
  - "与 C-YY 的区别：..."
```

最少 1 条 boundary（与最相邻簇的区别），最多 3 条。

## 主副簇规则

### 主簇原则

每个产品/内容样本必须有 **1 个**主簇。主簇由以下三个优先级判断：

```text
1. 用户为什么长期留下来？（留存动机）
2. 用户为什么愿意付费？（付费动机）
3. 素材钩子主要承诺什么？（点击动机）
```

**冲突时按 2 > 1 > 3 排序**。例如 SLG 大 R 广告打"我是大佬"（点击靠 C04），但实际付费来自联盟责任和资源控制（C12），主簇按 C12。

### 副簇规则

副簇允许标 **0-2 个**，用于解释：

- 复合承接产品（如原神同时承接 C07/C02/C10）
- 跨簇用户重叠（如 SLG 既有 C09 协作型也有 C12 统治型）
- 素材方向与留存簇不同时的标注

**禁止**：超过 2 个副簇 → 说明产品定位模糊或归类失败

### 失败指标（新）

复合归类率（含副簇率）**不再作为失败指标**。真正的失败指标：

| 指标 | 阈值 | 含义 |
|---|---|---|
| 无簇可归率 | >10% | 矩阵漏维度 |
| poor 质量率 | >15% | 簇定义不清 |
| 主簇不可解释率 | >20% | 主簇判断规则失效 |
| 副簇 > 2 个率 | >10% | 簇耦合或产品模糊 |

## v1.1 三层分离原则（不可互换）

```text
人群簇层  = 心理任务 × 承接偏好（第一性，进入 12 簇定义）
承接形态层 = 操作深度 / 成长结构 / 商业化模式 / 付费深度（次生，作为观察标签）
产品视角层 = 主流 / 衍生 / 顶部（应用注释，不进标准结构）
```

**硬规则**：

- 承接形态层不能反推人群定义（用玩法/付费分类人群是错的）
- 产品视角层不能定义人群（C12 不是"顶部小众人群"，是"产品中常以高 ARPU 形态出现的完整人群"）

**最重要的新边界**：

```text
心理任务相同 ≠ 用户画像相同
心理任务相同 ≠ 渠道人群重合
心理任务相同 ≠ 素材可共用
心理任务相同 ≠ 商业模型可互迁
```

立项时只写"目标人群是 C04"不够，必须同时给出**承接形态、媒介适配、现实约束**。

### 观察标签：归类后的描述工具，不是归类工具

```text
观察标签只能用于"同一心理任务下的承接形态差异"。
不能用于掩盖"心理任务不一致导致的错归"。
```

**准入条件**（必须全部满足）：

1. 该簇内所有样本，通过"归类三问"重答，主任务收敛到同一个 T
2. 该簇内样本的产品外显结构一致指向该 T
3. 反向投射验证：隐藏簇 ID 让 LLM 重判，5 个样本中 ≥4 个归同一 T
4. 标签描述用承接术语（操作 / 付费 / 商业化），禁止用心理术语
5. 不生成新 ID，不进入 12 簇结构

**失败处理**：若反向投射显示 >30% 样本不归同一 T，**不能强行保留观察标签**，应在簇定义里标注"此承接形态在用户层面存在心理任务分化，立项时需明确目标 T"。

## v1.1 完整归类流程（6 步）

```text
Step 1: 心理任务判定（T1-T6 / T7-candidate）
  问：用户长期留下来的核心动机是什么？
  禁止：用品类 / 题材 / 玩法 / 操作强度反推

Step 2: 承接偏好判定（P1-P4）
  问：用户用什么处理方式完成这个心理任务？
  禁止：用付费深度反推

Step 3: 候选簇定位（根据 T × P 落入）

Step 4: boundary 排除复核
  对照该簇所有相邻簇的 13 对 boundary 硬判据
  必须显式回答"为什么不是 C-XX"

Step 5: 错归筛查（针对历史大簇 C03/C04/C10）
  C03 → 走 C03 vs C04-C / T7-candidate 排除 checklist
  C04 → 走 C04 vs C05/C10/C11 排除 checklist
  C10 → 走 C10 vs C04/C11/C05/C07 强制排除 checklist
  排除规则不通过 → 重归

Step 6: 输出
  主簇 + 副簇（0-2 个） + 置信度（high/medium/low） + 错归筛查理由
```

**置信度判定**：

| 置信度 | 含义 |
|---|---|
| high | 三问 + 反向投射一致，无相邻簇候选，错归筛查通过 |
| medium | 三问一致，反向投射有边界样本，相邻簇候选 1 个 |
| low | 三问不一致，或反向投射不收敛，**必须人工复核** |

### 三问硬规则

```text
1. 用户主要为什么留下？
2. 用户主要为什么付费或持续投入？
3. 素材承诺和真实留存是否一致？（不一致时按留存）
```

**禁止**：点击动机、品类、题材、操作强度都不能直接定主簇。

## v1.1 历史大簇错归筛查（强制 checklist）

### C03 错归筛查

进入 C03 前必须显式排除：

```text
Step 1: 低操作不是 C03 的充分条件
  问：该产品的主循环是否显式围绕战力/境界/等级/装备/资源效率/推图卡点/排行榜/付费加速展开？
  是 → 排除 C03，优先排查 C04-C 数值确认型
  否 → 继续

Step 2: 判断是否承载固定社交/仪式关系
  问：该产品是否主要承载用户的熟人局/固定打卡/社交仪式？
  是 → 标记 T7-candidate（习惯维持候选），暂挂 C03? 不直接归 C03
  否 → 继续

Step 3: 剩下的才是真正的 C03
  问：用户进入的目的是不费脑地转移注意力，失败可退出，不强刺激？
  是 → C03
```

**C03 vs C04-C 的产品外显结构 checklist**：

| 判据 | 倾向 C03 | 倾向 C04-C |
|---|---|---|
| 主循环 | 一局一局玩、轻目标、随进随出 | 签到、养成、推图、升战力 |
| 成长压力 | 弱，失败也可退出 | 强，卡点驱动养成/付费 |
| 数值系统 | 轻道具/关卡进度 | 战力、境界、装备、资源效率 |
| 付费点 | 去广告、复活、道具、体力 | 加速成长、资源包、战力、抽卡、冲榜 |
| 素材承诺 | 放松、解压、简单、有趣 | 变强、逆袭、渡劫、爆装、碾压 |

**C03 vs T7-candidate 的三维区分**：

| 维度 | C03 | T7-candidate |
|---|---|---|
| 用户连接对象 | 内容本身（消除/找茬/合成）| 社交场景 / 习惯仪式 |
| 替换性 | 容易被其他低负荷内容替代 | 难替代（熟人局、固定打卡）|
| 卸载阻力 | 低（不玩了就不玩了）| 高（社交关系/仪式中断）|

**关键判据**：该产品是否承载用户的固定社交/仪式关系？是 → T7-candidate；否 → C03。

### C04 错归筛查

进入 C04 前必须显式排除：

```text
1. 是否主要靠 PvP 战胜真人？是 → C05
2. 是否主要靠经营秩序？是 → C11
3. 是否主要靠规则解码（构筑后退场）？是 → C10
4. 都"否" → 真 C04
```

### C10 强制排除 checklist

进入 C10 前必须显式回答四个问题：

```text
1. 本样本是否主要靠战斗成长？  是 → 排除 C10，归 C04
2. 本样本是否主要靠经营秩序？  是 → 排除 C10，归 C11
3. 本样本是否主要靠竞技胜负？  是 → 排除 C10，归 C05
4. 本样本是否主要靠剧情亲密/情感？是 → 排除 C10，归 C07/C02

四个都"否"，且满足下面任一条件，才能进 C10：
- 用户的核心快感来自"我理解了规则"
- 用户的核心快感来自"我破解了谜题"
- 用户的核心快感来自"我构筑出有效解"
- 用户的核心快感来自"我掌握了复杂系统的运行逻辑"
```

**复合产品的"主要靠"判定** —— 用"用户卡关时的本能反应"反推：

| 用户卡关时本能反应 | 主要靠 | 归簇 |
|---|---|---|
| "我等级不够，去刷怪/刷装备" | 战斗成长 | C04 |
| "这关有什么机制我没想到？" | 规则解码 | C10 |
| "我经济没建好/资源不够" | 经营秩序 | C11 |
| "对手太强，我得练手感/上分" | 竞技胜负 | C05 |
| "我想看主角和 NPC 关系发展" | 剧情亲密 | C07 |

这条"卡关反应"判据用于解决 Avowed / 暗区突围 / 太吾绘卷等**复合产品**的归簇歧义。

**C10 入簇时强制标注核心解码维度**（观察标签，不分簇）：

```yaml
c10_subdimension:
  - puzzle: 解谜推理（纪念碑谷、机械迷城、Disco Elysium）
  - build: 构筑策略（杀戮尖塔、Balatro、自走棋）
  - rule_decode: 复杂规则解码（文明、群星、矮人要塞、太吾绘卷）
```

## T7 习惯维持（候选状态）

v1.1 引入候选任务状态，处理棋牌/麻将/仪式型消费。

**候选定义**：

```text
T7 习惯维持 / 仪式延续：
用户不是为了内容刺激、情绪疏导、变强、亲密、协作或解码，
而是为了维持日常节奏、熟人局、固定仪式和低成本社交惯性。
```

**候选状态记法**：`T7-candidate` 或 `C03?`，**不直接归 C03**。

**激活路径**（升级为正式任务）：

```text
1. 连续累积 ≥10 个标 T7-candidate 的样本
2. 这些样本的主驱动都不是 T1-T6 任意一个
3. 主留存来自固定习惯/仪式，而非内容反馈或系统成长
4. 触发新增任务 T7 的提案
```

**非激活路径**（撤回候选状态）：

```text
如果累积过程中样本实际可归 T1（消磨时间）或 T4（社交仪式），
说明 T7 没有独立必要，候选状态解除。
```

## v1.1 新验证指标

v1.0 用"归类成功率 100%"作为通过指标，被证明粒度太粗（任何样本都能塞进 12 簇）。

**v1.1 新验证指标**（多维度）：

```text
1. 错归率
   明显违反 boundary 的样本占比，目标 <5%

2. 相邻簇冲突率
   同一样本在 C04/C10、C03/C04 等之间摇摆的比例，目标 <10%

3. 主簇置信度分布
   high / medium / low。low 样本必须进入人工复核
   目标：high >70%，low <10%

4. 跨标注一致率
   同一批样本由两次独立标注（换 prompt 或换模型），主簇一致率
   目标 >80%

5. 预测有效性（长期，需要真实数据）
   主簇能否预测素材钩子、留存原因、付费动机
```

**新验证结论判定**：

```text
不是"能归类 = 通过"
而是"能稳定归类 + 能解释留存/付费 + 能指导素材 = 通过"
```

### 反向投射验证

观察标签准入和 C04 类大簇验证必须做反向投射，防止 LLM 复读原归类。

**反向投射设计原则**：

```text
A. 换 prompt：不给原簇结果，只问"这几个样本共享的心理任务是什么？"
B. 换输入粒度：隐藏原簇 ID 和归类理由，只保留产品名 + 核心循环 + 付费驱动 + 素材承诺
C. 换模型或换轮次：理想用不同模型，至少用新会话+新 prompt
```

**反向投射 prompt 强制要求**：

```text
对每个产品，回答以下三个问题，每个问题只能用 T1-T6 或 T7-candidate 之一：
1. 用户的核心留存驱动属于哪个心理任务？
2. 用户的核心付费动机属于哪个心理任务？
3. 素材承诺主要承诺哪个心理任务？（信息项，不参与主簇判断）

然后回答：5 个产品的"核心留存驱动"是否都收敛到同一个 T？
```

**拒绝答案**：

```text
- "它们都是 XX 品类" ❌
- "它们都需要 XX 技能" ❌
- "它们都有 XX 机制" ❌
这些都不是心理任务，必须要求 LLM 重答。
```

**通过标准**：

```text
5 个样本中 ≥4 个收敛到同一 T，且理由来自留存/付费/核心循环 → 允许观察标签
低于 4 个，或理由主要是"都低操作/都修仙/都动作" → 不允许观察标签，必须重归
```

## 填库工作流

### 新增人群簇实例

```text
1. 提案：说明拟新增条目的主任务、主承接、boundary 草案
2. 草稿：在 archive/资料/人群簇库/_draft/ 下新建草稿，文件名 draft-AUD-CXX-XXX.md
3. 自检：必填字段、boundary、代表案例 ≥3 个（跨媒介）、证据等级
4. 评审：用户审批
5. 归档：移到正式库，分配 ID 和加入索引
```

### 评分维度说明

#### 获量难度（acquisition_difficulty）

| 分数 | 含义 |
|---|---|
| 1 | 极易获，主流买量渠道任何素材都能命中 |
| 2 | 容易获，主流买量渠道，标准素材模板可覆盖 |
| 3 | 中等难度，需要针对性素材策略 |
| 4 | 较难，人群分散或CPI较高 |
| 5 | 极难，仅特定渠道或长期内容运营才能触达 |

#### LTV 潜力（ltv_potential）

| 分数 | 含义 |
|---|---|
| 1 | 极低，主要靠广告变现 |
| 2 | 较低，付费转化率低，ARPPU 低 |
| 3 | 中等，有月卡/小额付费 |
| 4 | 较高，有抽卡或大R付费 |
| 5 | 极高，重氪渠道明确，大R潜力强 |

### 跨媒介证据要求

| 证据级别 | 要求 |
|---|---|
| S | 跨 3+ 媒介验证 + 内部产品数据支撑 |
| A | 跨 3+ 媒介验证 |
| B | 跨 2 类媒介验证 |
| C | 单一媒介或推演假设 |
| D | 假设阶段，未验证 |

骨架阶段（人群簇库初建）允许游戏+影视反推作为 B 级证据。条目晋升 A/S 前必须补跨媒介证据。
