# 成功复盘 SOP

> 本 SOP 仅用于"已经在市场上成功的竞品分析"。自己尚未做的玩法构想走 [07a-立项分析SOP.md](07a-立项分析SOP.md),两者方向相反,不可混用。

---

## 一、目的与适用场景

- **目的**:理解 N / T / A / F 四层在**成功产品**上是如何协同的,提炼可迁移规律
- **输入**:已经成功的竞品(榜单稳定、留存付费数据可验证、上线超过 3 个月)
- **输出**:可迁移的承接组合规律 + 反例累积(违反硬约束但成功的案例)+ 可选的框架修订建议
- **不适用**:自己尚未做的玩法构想(必须走 07a 文档)

---

## 二、核心心法

> **理解为什么这个 N / T / A / F 组合能成功,不是判断它"对不对"。**

复盘阶段的惯性陷阱是"用框架挑刺 → 这个竞品违反框架某条 → 框架错了 / 它也错了"。这是把框架当成"成功必要条件"的误解。框架是**失败避免条件**,违反框架但成功的产品,通常是用不可迁移因素(IP / 团队 / 时机 / 渠道)弥补了承接缺陷。复盘的方向是**反推为什么用户接受**,而不是判罚。

---

## 三、强制流程(5 步)

### Step 1 [中立拆解,不带预设]

- 用 v1.2 yaml 字段独立拆产品
- **禁止**:此阶段带"它符合框架 / 它不符合框架"的预设
- 必填字段同 v1.2 模板,但所有判断写"观察到 X"而非"X 是对 / 错"

### Step 2 [反例承认,违反硬约束不立刻判错]

如果该产品违反某条硬约束(H1-H5)但已成功,先问 3 个问题:

1. **是不是本质上是"特例"**(IP / 团队 / 时机 / 渠道 / 创始人个人影响)?
2. **是不是市场容忍度 vs 体验有 trade-off**(用户知道体验有问题但仍买单,如氪金型 SLG)?
3. **是不是硬约束有"成功容忍区间"未被框架捕捉**(框架本身需要修订)?

**把违反内容写入 `counterexample_log` 字段**(见 01 文档"反例累积机制"小节)。每个反例必填:`product` / `violates` / `why_succeeded` / `framework_lesson` / `logged_date`。

### Step 3 [成功机制识别]

拆分该产品的承接贡献度:

- **哪几层(N / T / A / F / THM)是核心承接**,各自贡献了多少留存付费(定性即可,有数据更好)
- **哪几层是装饰**(可替换、可弱化、玩家不在意)
- **各层相互喂养关系**:T 由哪些 A / F 撑住,THM 怎么放大 T,A / F 之间是否互补

### Step 4 [可迁移性判断]

对识别出的成功机制,逐条问:

- **组合本身能否复用**(只要做出同样的 N+T+A / F+THM 组合就能复现)?
- 还是**依赖了不可迁移因素**(米哈游级 IP、网易级渠道、独占发行档期、某个独特创始人)?

只有"组合本身能复用"的部分,才进入可迁移规律库。依赖不可迁移因素的部分,只做"已知特例"记录,不进规律库。

### Step 5 [框架修订建议(可选)]

- 反复观察到产品违反某条硬约束但成功 → 触发框架修订提案
- **累积 ≥ 3 个针对同一硬约束的反例时**,触发该硬约束的修订评估(写入 01 文档的 `evolution_trigger` 字段)
- 修订提案在主对话讨论,不在 SOP 内直接改框架


用于和 07a 立项分析产物在数据层区分。

---

## 五、典型错误模式

- **错误 1**:用框架挑刺 → 反推"框架错了"。正确做法:问"为什么用户接受",硬约束是失败避免条件,不是成功必要条件
- **错误 2**:误把不可迁移因素当成可迁移规律(米哈游 IP / 独占档期 / 创始人个人影响 → 抄不出第二个)
- **错误 3**:把 5 大硬约束当作"成功必要条件"而非"失败避免条件"。违反硬约束的产品也能成功,但通常用别的东西弥补
- **错误 4**:不区分"硬约束 + 隐性优势弥补"(原神:AF.A 超 3 但米哈游研发 / IP 弥补)vs"硬约束错误"(普通团队同样配置必败)

---

## 六、与立项分析 SOP 的接口

- 复盘产物的**可迁移规律 / 反例**→ 进入 07a Step 4(竞品对照)作为输入,用于差异定位
- 复盘产物的**框架修订提案**→ 进入 01 文档 v1.2 的 `evolution_trigger` 字段评估,达到累积阈值(≥ 3 个同硬约束反例)时启动修订流程
- 复盘的 `counterexample_log` 字段累积在簇定义里,不在 SOP 内单独维护
