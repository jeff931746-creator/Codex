## 章节 1:这是什么

本文档定义**跨人群簇库与玩法承接库共享的基础维度**。

当前唯一基础维度:**T 任务态**(用户当下处理的心理任务)。

### 1.1 为什么单独建文件

T 任务态在两个库都要用,但**职责不同**:

| 库 | 字段 | 含义 |
|---|---|---|
| 人群簇库(下游) | `T_main` + `T_secondary` | `T_main` 必填 1 个主任务态;`T_secondary` 0-1 个并存副任务态(簇是用户聚类,任务态过多即聚类不稳)|
| 玩法承接库(上游) | `t_main` + `t_secondary` | `t_main` 必填 1 个主承接任务态;`t_secondary` 0-2 个副(玩法可同时承接多个任务态)|

> 命名同步(2026-05-15 修订,来源:P0-2):原 `t_can_carry` / `t_others` 已统一改为 `t_main / t_secondary`(玩法承接库)和 `T_main / T_secondary`(人群簇库)。本文件下文若出现旧字段名,以本表为准。

T 既不属于"人群"也不属于"玩法",而是**用户在某段时间具体处理的心理问题**。如果把 T 写进任何一个库,就会让另一个库不得不引用、复制或重新定义。所以单独定义在本文件。

### 1.2 跨库引用规则

- T 编号(T1-T6 + T7-candidate)在本文件维护,**两个库都引用本文件,不重定义**
- T 的定义、易混判据、范例对应都在本文件
- 人群簇库 / 玩法承接库的 T 字段值必须是本文件的合法枚举
- 如需新增 T,先改本文件,再让下游引用

## 章节 2:T 与 N 的关系(关键)

T 和 N 是**两层不同抽象**,经常被混淆,必须分清楚。

### 2.1 两者定义对照

| 维度 | T(任务态) | N(SDT 基本心理需求) |
|---|---|---|
| 抽象层级 | 用户当下处理的具体心理任务 | 底层心理需求 |
| 时间尺度 | 场景化,可短可长 | 长期不变 |
| 数量 | 6 个 + 1 候选 | 3 个(SDT 经典) |
| 变化性 | 同一用户不同时段处理不同 T | 同一用户长期保持相同 N 偏好 |
| 定义来源 | 本框架基于市场样本归纳 | 心理学 SDT(Deci & Ryan) |
| 库归属 | 本文件维护 | 玩法承接库 v1.1 维护 |

### 2.2 关键关系

```
T 与 N 解耦,不强制 1:1 对应:

  一个 N 可以服务多个 T:
    N-Comp(胜任感) → T1(快速胜任泄压) / T2(变强) / T5(规则理解) / T6(秩序掌控)

  一个 T 可以由多个 N 承接:
    T1(状态调节) ← N-Comp(快速胜任爽感) / N-Auto(无目标转移) / N-Rel(治愈陪伴)
```

### 2.3 常见错误

| 错误 | 例子 | 正确做法 |
|---|---|---|
| 把 T1 当成 N-Auto 的别名 | 看到"割草泄压"就归 N-Auto | 割草泄压本质是 N-Comp(瞬间胜任),T 才是 T1 |
| 把 T2/T5/T6 合并 | 都是 N-Comp 就当一个 T 处理 | T 是用户处理的任务,不同任务承接方式差异巨大,不能合并 |
| 让玩法直接归属 N,不经 T | 跳过 T 直接讨论"这个玩法是 N-Comp 玩法" | T 是承接桥梁,玩法承接的不是 N,而是"服务某个 T 的 N 满足方式" |

## 章节 3:T1-T6 完整定义

T1-T6 是当前框架定义的 6 个稳定任务态,基于 230+ 真实爆款样本归纳。

### 3.1 总览表

| T | 名称 | 用户在处理什么 | 主要由哪些 N 承接 | 典型场景 |
|---|---|---|---|---|
| T1 | 状态调节 | 缓解无聊、压力、疲惫、紧张,处理负面状态 | N-Auto(无目标转移) / N-Comp(快速胜任爽感) / N-Rel(治愈陪伴) | 下班通勤、午休、睡前 |
| T2 | 价值/能力确认 | 确认"我变强、我有价值、我没掉队" | N-Comp | 周末长时段、版本更新后 |
| T3 | 对象亲密 | 和角色/宠物/虚拟对象建立情感连接 | N-Rel(rel_object=virtual) | 每日剧情解锁、节日活动 |
| T4 | 群体位置 | 在组织/队伍/关系网里有位置 | N-Rel(rel_object=real / mixed) | 晚间公会战、固定开黑时段 |
| T5 | 规则理解 | 理解、破解、看懂复杂规则 | N-Comp | 入坑期、版本机制刚出 |
| T6 | 秩序掌控 | 把系统、世界、资源变得可控 | N-Comp / N-Auto | 长期经营、SLG 城建期 |

### 3.2 每个 T 详细定义

#### T1 状态调节

**用户在处理什么**:负面状态(疲惫、紧张、焦虑、无聊)需要被处理掉。用户不在追求增长,只在追求"从不舒服变舒服"。

**关键特征**:
- 短时段,可碎片
- 用户进入时已经在某种负面状态
- 用户期待离开时状态变好,而不是状态变强
- 成功标志是"舒服了 / 爽了 / 心情好了 / 累但放空了"

**典型场景**:下班通勤地铁、午休、睡前、加班间隙、考试后

**典型游戏**:消消乐(慢节奏版)、咸鱼之王(挂机泄压)、向僵尸开炮(割草爽感)、蛋仔派对(派对模式)、动森散步

**承接 N**:
- N-Auto:用"无目标自由"转移状态(动森散步、Minecraft 闲逛)
- N-Comp:用"快速胜任反馈"覆盖状态(咸鱼之王秒杀、割草游戏)
- N-Rel:用"温和陪伴"治愈状态(乙女游戏日常剧情、宠物游戏)

#### T2 价值/能力确认

**用户在处理什么**:确认"我变强了 / 我有价值 / 我没掉队 / 我做对了选择"。用户处于追求增长状态,需要外部验证。

**关键特征**:
- 中-长时段
- 用户进入时已经有"想变强"的预期
- 成功标志是"我比昨天/比别人更强了"
- 失败惩罚强(否则没办法承接"确认")
- 与 T1 的核心区别:T1 处理负面状态,T2 追求正向价值

**典型场景**:周末长时段、版本更新后、新角色出后、活动开启时

**典型游戏**:黑神话:悟空(操作变强)、咸鱼之王(战力变强)、王者荣耀(段位上升)、原神(角色练度)、斗罗大陆类传奇(数值膨胀)

**承接 N**:N-Comp(几乎唯一,T2 与 N-Comp 高度耦合)

#### T3 对象亲密

**用户在处理什么**:和角色 / 宠物 / 虚拟对象建立情感连接。用户处于"想要被某个特定对象需要 / 喜欢 / 陪伴"的状态。

**关键特征**:
- 长周期累积,情感门槛
- 对象必须有"个体识别度"(不是泛化的 NPC,而是某个特定的"她/他/它")
- 成功标志是"我和 ta 的关系更进了一步"
- 与 T4 的核心区别:T3 对象是虚拟角色 / 宠物,T4 对象是真人组织 / 队伍

**典型场景**:每日剧情解锁、节日活动、生日活动、纪念日

**典型游戏**:乙女游戏(光与夜之恋、未定事件簿)、原神角色向(雷电将军、可莉粉丝)、宠物游戏、视觉小说、咒术回战恋爱向

**承接 N**:N-Rel(`rel_object: virtual`)

#### T4 群体位置

**用户在处理什么**:在组织 / 队伍 / 关系网里找到并维持位置。用户处于"想被一个真实群体认可、需要、不可替代"的状态。

**关键特征**:
- 持续投入,出场制
- 对象是真人组织 / 固定队 / 公会 / 联盟
- 成功标志是"我在这个组织里有不可替代的位置 / 我被需要"
- 与 T3 的核心区别:对象是真人或包含真人,不是单一虚拟角色

**典型场景**:晚间公会战、固定开黑时段、联盟战、家族战、固定队 raid

**典型游戏**:三国志战略版(联盟政治)、率土之滨(联盟战)、魔兽世界公会、固定五黑王者荣耀、Among Us 熟人局

**承接 N**:N-Rel(`rel_object: real` 或 `mixed`)

#### T5 规则理解

**用户在处理什么**:理解、破解、看懂复杂规则。用户处于"我想搞明白这个系统怎么转的"状态。

**关键特征**:
- 入坑期 / 版本机制刚出时密集发生
- 成功标志是"我看懂了 / 我会玩了 / 我能解释给别人听"
- 一旦理解,T5 任务态会自然减弱,用户可能转向 T2(确认能力)或 T6(掌控秩序)
- 与 T2 的区别:T2 确认"我能做到",T5 确认"我看明白了"

**典型场景**:入坑前 1-2 周、版本大改后、新机制公开后

**典型游戏**:杀戮尖塔(卡组逻辑)、Hades(机制熟悉)、Inscryption(规则解密)、纪念碑谷(谜题理解)、Outer Wilds(世界规则解谜)

**承接 N**:N-Comp(认知胜任)

#### T6 秩序掌控

**用户在处理什么**:把系统 / 世界 / 资源变得可控、有序、按自己规则运转。用户处于"想让世界按我设定的方式运行"状态。

**关键特征**:
- 超长周期,系统化投入
- 对象是"系统/世界/资源"而非"我自己"
- 成功标志是"我让这个东西按我设计的方式跑起来了"
- 与 T2 的区别:T2 向内(我变强),T6 向外(世界按我转)
- 与 T5 的区别:T5 理解后退场,T6 持续维护

**典型场景**:长期经营、SLG 城建期、模拟经营长线、生存建造长线

**典型游戏**:Factorio(流水线掌控)、Dyson Sphere Program(星系工业掌控)、文明(文明掌控)、城市天际线(城市掌控)、SLG 大盟主(联盟掌控)、Rimworld(殖民地掌控)

**承接 N**:N-Comp(系统胜任)、N-Auto(自定节奏自主掌控)

## 章节 4:T 易混判据

### 4.1 易混对总表

| 易混对 | 关键判据 | 典型反例 |
|---|---|---|
| T1 vs T2 | 处理负面状态(我感觉不好,要好起来) → T1;追求正向价值(我要变更强) → T2 | 割草泄压(短时舒服)→ T1;数值膨胀肝战力 → T2 |
| T2 vs T5 | 确认"我能行/我变强" → T2;确认"我看懂了/我理解了" → T5 | 黑神话练操作 → T2;杀戮尖塔学卡组 → T5 |
| T2 vs T6 | 确认"我个体变强"(向内) → T2;确认"我让世界按我规则运转"(向外) → T6 | 咸鱼之王肝战力 → T2;Factorio 拉传送带 → T6 |
| T3 vs T4 | 关系对象是虚拟角色 → T3;关系对象是真人组织 → T4 | 原神角色向 → T3;原神公会(若有真人组织)→ T4 |
| T5 vs T6 | 理解规则后退场(我懂了) → T5;持续维护系统运转(我让它转起来) → T6 | Outer Wilds 解谜 → T5;Rimworld 经营 → T6 |
| T1 vs T6 | 处理负面状态(短期) → T1;长期建立可控秩序 → T6 | 通勤路上消消乐 → T1;长期 SLG 城建 → T6 |
| **L3:T5 vs T1**(解谜场景)| 看**卡关回头率**:卡住后**回头攻克** → T5;**卡住即弃** → T1 | 动物井 / 机械迷城 → T5;化学(卡了就关掉)→ T1 |
| **L4:T2 vs T4**(合作场景)| 队友是**执行工具** → T2;队友是**共同体 / 有归属感** → T4 | 王者荣耀路人局 → T2;MMO 公会团本 → T4 |
| **L5:T6 vs T1**(沙盒经营)| 有**可观测系统秩序变化** → T6;**仅放置触感无优化目标** → T1 | Factorio → T6;咸鱼之王挂机 → T1 |

L3 / L4 / L5 三对是 1455 样本验证中最易摇摆的 T 对(L3=44 次、L4=24 次、L5=26 次),详细判据见 4.3 节。

### 4.2 详细易混说明

#### T1 vs T2(最易混)

**核心区分**:用户进入时的状态。
- T1:用户已经在某种负面状态(累、烦、闷)中,需要状态改善 → "我要从不舒服变舒服"
- T2:用户处于正向预期(想变强),需要价值确认 → "我要从一般变更强"

**关键问题**:**用户停玩时本能反应是什么?**
- "舒服了 / 心情好了 / 放空了" → T1
- "我又变强了 / 我没掉队 / 我比别人厉害" → T2

#### T2 vs T6

**核心区分**:能力指向的对象。
- T2:能力指向**自己**(我变强、我能行)
- T6:能力指向**系统/世界**(我让世界按我转)

举例:同样玩 SLG,
- 小盟员肝战力、抢资源、上排行 → T2(我变强)
- 大盟主调度联盟、安排资源分配、设计联盟战略 → T6(我让联盟按我转)+ 可能含 N-Rel 的权力关系

#### T3 vs T4

**核心区分**:关系对象的类型。
- T3:虚拟角色(NPC、攻略对象、宠物)
- T4:真人组织(公会、联盟、固定队)

举例:同样是原神,
- 单机刷剧情、追角色 → T3
- 加入大世界联机/官方组织 → 可能 T4(但原神现在 T4 承接弱)

如同时有,标主 T 即可,副 T 进 `t_secondary` 或人群簇 `T_secondary` / `secondary_N`。

#### T1 vs T6

**核心区分**:时间尺度和驱动来源。
- T1:短期,被负面状态驱动
- T6:长期,被"建立秩序的成就感"驱动

举例:消除游戏,
- 通勤随便玩两关解闷 → T1
- 收藏全部关卡、刷三星、做研究 → 可能转 T2/T5/T6

### 4.3 高频摇摆三对(L3 / L4 / L5)

L3 / L4 / L5 是 1455 样本 SDT 验证中最频繁摇摆的三对 T,合计 94 次 medium 置信样本落入这三个边界区。下面给出详细判据。

#### L3:T5 vs T1(解谜场景,2026-05-15 新增,来源:P0-7)

解谜类游戏既可能承接 T5(规则理解),也可能承接 T1(状态调节)。关键判据是**卡关回头率**:

- 玩家卡关后**回头攻克**(继续死磕、查攻略、第二天再试)→ **T5 规则理解**(用户的核心动力是"我要看懂这个规则")
- 玩家卡关后**即弃**(关掉游戏转其他活动)→ **T1 状态调节**(用户来这里只是为了"消磨时间",卡关意味着调节失败,自然转走)

**典型样本**:
- T5:动物井、机械迷城、Outer Wilds、Baba Is You — 玩家卡关后会反复回看、记笔记、找资料
- T1:化学(消除类小程序)、各类消除合集 — 玩家卡关后大概率不再回来

**数据法**:看 7 日内"卡关后 24h 内回访率",高于 40% → T5;低于 15% → T1;15%-40% 边界,需结合 A/F 复核。

**摇摆样本数**:1455 样本里 T5 vs T1 摇摆 44 次,是 T 维度**最高频**的歧义对。

#### L4:T2 vs T4(合作场景,2026-05-15 新增,来源:P1-5)

多人协作类游戏既可能承接 T2(价值/能力确认),也可能承接 T4(群体位置)。关键判据是**队友在玩家认知中的角色**:

- 队友被视为**执行工具**(为我服务,为我上分,为我打副本)→ **T2 价值确认**(用户的核心动力是"我比别人更强 / 我赢了")
- 队友是**共同体**(有归属感、有不可替代性、有持续关系)→ **T4 群体位置**(用户的核心动力是"我在这个组织里有位置")

**典型样本**:
- T2:王者荣耀路人局(队友是变量,我上分是目的)、CS 单排
- T4:MMO 公会团本(同一批人长期一起、有 raid 时间表)、SLG 联盟战(长期联盟关系)、固定五黑王者(队友是熟人)

**数据法**:看玩家是否**重复匹配相同队友** + **队友离线后玩家是否继续玩**。高重复 + 队友离线即弃玩 → T4;低重复 + 队友离线无影响 → T2。

**摇摆样本数**:1455 样本里 T2 vs T4 摇摆 24 次,多发于 PVP 团队竞技类。

#### L5:T6 vs T1(沙盒经营场景,2026-05-15 新增,来源:P1-6)

沙盒 / 经营 / 放置类游戏既可能承接 T6(秩序掌控),也可能承接 T1(状态调节)。关键判据是**有无可观测的系统秩序变化**:

- 有**可观测系统秩序变化**(产线扩张、解锁链推进、等级跃升、效率优化)→ **T6 秩序掌控**(用户的核心动力是"我让系统按我规则转得更好")
- **仅有放置触感无优化目标**(挂机看动画、点点击击、随意摆设无系统反馈)→ **T1 状态调节**(用户的核心动力是"无脑触感放松")

**典型样本**:
- T6:Factorio、戴森球计划、城市天际线、Rimworld — 玩家行为有明确"系统更优化"的目标
- T1:咸鱼之王挂机段(纯看战力被动涨)、各类无攻略放置类、动森"只散步不装修"型用户

**数据法**:看玩家是否**主动查阅攻略 / 计算公式 / 设计布局**。主动钻研 → T6;只点点不优化 → T1。

**摇摆样本数**:1455 样本里 T6 vs T1 摇摆 26 次,多发于经营 / 放置融合类。

## 章节 5:T7-candidate(候选任务态)

### 5.1 T7 是什么

T7-candidate:**习惯维持 / 仪式延续**。

**用户在处理什么**:维持已经形成的游戏习惯,不让中断。用户的目标不是"获得什么",而是"不丢掉什么"(连续登录、连续签到、不掉队、不打破记录)。

### 5.2 为什么是候选,不是正式 T

候选原因:
- T7 在 230+ 样本中虽然普遍存在(几乎所有运营长线手游都有),但**很少作为主驱动**,通常是 T2/T4/T6 的伴生状态
- 单独以 T7 为主驱动的玩法极少(类似 Wordle 极简日常仪式才接近)
- 与 T2 的边界不清晰(连续登录拿奖励 ≈ T2 的一种)

激活条件(任一即可升格为正式 T7):
- 出现 ≥ 3 个以 T7 为单独主驱动的爆款样本
- 与 T2 的边界判据稳定(明确什么时候是 T7、什么时候是 T2 伴生)
- 至少 1 个立项产品确认 T7 是核心承接对象

### 5.3 T7 的临时定义(候选状态)

**临时定义**:玩家的核心动力是"已经投入了,不能让前面的投入白费"或"已经形成习惯,中断会有损失感"。

**典型场景**:
- 连续登录第 600 天
- Duolingo 连续打卡 500 天
- 微信跳一跳保持记录

**承接 N**:暂时归入 N-Comp(投入累积的胜任感)或 N-Rel(对游戏本身的关系延续),不确定。

**当前处理**:在 yaml 中允许写 `t_secondary: [..., T7-candidate]`,但配置校验时给出 warning 提示;不允许作为 `t_main` / `T_main` 主字段(人群簇库与玩法承接库均不接受 T7-candidate 作主 T)。
