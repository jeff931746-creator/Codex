# 数值评审模板

适用范围：游戏数值系统设计方案的评审——经济、养成、战斗三域，按游戏类型按需启用。

判据来源：`archive/方法论/策划/经济与养成数值评审判据_2026-06-10.md`

---

## 目标

评审一份数值设计方案的结构完整性、内在一致性和可持续性。

它解决的不是"数值调得准不准"，而是：

- 经济体系的结构是否完整——源、汇、流转、调节四要素是否齐全
- 养成体系的结构是否合理——投入能否变强、变强能否感知、感知后能否继续追求
- 战斗体系的数值是否自洽——公式可解释、属性有分工、平衡可调控
- 各域之间的接口是否衔接——经济喂养成、养成喂战斗、战斗验证养成
- 哪些维度需要补充设计或纸面验证

---

## 使用规则

### 1. 域适用性判定

评审开始前，先确认被评审产品包含哪些数值域：

| 域 | 适用条件 | 典型不适用场景 |
|----|----------|---------------|
| 经济 | 产品存在货币、资源产出与消耗体系 | 纯叙事游戏、纯竞技无经济 |
| 养成 | 产品存在角色/装备/技能等可成长的数值系统 | 纯棋牌、纯解谜 |
| 战斗 | 产品存在基于数值的战斗系统（含PVE/PVP） | 纯经营模拟、纯社交 |

**规则：适用则评，不适用则整域跳过，不计入评审统计。**

### 2. 评审顺序

固定按以下顺序：先评各域内部，再评跨域接口。

1. **经济域**（如适用）：货币清晰 → 产出驱动 → 消耗合理 → 循环闭合 → 模块串联 → 自我调节 → 交易体系（条件）
2. **养成域**（如适用）：养成线清晰 → 提升合理 → 阶段闭合 → 养成联动 → 层级分明 → 节奏调控
3. **战斗域**（如适用）：公式自洽 → 属性有责 → 平衡可控
4. **跨域接口检查**（适用域 ≥2 时）

### 3. 评审结构

每个判据分为三部分：

- `事实`：从设计文档中提取的客观信息，引用原文或标注"文档未提及"
- `判断`：基于事实的分析与推理
- `结论`：该判据的评审结果

### 4. 判据分级

每域内的判据分为基础、核心、条件三级。基础判据出问题，该域下游全部不可信。

**经济域**

| 级别 | 判据 | 含义 |
|------|------|------|
| 基础 | 货币清晰、产出驱动、循环闭合 | 经济地基——货币定义、资源来源、流转闭环 |
| 核心 | 消耗合理、模块串联、自我调节 | 运转质量——消耗节奏、模块衔接、调节能力 |
| 条件 | 交易体系 | 仅当产品存在玩家交易系统时适用 |

**养成域**

| 级别 | 判据 | 含义 |
|------|------|------|
| 基础 | 养成线清晰、阶段闭合 | 养成地基——维度定义、成长可感知 |
| 核心 | 提升合理、养成联动、层级分明、节奏调控 | 运转质量——转化效率、线间传导、付费梯度、节奏管理 |

**战斗域**

| 级别 | 判据 | 含义 |
|------|------|------|
| 基础 | 公式自洽 | 战斗地基——核心公式可解释、可预测 |
| 核心 | 属性有责、平衡可控 | 运转质量——属性分工、平衡可调 |

### 5. 结论等级

每个判据给出结论 + 问题类型：

**结论**（三选一）：

- `达标`：设计完整、逻辑自洽、无明显问题
- `待完善`：方向可行，但存在需要补充或修正的具体问题
- `不达标`：存在结构性缺陷，需要重新设计

**问题类型**（待完善或不达标时必填）：

| 类型 | 含义 | 修复代价 |
|------|------|----------|
| `结构性` | 设计方向或激励逻辑有误，调参无法修复 | 需要重新设计该模块 |
| `补充性` | 方向对但信息不足，缺少关键设计细节 | 需要补充设计文档 |
| `参数性` | 结构合理但具体数值需要调整或验证 | 可在后续阶段通过调参/测试解决 |

一个判据内可以同时存在多种类型的问题，按最严重的类型定性。

### 6. 条件模块处理

域级条件：不适用的域整域跳过，不计入统计。
判据级条件：经济域的"交易体系"，如产品不存在交易系统，跳过该判据。

### 7. 评审原则

- 不允许用"后期调数值"掩盖结构性问题
- 不允许把单一数值参数的合理性等同于体系合理性
- 事实必须引用设计文档原文或明确标注"文档未提及"
- 判断必须基于本文档事实段的内容，不基于评审者的品类偏好

### 8. 立项阶段校准

**原则：立项评的是数值架构的逻辑完整性，不是数值的精确性。**

各判据的事实清单是完整 checklist——有则填，没有标"文档未提及"。但立项阶段的达标判定只看"达标线"以内的项目。达标线以外的项目缺失不扣分，有则加分。

**经济域**

| 判据 | 达标线（立项必须回答） | 不要求（详设补充） |
|------|----------------------|-------------------|
| 货币清晰 | 货币种类与用途、层级关系、兑换方向、付费货币定位 | 精确汇率数值、具体售价档位 |
| 产出驱动 | 产出来源清单、免费/付费结构关系、缺口方向、上限机制类型、投放双维度方向（场景×节奏） | 精确恢复速率、每日产出量、衰减曲线参数 |
| 消耗合理 | 消耗去向清单、消耗曲线方向（指数/阶梯/…）、付费免费差异方向、首付触发位置、重复付费驱动来源 | 每级消耗量、精确膨胀系数、消耗寿命精确数值 |
| 循环闭合 | 完整的资源流转图、核心循环描述、正/负反馈识别、付费介入点位置 | 每条路径的数值量级 |
| 模块串联 | 模块清单、依赖关系、传导路径、关键模块流转方向 | 传导公式、精确量级比例 |
| 自我调节 | 知道经济会失衡、有方向性的调节思路、内容供给依赖度判断 | 完整的调节参数方案、监控指标阈值 |
| 交易体系 | 交易形式、可交易范围、控制手段方向 | 详细税率、价格区间参数、频率限制数值 |

**养成域**

| 判据 | 达标线（立项必须回答） | 不要求（详设补充） |
|------|----------------------|-------------------|
| 养成线清晰 | 养成维度清单、各线对战力/体验的贡献定位、线间不重叠 | 精确数值比例 |
| 提升合理 | 提升曲线方向（线性/指数/阶梯）、资源换成长的转化率方向（与经济侧衔接） | 精确每级提升量、边际收益曲线参数 |
| 阶段闭合 | 关键验证场对应（每段成长在哪里被感知）、投入→变强→感知→追求闭环方向 | 精确节点数值 |
| 养成联动 | 线间解锁/前置/乘算关系描述 | 精确联动公式 |
| 层级分明 | 免费/小R/中R/大R在时间轴上的目标方向、付费梯度有结构性差异 | 精确时间节点和数值目标 |
| 节奏调控 | 各线开启时间规划方向、追赶机制方向、天花板管理方向 | 精确追赶参数、版本膨胀控制参数 |

**战斗域**

| 判据 | 达标线（立项必须回答） | 不要求（详设补充） |
|------|----------------------|-------------------|
| 公式自洽 | 核心公式结构（伤害=f(攻,防,…)的形式）、属性缩放方向、公式可解释性 | 精确系数、平衡测试数据 |
| 属性有责 | 属性清单、各属性功能定位（不重叠）、主次属性关系 | 精确属性数值范围、成长曲线 |
| 平衡可控 | PVE难度曲线方向、调参旋钮识别；PVP（如有）平衡框架方向 | 精确平衡参数、匹配算法 |

### 9. 一票否决项

以下任一成立，无论其他判据得分如何，总体结论直接判定为**重新设计**：

1. **核心循环激励方向矛盾** — 两套或多套循环的激励结构指向相反方向，调参无法调和
2. **付费逻辑无结构支撑** — 说不出"为什么玩家会付第二笔钱"，或付费理由仅靠单点卡顿而非体系缺口
3. **资源流转存在不可修复的漏洞** — 某资源只有源没有汇（必然通胀）或只有汇没有源（玩家获取无望），且设计上无法补救
4. **产出与消耗完全脱节** — 产出体系和消耗体系之间没有设计意义上的数值关联，两套独立运转
5. **养成与验证脱节** — 养成提升无法在任何验证场景中被玩家感知，"变强了但感觉不到"
6. **战斗公式不可解释** — 核心战斗结果无法用属性关系解释，纯黑箱或纯随机

### 10. 经济↔养成镜像关系

经济管"流"（资源怎么流动），养成管"位"（战力怎么生长）。接口只有一处：转化率（经济定资源量，养成定提升量）。

评审任一侧发现问题时，对照检查另一侧镜像位判据：

| 经济域 | 养成域 | 共振含义 |
|--------|--------|----------|
| 货币清晰 | 养成线清晰 | 资源定位乱 ↔ 养成定位也可能乱 |
| 产出驱动 | 层级分明 | 产出结构有问题 ↔ 付费层级目标也可能失效 |
| 消耗合理 | 提升合理 | 资源消耗曲线问题 ↔ 成长转化率也可能脱节 |
| 循环闭合 | 阶段闭合 | 资源循环断裂 ↔ 成长阶段也可能断裂 |
| 模块串联 | 养成联动 | 经济模块各自为政 ↔ 养成线也可能各自为政 |
| 自我调节 | 节奏调控 | 经济无调节 ↔ 养成节奏也可能失控 |

## 经济域

> 如经济域不适用，跳过本节。

### E1 [货币清晰] 货币体系与汇率设计

#### 事实

- 货币种类清单（名称、获取方式、主要用途）：
- 货币层级关系（硬通货 / 软通货 / 代币 / 积分等）：
- 货币间兑换规则：
  - 哪些货币可互换，哪些不可：
  - 兑换比率是固定还是浮动：
  - 兑换方向是否有限制（如：付费货币 → 通用货币可以，反向不可以）：
- 付费货币的获取途径（仅付费 / 付费为主 + 少量免费）：
- 每种货币有几个消耗出口：

#### 判断

- 每种货币是否有明确且不重叠的功能定位：
- 是否存在"万能货币"（一种货币能买所有东西，导致其他货币失去意义）：
- 硬通货 → 软通货的兑换是否单向（保护付费价值）：
- 货币种类数量与系统复杂度是否匹配（过多 → 认知负担；过少 → 调控不足）：

#### 结论

- 结论：`达标 / 待完善 / 不达标`
- 问题类型：`结构性 / 补充性 / 参数性`
- 具体问题：

### E2 [产出驱动] 产出体系设计

#### 事实

- 各资源的产出来源清单（系统产出 / 活动产出 / 付费产出）：
- 免费产出的上限机制（体力 / 时间门 / 次数限制）：
- 免费产出的恢复节奏（如：体力 X 分钟恢复 1 点，日上限 Y）：
- 付费加速方式（直接购买 / 加速回复 / 解锁额外来源）：
- 是否存在随机产出（概率掉落、抽卡等）：
- 产出是否有阶段性衰减或膨胀曲线：
- **投放双维度**（每种养成资源）：
  - 内容场景维度（PVP / PVE）的分配：
  - 获取节奏维度（日常 / 挑战 / 付费）的分配：

#### 判断

- 免费产出是否能维持基础体验但不足以满足进度需求（缺口是否存在且稳定）：
- 产出缺口是靠时间还是付费来弥补：
- 随机产出的方差是否可控：
- 多个产出来源之间是否存在替代关系（能否绕过核心付费点）：
- 投放双维度是否同时覆盖（只有单维度 → 失效模式：场景内比例失控 或 资源不绑内容）：

#### 结论

- 结论：`达标 / 待完善 / 不达标`
- 问题类型：`结构性 / 补充性 / 参数性`
- 具体问题：

---

### E3 [消耗合理] 消耗体系设计

#### 事实

- 各资源的消耗去向清单（升级 / 强化 / 解锁 / 消耗品等）：
- 消耗需求曲线类型（线性 / 指数 / 阶梯 / S 型）：
- 成本膨胀系数（每级或每阶段的成本增长倍率）：
- 代表性层级的消耗量（早期 / 中期 / 后期各举一例）：
- 付费玩家与免费玩家的成长速度差异：
- **长线可量化项**：
  - 免费玩家的消耗寿命估算：
  - 中 R / 大 R 的消耗寿命估算：
  - 首次付费触发的数值节点：
  - 重复付费的数值驱动力来源（体系持续缺口 vs 依赖内容更新）：
  - 高付费玩家的数值天花板：

#### 判断

- 成本膨胀速度是否始终高于免费产出增速（维持缺口）：
- 是否存在"追完风险"——高付费玩家穷尽所有内容：
- 消耗曲线是否存在"断层"——某阶段投入产出比突变：
- 消耗去向是否有足够多样性：
- 首付节点是否在核心循环的自然瓶颈处（非人为卡点）：
- 重复付费是体系持续缺口驱动（可持续）还是内容更新驱动（不可持续）：

#### 结论

- 结论：`达标 / 待完善 / 不达标`
- 问题类型：`结构性 / 补充性 / 参数性`
- 具体问题：

---

### E4 [循环闭合] 资源流转与循环结构

#### 事实

**流转完整性**

- 文档是否提供了资源流转图 / 框图：`是 / 否`
- 流转图覆盖的资源种类：
- 已标注的"源"清单：
- 已标注的"汇"清单：
- 主要流转路径描述：

**循环结构**

- 核心经济循环描述（获取 → 消耗 → 提升 → 解锁新获取 → 回到获取）：
- 正反馈环路（越强 → 产出越多 → 越强）：有几条，在什么位置：
- 负反馈 / 制约机制（防止正反馈滚雪球）：
- 付费介入点在循环中的位置（加速/跳过哪个环节）：

#### 判断

- 是否所有货币/资源都同时具备"源"和"汇"（无孤立节点）：
- 是否存在只有源没有汇（通胀）或只有汇没有源（获取无望）的资源：
- 核心循环是否形成闭环（不存在断裂点）：
- 正反馈是否有天花板或衰减：
- 付费介入点是否在自然瓶颈处：
- 免费玩家是否能完整体验核心循环（慢但不被排除）：
- 循环在不同阶段（新手/中期/后期）是否仍然有效：

#### 结论

- 结论：`达标 / 待完善 / 不达标`
- 问题类型：`结构性 / 补充性 / 参数性`
- 具体问题：

### E5 [模块串联] 经济模块串联

#### 事实

- 数值模块清单及各模块的核心输入 / 输出：
- 模块间的依赖关系：
- 数值传导路径（如：战力 → 关卡难度 → 产出量 → 成长速度）：
- 是否存在多条并行循环，并行循环之间是否共享资源：
- **关键模块流转图**（选 1–2 个对付费或留存影响最大的模块）：
  - 模块名称：
  - 输入资源、内部转化逻辑、输出资源的完整流转：

#### 判断

- 是否存在循环依赖（无法独立调参）：
- 各模块数值量级是否匹配：
- 付费投入在各模块间的传导是否一致（不出现"花钱在A但B受益"的错位）：
- 传导链长度是否合理（>3 层 → 调参困难）：
- 是否有单个模块卡死导致全系统停滞：
- 并行循环激励方向是否一致：

#### 结论

- 结论：`达标 / 待完善 / 不达标`
- 问题类型：`结构性 / 补充性 / 参数性`
- 具体问题：

### E6 [自我调节] 经济平衡

> 立项阶段只要求调节方向和手段类型，不要求参数化方案。

#### 事实

- 文档是否描述了经济失衡的调节方案：`是 / 否`
- 已提及的调节手段清单（动态定价 / 产出衰减 / 活动投放 / 系统回收等）：
- 是否有数据监控方向：
- 是否考虑了不同付费层级玩家的经济体验差异：
- 版本迭代中的追赶或重置思路：
- **内容供给的经济影响**：
  - 新内容是扩展循环还是已有循环加量：
  - 内容停更后经济独立运转能力：

#### 判断

- 调节手段是否覆盖通胀和通缩两个方向：
