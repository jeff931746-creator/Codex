# GDD 写作标准

适用范围：系统设计文档、玩法设计文档、战斗设计文档及同类功能设计规格产出物。

---

## 核心写作视角

**流程优先，工具其次。**

系统不是工具的集合，而是一条有序运行的流程。流程决定工具存在的意义，工具挂在流程节点上才有上下文。

策划拿到文档后应该能回答四个问题：

1. **系统怎么运转**：整体流程是什么，哪里是循环，哪里是单次
2. **每个节点有哪些可配置项**：各阶段策划可操作的配置模块
3. **规则是什么**：配置如何转化为系统行为，约束如何生效
4. **如何拼出目标体验**：给定体验目标，选什么流程结构和配置

禁止用配置项堆叠视角写文档：
- ❌ 平铺列出所有配置项，配置项之间无顺序、无流向
- ✅ 先画流程图，再在每个节点上挂配置项定义

---

## 写作框架（四层）

每个系统文档必须包含以下四层，顺序不可颠倒：

---

### 第一层：体验目标

**格式固定**：
> "玩家在 [场景] 应感受到 [具体情绪/认知状态]，因为 [设计理由]"

约束：
- "有趣""好玩""爽"不是合法答案，必须命名具体的情绪或认知状态
- 两个人读完后能判断某个流程配置是否满足了这句话
- 写不出这句话 → 停下来澄清需求，不许继续

每个系统可以有多个体验目标，每个目标必须独立成句。

---

### 第二层：系统流程与节点定义

先画流程图，再定义每个节点。不允许跳过流程图直接写节点定义。

#### 2.1 流程图（强制）

用文字流程图或嵌入图表表示，必须包含：

- **阶段序列**：各阶段按执行顺序排列
- **循环节点**：标注哪里循环（`↺`）、循环条件（次数 / 时间 / 触发条件）
- **数据流**：每个阶段结束时向下一阶段传递什么数据
- **条件分支**：不同条件走不同路径时标注分支条件

示例格式：
```
[阶段A]（单次）
  ↓ 传递：数据X
[阶段B]（循环：每N分钟 / 直到条件Y）
  ↺ 循环内：步骤1 → 步骤2 → 步骤3
  ↓ 传递：累积数据Z
[阶段C]（单次）
  ↓
[结算]
```

**流程图删除测试**：删掉某个阶段，第一层的体验目标还能实现吗？不能实现 → 保留，能实现 → 删除。

#### 2.2 节点定义

按流程图的每个节点逐一定义，每个节点包含：

| 字段 | 要求 |
|---|---|
| **节点名** | 与流程图一致 |
| **类型** | 单次 / 循环（标注循环条件） |
| **进入条件** | 触发该节点的前置条件 |
| **可配置项** | 策划在该节点可配置的模块（能配置什么 / 影响什么体验） |
| **强制规则** | 必须 / 禁止 / 当...则... 格式，系统强制执行 |
| **推荐范围** | 推荐范围 + 默认值（格式：默认 X，可配置 Y–Z） |
| **输出** | 该节点结束时向下一节点传递的数据 |
| **完成条件** | 离开该节点的条件 |

**配置项删除测试**：对每个节点内的配置项问"删掉这个配置项，该节点的体验目标还能实现吗？"不能实现 → 保留。

每个节点对应的配置项不超过 3 个。超过 3 个必须说明为什么删不掉。

---

### 第三层：规则层

在流程和节点定义之上，补充系统的操作规则。

#### a) 操作规则

格式：`当 [触发条件] 时，系统必须/禁止 [行为]`

覆盖：
- 各节点之间的联动（A 节点的输出如何影响 B 节点的行为）
- 循环内的状态变化规则

#### b) 规则优先级

当多条强制规则同时触发时的处理顺序：
> 第 1 优先级 > 第 2 优先级 > ...

若各规则不存在冲突场景，明确声明"各规则独立生效，无优先级冲突"。

#### c) 边界行为

| 违反的规则 / 异常场景 | 系统响应 | 兜底行为 |
|---|---|---|
| [规则名 / 场景描述] | 报错 / 回退 / 强制修正 | [具体处理] |

含结算/发奖的系统，边界行为必须覆盖：发奖时机、在线/离线处理、发奖失败兜底。

**规则层删除测试**：对每条规则问"删掉这条规则，系统行为还有明确定义吗？"无法定义 → 保留。

---

### 第四层：拼装示例

给出至少 2 个体验目标的拼装配置，每个示例必须包含决策理由：

```
体验目标：[第一层的句子]
决策理由：[为什么选这套流程结构和配置，而不选其他]
流程配置：
  · [阶段A]：[配置值，循环条件]
  · [阶段B]：[配置值]
预期效果：[玩家会感受到什么，对应第一层]
```

拼装示例是策划设计新实例时的决策模板，决策理由说明"为什么这样配"，不可省略。

---

## 文档输出结构

每个系统文档分三个区：

**必须锁定**
- 体验目标句（第一层）
- 系统流程图（第二层 2.1，含循环节点和数据流）
- 节点配置项定义（第二层 2.2，含删除测试结论）
- 所有强制规则
- 规则层（第三层）

**开发自决**
- 满足必须锁定约束下，内部实现方式开发自行决定
- 只列约束，不给方案
- 算法步骤、数据结构、渲染方案均属于开发自决区

**待定**
- 需要数据或测试才能定的内容
- 明确标注"待定，原因：[X]"，不许用猜测填充

---

## 禁止行为

- 没有体验目标就开始写流程或配置项
- 跳过流程图直接平铺配置项（配置项必须挂在节点上）
- 循环节点没有标注循环条件（次数 / 时间 / 触发条件）
- 阶段间数据流不明确（不知道上一阶段传了什么给下一阶段）
- 用"通常""常见做法""同类游戏都有"作为保留某个节点或配置项的理由
- 在强制规则字段写"建议""推荐"等非强制表述（建议值进推荐范围字段）
- 推荐范围只给范围，不给默认值
- 核心规则仅存在于外链白板，文档文字层无对应规则（图表可辅助说明，但文字规则必须完整自洽）
- 在"必须锁定"区写实现细节（算法步骤、像素尺寸、具体动画）
- 只写一个拼装示例
- 拼装示例缺少决策理由
- 用推测填充"待定"区

## 写作 Prompt

```
你是一名资深系统策划。你的工作是定义系统的流程结构和策划操作界面，不是描述系统实现。

核心原则：先有流程，再有工具。工具挂在流程节点上，不平铺。

## 强制推导链（四步，不可跳过）

### Step 1 — 体验目标
写出所有体验目标句，格式固定：
"玩家在[场景]应感受到[具体情绪/认知状态]，因为[设计理由]"

约束：
- "有趣""好玩""爽"不是合法答案
- 两个人读完后能判断某个配置是否满足了它
- 写不出 → 停下来澄清，不许继续

### Step 2 — 系统流程图
画出整体流程，必须标注：
- 各阶段的执行顺序
- 循环节点（↺）及循环条件
- 阶段间传递的数据
- 条件分支及分支条件

对每个阶段做删除测试：删掉它，体验目标还能实现吗？

### Step 3 — 节点定义
按流程图逐节点定义。每个节点包含：
- 类型（单次 / 循环）
- 进入条件
- 可配置项（能配置什么 / 影响什么体验）
- 强制规则（必须/禁止格式）
- 推荐范围（默认 X，可配置 Y–Z）
- 输出
- 完成条件

对每个节点的配置项做删除测试。

### Step 4 — 规则层
定义三类规则：
a) 操作规则：当[条件]时，系统必须/禁止[行为]
b) 规则优先级：第1 > 第2 > ...（或声明无冲突）
c) 边界行为：违反强制规则时系统如何响应 + 兜底

含结算/发奖系统必须覆盖：发奖时机、在线/离线处理。

### Step 5 — 拼装示例
至少 2 个体验目标的拼装配置：
体验目标 / 决策理由 / 流程配置 / 预期效果
```

## 审核 Prompt 模板

```
请先读取以下文件：
1. reference/部门标准/策划/current/GDD写作标准.md（审核标准）
2. [目标文档路径]（被审核文档）

按照 GDD写作标准.md 中的 Self-Review 评审判据，逐系统核查以下四项：

**判据一：体验目标存在**
每个系统是否有明确的体验目标句？情绪/认知状态是否具体可判断？

**判据二：流程图存在且完整**
是否有文字流程图（状态序列 + 循环节点 + 数据流 + 分支条件）？
循环节点是否标注了循环条件？
阶段间是否说明了数据传递？
每个阶段是否通过了删除测试？

**判据三：节点定义与规则层完整**
节点定义是否按流程节点组织（不平铺）？
每个节点是否包含：进入条件 / 可配置项 / 强制规则 / 推荐范围（含默认值）/ 输出 / 完成条件？
规则层是否包含操作规则、规则优先级、边界行为？
含结算/发奖的系统是否覆盖发奖时机和离线处理？

**判据四：拼装示例存在且可操作**
是否有至少 2 个体验目标的拼装配置，含决策理由？
必须锁定区是否混入了实现细节？

输出格式：
- 每个系统单独一节
- 四项判据逐条给出：通过 / blocking issue
- blocking issue 标注具体位置和问题描述
- 最后：可通过 / 需打回修改（列 blocking issue 清单）
```

---

## Self-Review 评审判据

| 判据 | 通过标准 | 不通过标准 |
|---|---|---|
| 体验目标存在 | 每个系统有明确的 Step 1 句式，情绪/认知状态具体可判断 | 缺失、模糊（"有趣""好玩"） |
| 流程图存在且完整 | 有文字流程图；循环节点标注循环条件；阶段间有数据流；各阶段通过删除测试 | 无流程图；平铺配置项；循环节点无条件；数据流不明 |
| 节点定义与规则层完整 | 节点按流程组织；每节点有完整字段；规则层覆盖操作规则/优先级/边界行为；含发奖系统覆盖时机和离线处理 | 配置项平铺不挂节点；缺强制规则或推荐范围默认值；缺规则层；发奖规则缺失 |
| 拼装示例存在且可操作 | 至少 2 个体验目标配置，含决策理由，可直接操作 | 缺示例；无决策理由；必须锁定区混入实现细节 |

四项均通过 → self-review 完成，可进入 delivery。
任意一项有 blocking issue → 打回 edit gate，不可进入 delivery。
