# 多Agent设计文档调度规则

## 定位

本文件定义多 Agent GDD 写作的底层调度语义：上下文如何装配、阶段状态如何保存、打回如何回滚、循环如何熔断、checkpoint 如何恢复。

本文件不定义阶段顺序。阶段顺序见 `多Agent设计文档工作流.md`。

## 路由与证据读取边界

主 Agent 在确认是否进入 GDD 写作流程时，只允许装配路由上下文：

- 用户原始请求
- 用户显式提供的目标路径和参考路径清单
- 工作区入口规则
- 任务流路由规则
- `gdd-write` 执行入口
- 本工作流和本调度规则
- 当前运行时可用的子 Agent / delegation 能力

命中 GDD 写作流程后，参考 GDD、历史记忆、机制资料、竞品资料、业务正文、已有设计文档正文等业务证据，必须作为 G1 输入交给子 Agent 首次读取和拆解。

主 Agent 在 G1 之前不得：

- 提炼设计目标、意图或边界
- 判断核心循环或功能定位
- 从历史记忆合成方案方向
- 把参考资料中的机制关系改写成候选方案
- 输出“我会把 X 设计成 Y”这类设计结论

如果主 Agent 已经越界读取并解释了业务证据，该解释只能作为污染风险记录，不得作为 G1/M1 证据；必须重新启动 G1，让子 Agent 在不继承该业务结论的任务包中完成资料与目标拆解。

## 状态字典

执行过程中维护一个全局状态 S，至少包含：

- confirmed_facts
- unknown_facts
- candidate_design_problems
- candidate_design_goals
- candidate_design_intents
- confirmed_goal
- confirmed_intent
- confirmed_boundary
- confirmed_loop
- confirmed_features
- confirmed_ue
- direction_validation_pending_items
- formal_gdd_blockers
- stage_outputs
- return_opinions
- stage_snapshots
- return_counters

## 阶段快照

进入 G1-G6 任一阶段前，必须记录当前状态快照。

跨阶段打回时，必须：

1. 回滚到目标阶段进入前的快照。
2. 追加本次打回意见。
3. 标记目标阶段之后的产物为作废。
4. 从目标阶段重新执行。

禁止在跨阶段打回后继续保留被打回阶段之后的中间结论作为上下文事实。

## 上下文装配

每次调用 Agent 时，只装配当前阶段所需上下文：

- 已确认事实
- 未覆盖事实
- 当前阶段任务
- 当前阶段判断原则
- 当前角色卡
- 当前禁止事项
- 当前输出要求

不得把所有阶段判断原则一次性塞入上下文。

主策 Agent 使用同一基础身份，但在不同确认点注入不同判断原则：

- M1：`主策/M1-目标与边界判断原则.md`
- M2：`主策/M2-循环闭环判断原则.md`
- M3：`主策/M3-落地可执行性判断原则.md`
- M4：`主策/M4-交付一致性判断原则.md`

禁止用一个巨大主策 Role-Card 覆盖所有确认点。

## 打回记录

任何打回都必须记录：

- 源阶段
- 目标阶段
- 阻塞原因
- 必须修改的产物
- 是否影响已确认目标、循环或功能点

不允许只写“质量不够”“再优化一下”。

## 熔断计数

打回计数按 `(源阶段 -> 目标阶段)` 记录，不使用全局单一计数器。

- 同阶段循环打回：最多 2 次。
- 主策节点退回上一子阶段：最多 2 次。
- G6 跨阶段打回：同一目标阶段最多 1 次。
- 同一问题第三次出现：必须进入主策裁决。

工程实现可增加 `reason_hash` 区分同源不同问题，但标准只强制阶段路径计数和同问题重复识别。

## 主策裁决

触发熔断时，主策只能选择三类裁决：

- 补资料：明确需要补什么资料，回到 G1。
- 降级为方向验证稿：明确哪些问题作为方向验证保留项保留。
- 停止方向：说明当前方向为何无法继续成立。

## 分段落盘

每个主策确认点都必须形成可恢复 checkpoint：

- M1 通过后，落盘 G1/G2 产物、已确认目标、设计意图和边界。
- M2 通过后，落盘已确认循环。
- M3 通过后，落盘已确认功能点、规则、状态和 UE 要求。
- M4 通过后，落盘待验收文档草稿。
- G6 通过后，落盘最终交付版本。

推荐落盘位置：

`workspace/tmp/agent-checkpoints/gdd-write/<doc-id>/`

如果运行中断，应优先从最近一个已确认 checkpoint 恢复，而不是从头重跑。

## 方向验证稿与正式 GDD

方向验证稿与正式 GDD 的质量标准由 `多Agent设计文档判断原则/子Agent/交付验收原则.md` 定义。

调度层只处理交付分支：

- 方向验证稿在 G6 通过后可交付。
- 正式 GDD 在 G6 通过后，必须继续调用 `gdd-review`。
- `gdd-review` 通过前，正式 GDD 不得视为正式交付完成。
- 正式 GDD 阻塞项不得在调度层降级为普通待确认项。

## 交付前检查

交付前必须确认：

- 工作流已读。
- 调度规则已读。
- 当前阶段对应判断原则已读。
- 主策确认点均有明确结论。
- 打回计数未超限，或已完成主策裁决。
- 写作标准和输出模板已应用。
- 交付验收已通过。
- 正式 GDD 已通过 `gdd-review`。
