# 手段框架与结构依据候选原则

## 适用阶段

适用于 G3 方案推演。

## 判断目标

G3 从 M1 已锁定的设计目的、循环依据、当前缺口和探索边界出发，提出能够服务该目的的手段框架候选，并为每个候选推导设计对象、交付对象边界和结构依据。

G3 不默认资料中的原方案正确，也不直接拆正文功能或目录。不同候选可以使用不同规则路径，但都必须解释为什么服务同一个设计目的。

## 每个候选必须说明

- 手段框架：通过什么规则，把哪些行为、资源、状态或关系转成什么结果。
- 目的承接：该转化为什么能补足 M1 确认的循环缺口。
- 设计对象：哪些对象或关系贯穿主要规则并承载转化结果。
- 交付对象边界：后续需要定义哪些规则、状态、配置、展示、结算或功能级调用关系。
- 配套内容：哪些入口、页面、奖励包装或运营表现不承担核心转化，只能后续归位。
- 结构依据：后续应根据流程、状态、对象、资源、关系或调用中的哪类真实关系识别独立功能。
- 断点与依赖：哪里缺少输入、判断、结果、反馈或外部系统承接。
- 与资料原方案的关系：保留、调整或排除哪些内容，以及原因。

## 候选比较

G3 可以比较不同候选对设计目的的承接强度、规则复杂度、依赖、风险和交付范围，但不能替 M2 选择。

结构依据不是预先给定的正文目录，也不是固定类型模板；它只说明哪些真实关系必须在 G4 识别独立功能时被保留。

## 断点

以下情况必须显性标记：

- 手段框架只是功能、奖励、页面或活动清单，没有转化关系。
- 候选结果与 M1 设计目的无关，只能解释指标变化。
- 设计对象只能解释局部配置，不能贯穿核心规则。
- 有输入或行为，没有结果或状态变化。
- 有结果，没有玩家反馈或下游功能承接。
- 需要他人或外部系统回应，但缺少回应关系或功能级边界。
- 结构依据来自体验卖点或交付分类，而不是真实运行关系。

## 禁止事项

- 禁止修改 M1 已锁定设计目的、循环依据和探索边界。
- 禁止默认资料中的原方案正确。
- 禁止用功能清单或奖励列表代替手段框架。
- 禁止把入口、页面、配置、展示或结算反推为设计目的。
- 禁止直接生成正文目录或独立功能清单。
- 禁止替 M2 选择候选。
