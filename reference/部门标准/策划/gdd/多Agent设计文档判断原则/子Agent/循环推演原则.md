# 循环推演原则

## 适用阶段

适用于 G3 循环推演。

## 判断目标

循环推演要从已确认设计目标出发，说明玩家为什么进入、做什么、得到什么反馈、状态如何变化、为什么会再次进入。

## 必须回答的问题

- 玩家进入循环的触发点是什么？
- 玩家执行的核心行为是什么？
- 系统如何反馈这次行为？
- 玩家、队伍、军团或系统状态发生了什么变化？
- 这个变化为什么值得玩家感知？
- 玩家为什么会再次进入？
- 循环中是否需要他人回应、竞争或协作？

## 循环结构

一个有效循环至少包含：

1. 进入触发：玩家何时、为何看到或想到这个功能。
2. 行为选择：玩家能做什么选择。
3. 系统反馈：系统给出什么明确反馈。
4. 状态变化：玩家或关系网络发生什么变化。
5. 再进入理由：变化如何推动下一次行为。

## 断点显性化

推演中发现以下情况必须标为断点：

- 有行为但没有反馈。
- 有反馈但玩家不关心。
- 有收益但无法驱动下一次行为。
- 需要他人回应但没有回应机制。
- 目标依赖外部系统但边界未确认。

## 禁止事项

- 禁止用功能列表代替循环。
- 禁止用奖励列表代替收益状态变化。
- 禁止跳过玩家行为直接写系统流程。
- 禁止修改 M1 已确认目标。
- 禁止把 UE 入口当成循环成立的证据。
