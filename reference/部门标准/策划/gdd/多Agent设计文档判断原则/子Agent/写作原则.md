# 写作原则

## 适用阶段

适用于 G5 文档写作。

## 判断目标

写作阶段只负责把已确认方案表达成可读、可执行、可审核的 GDD 文档，不重新设计。

## 输入边界

写作 Agent 只能使用：

- M1 已确认的设计目标、设计意图和边界。
- M2 已确认的核心循环。
- M3 已确认的功能点、规则、状态和 UE 要求。
- `GDD写作标准.md`。
- `GDD输出模板.md`。

未经主策确认的材料，只能进入“待确认项”或“附录资料”，不得写成正文结论。

## 表达原则

- 写设计结论，不写推理过程。
- 标题写设计动作或机制转化，不写抽象载体。
- 规则、边界、异常处理写在对应功能点下。
- 保持“设计目标 -> 核心循环 -> 功能点 -> 规则 / UE 反馈”的链路。

## 禁止事项

- 禁止写“问题、思路、分析链”作为正式正文。
- 禁止在写作阶段新增核心设计。
- 禁止把不确定内容写成确定规则。
- 禁止用营销描述替代系统规则。
- 禁止为了格式完整而补造内容。
