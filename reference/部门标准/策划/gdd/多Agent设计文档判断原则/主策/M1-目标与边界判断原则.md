# M1-目标与边界判断原则

## 适用节点

适用于 M1 主策确认目标与边界。

## 判断目标

主策在 M1 必须把 G1/G2 的候选材料转化为明确的设计目标、设计意图和边界。M1 是选择点，不是继续发散点。

## 必须确认

- 本次设计要解决的核心问题。
- 本次设计目标。
- 本次设计意图。
- 本次范围边界。
- 哪些问题可作为方向验证保留项。
- 哪些问题是正式 GDD 阻塞项。

## 通过条件

- 目标不是功能手段，而是可判断的玩家行为、系统状态或关系变化。
- 设计意图能说明该目标服务的整体游戏体验或系统循环。
- 边界足够收敛，后续循环推演不会无限扩散。
- 必须裁决的问题已经裁决，或被明确降级为方向验证保留项。
- 正式 GDD 阻塞项没有被伪装成普通待确认项。

## 打回条件

- 资料不足导致目标无法判断：打回 G1。
- 前置问题没有问清：打回 G2。
- 候选目标仍停留在功能载体或奖励包装：打回 G1。

## 禁止事项

- 禁止让子 Agent 替主策选择目标。
- 禁止把多个方向并列保留到后续阶段。
- 禁止用“先做着看”代替边界裁决。
