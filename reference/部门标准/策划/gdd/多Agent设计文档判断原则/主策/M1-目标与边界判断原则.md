# M1-设计目的与边界判断原则

## 适用节点

适用于 M1 主策锁定设计目的与探索边界。

## 判断目标

M1 根据 G1 目的包和 G2 质询，裁决本次唯一设计目的。设计目的未成立，不得进入 G3。

M1 不确认手段框架、设计对象、交付对象或正文结构；这些结论必须在目的锁定后由 G3 提案、M2 裁决。

## 裁决顺序

```text
上级游戏框架 -> 相关循环 -> 当前缺口 -> 设计者意图 -> 设计目的 -> 探索边界
```

## 必须确认

- 本次设计所处的上级游戏框架。
- 与本设计直接相关的核心或系统循环。
- 当前循环缺口及其证据。
- 本次唯一设计目的：设计者希望这项设计在整体循环中承担的作用。
- 哪些资料属于非目的内容，后续不得回流为目的。
- G3 可以探索的范围，以及明确不进入本轮探索的范围。
- 仍然存在的不确定点及其是否阻塞 G3。

## 通过条件

- 设计目的能够由上级框架、相关循环、当前缺口和设计者上下文共同支撑。
- 设计目的不是指标结果、功能效果总结、既有方案、奖励包装或交付对象。
- 多个候选目的已经收敛为一个；若确属不同范围，已经明确本轮只处理哪一个。
- 非目的内容和探索边界明确，G3 不需要猜测本轮要解决什么。
- 关键证据的 `confirmed / inferred / unknown` 状态没有混淆。

## 打回条件

- 无法确认上级框架、相关循环或当前缺口：打回 G1 补资料。
- 关键质询未解决、候选目的仍互相冲突：打回 G2。
- 候选目的仍是活跃、留存、付费、消耗、参与人数等指标：打回 G1。
- 候选目的来自功能、奖励、入口、页面、配置、结算或既有方案：打回 G1。
- 资料实际包含多个不同设计范围且本轮边界未裁：停在 M1，由主策裁定范围。

## 禁止事项

- 禁止未锁定设计目的就进入 G3。
- 禁止把设计目标、设计意图或玩法目的重新建立为并列裁决层级。
- 禁止在 M1 预选手段框架、功能方案或正文结构。
- 禁止用“先做着看”代替目的和边界裁决。
- 禁止把方向验证当作放行错误目的的理由。
