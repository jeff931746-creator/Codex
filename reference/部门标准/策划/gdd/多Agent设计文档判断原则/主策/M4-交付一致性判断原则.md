# M4-交付一致性判断原则

## 适用节点

适用于 M4 主策确认文档一致性。

## 判断目标

主策在 M4 判断文档是否忠实表达 M1-M3 已确认方案。M4 不重新设计，只做一致性确认。

## 必须确认

- 正文是否忠实表达已确认玩法目的、手段框架、设计对象、交付对象边界、结构依据、交付结构和功能点。
- 需求目的是否只来自 M1 已确认的玩法目的。
- 需求目的是否被交付对象、系统口径、统计、接入、归属、互斥、计分、配置、展示或结算污染。
- 是否新增未经确认的目标、结构依据、交付结构或核心规则。
- 是否绕过手段框架，直接把功能清单、交付物、承载方式或配套内容写成主体。
- 章节顺序是否支持读者理解设计链路。
- 规则、状态、UE 是否写在对应功能点下。
- 主体章节是否来自 M3 已确认的交付结构。
- 主体章节是否已经落成可交付内容。
- 正文是否把设计推演词归位到对应规则、表现或验收关注点，而不是直接写成目录。
- 正文是否完成 G4-G5 正文语言降噪，没有混入内部判断语言、流程标签或工作口径。
- 正文是否根据内容选择自然表达形态，而不是机械套用内部检查项。
- 待确认项和阻塞项是否表达清楚。

## 通过条件

- 文档的内部证据链能对应“玩法目的 -> 手段框架 -> 设计对象 -> 交付对象 -> 结构依据 -> 交付结构 -> 主体节点 -> 规则 / UE 反馈”，但正文没有把推演过程写成目录或正文内容。
- 需求目的表达的是游戏关系、状态或结果，而不是功能手段或交付产物。
- 文档能让开发、UE、数值或测试判断各主体节点要实现、配置、展示、结算或验证什么。
- 正文没有暴露内部思考过程。
- 正文没有混入内部判断语言、流程标签或工作口径。
- 正文没有把“本节作用、适用对象、规则说明、判断方式、结果变化、玩家表现”等内部检查项机械写成固定标题。
- 未确认内容没有被写成确定结论。
- 文档满足进入 G6 交付验收的完整度。

## 打回条件

- 只是表达不清或章节错位：打回 G5。
- 仅存在内部判断语言、流程标签或工作口径污染：打回 G5，不回退 G1-G4。
- 需求目的写成交付对象、系统口径或正文结构：打回 G5；如果暴露 M1 分层错误，打回 M1。
- 文档暴露手段框架缺口：打回 G3；如果暴露 M1 裁决错误，打回 M1。
- 文档暴露落地缺口：打回 G4。
- 文档暴露结构依据缺口：打回 G3。
- 文档主体结构不来自已确认交付结构：打回 G4。
- 文档主体节点停留在抽象结构，无法指导开发落地：打回 G4。

## 禁止事项

- 禁止在 M4 新增核心设计。
- 禁止把写作润色问题升级成目标问题。
- 禁止让写作 Agent 自己决定方案取舍。
- 禁止放行机械模板化正文。
- 禁止放行混入内部判断语言、流程标签或工作口径的正文。
- 禁止放行只有设计判断、没有可交付内容的正文。
- 禁止放行需求目的被交付对象或系统口径污染的正文。
- 禁止放行绕过手段框架的正文。
- 禁止放行把设计意图、体验强度、风险高低、收益感知或策略卖点直接作为主体章节的正文。
