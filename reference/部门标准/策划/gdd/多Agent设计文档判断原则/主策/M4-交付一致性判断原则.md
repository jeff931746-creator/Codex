# M4-交付一致性判断原则

## 适用节点

适用于 M4 主策确认文档一致性。

## 判断目标

主策在 M4 判断文档是否忠实表达 M1-M3 已确认方案。M4 不重新设计，只做一致性确认。

## 必须确认

- 正文是否忠实表达已确认目标、循环和功能点。
- 是否新增未经确认的目标、循环或核心规则。
- 章节顺序是否支持读者理解设计链路。
- 规则、状态、UE 是否写在对应功能点下。
- 待确认项和阻塞项是否表达清楚。

## 通过条件

- 文档能清晰呈现“目标 -> 循环 -> 功能点 -> 规则 / UE 反馈”。
- 正文没有暴露内部思考过程。
- 未确认内容没有被写成确定结论。
- 文档满足进入 G6 交付验收的完整度。

## 打回条件

- 只是表达不清或章节错位：打回 G5。
- 文档暴露落地缺口：打回 G4。
- 文档暴露循环缺口：打回 G3。

## 禁止事项

- 禁止在 M4 新增核心设计。
- 禁止把写作润色问题升级成目标问题。
- 禁止让写作 Agent 自己决定方案取舍。
