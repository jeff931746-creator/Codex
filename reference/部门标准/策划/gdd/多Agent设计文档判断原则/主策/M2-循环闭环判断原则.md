# M2-手段与结构依据判断原则

## 适用节点

适用于 M2 主策裁决 G3 候选。

## 判断目标

M2 选择最能服务 M1 设计目的的手段框架，并确认与该手段匹配的设计对象、交付对象边界和结构依据。M2 不拆正文功能；独立功能由 G4 根据 M2 结论识别。

## 必须确认

- 手段框架是否清楚说明规则如何把输入转成结果。
- 该结果是否直接补足 M1 确认的循环缺口，而不是只带来指标变化。
- 设计对象是否贯穿核心规则并承载主要结果。
- 交付对象边界是否足以支持 G4 落地，又没有把页面、配置或包装升级为设计本体。
- 配套内容是否已经与核心转化关系分开。
- 结构依据是否来自真实流程、状态、对象、资源、关系或调用，而不是预设目录。
- 外部依赖和断点是否可以接受，哪些属于正式 GDD 阻塞项。

## 通过条件

- 已选择一个手段框架，并说明未选候选为什么不适合当前目的。
- 已确认设计对象、交付对象边界和结构依据。
- 手段框架、设计对象和结构依据之间没有断链。
- G4 可以据此识别独立功能，而不需要猜测目的或重新选择方案。
- 正式阻塞项没有被降级为普通待确认项。

## 打回条件

- 所有候选手段都无法服务设计目的：打回 G3；若暴露 M1 目的错误，回 M1。
- 候选只有功能或奖励清单，没有转化关系：打回 G3。
- 设计对象或交付边界无法承接手段：打回 G3。
- 结构依据是预设目录、体验卖点或交付分类：打回 G3。
- 目的本身需要改变：回 M1，必要时回 G1。

## 禁止事项

- 禁止在 M2 修改设计目的。
- 禁止在 M2 直接拆功能或正文目录。
- 禁止用功能数量、页面完整度或奖励丰富度代替手段成立。
- 禁止把统计、接入、配置、展示或结算等交付对象反推为目的。
- 禁止放行无法说明输入、规则和结果的方案。
