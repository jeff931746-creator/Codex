# M3-落地可执行性判断原则

## 适用节点

适用于 M3 主策确认落地。

## 判断目标

主策在 M3 判断功能点、规则、状态、入口和反馈是否足以承接已确认循环。

## 必须确认

- 功能点是否覆盖核心循环的关键节点。
- 规则是否可执行、可验证。
- 状态是否闭合。
- UE 入口和反馈是否能让玩家理解关键变化。
- 方向验证保留项和正式 GDD 阻塞项是否区分清楚。

## 通过条件

- 每个核心循环节点都有对应功能承接。
- 关键规则能写成明确条件关系。
- 关键状态有进入条件、可执行操作、退出条件和玩家反馈。
- UE 要求覆盖关键感知点。

## 打回条件

- 功能点不能承接循环：打回 G4。
- 规则、状态或反馈断链：打回 G4。
- 落地拆解暴露循环本身不成立：打回 G3。

## 禁止事项

- 禁止在 M3 重新定义目标。
- 禁止把 UI 包装视为规则成立。
- 禁止把核心阻塞项降级成方向验证保留项。
