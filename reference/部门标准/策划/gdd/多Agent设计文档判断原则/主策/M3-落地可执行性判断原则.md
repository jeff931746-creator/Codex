# M3-落地可执行性判断原则

## 适用节点

适用于 M3 主策确认落地。

## 判断目标

主策在 M3 判断 G4 是否把设计推演材料和 M1 已确认交付对象正确转译成交付结构，并判断功能点、规则、状态、入口和反馈是否足以支撑交付。

同时判断落地拆解是否来自已确认结构依据，而不是来自设计意图、体验强度、风险高低、收益感知、页面、配置、奖励、状态枚举、指标或局部规则清单。

M3 不重新定义玩法目的，也不允许交付对象反推需求目的。

## 必须确认

- 功能点是否覆盖已确认结构依据下的关键交付节点。
- 功能点是否覆盖 M1 已确认交付对象边界。
- 主体节点是否来自交付结构，而不是设计推演词的直接展开。
- 主体节点是否已经落成开发、UE、数值或测试能接住的交付内容。
- 规则是否可执行、可验证。
- 状态是否闭合。
- UE 入口和反馈是否能让玩家理解关键变化。
- 配置、奖励、状态枚举、UE、打点和公式是否挂回实际生效节点。
- 方向验证保留项和正式 GDD 阻塞项是否区分清楚。
- 落地内容是否没有把玩法目的拆成主体节点，也没有把交付对象写回需求目的。

## 通过条件

- 每个关键交付结构节点都有对应功能承接。
- 每个关键交付对象都有对应主体节点或归位说明。
- 每个主体节点都承担本文档交付结构中的明确职责。
- 每个主体节点都能说明具体要实现、配置、展示、结算或验证什么。
- 设计推演材料已经完成归位，没有直接变成正文目录。
- 附属内容没有错误升级为主体节点。
- 关键规则能写成明确条件关系。
- 关键状态有进入条件、可执行操作、退出条件和玩家反馈。
- UE 要求覆盖关键感知点。

## 打回条件

- 功能点不能承接结构依据：打回 G4。
- 功能点不能承接交付对象边界：打回 G4。
- 主体节点来自设计推演词或附属内容分类，而不是交付结构：打回 G4。
- 主体节点停留在抽象结构，开发无法判断要做什么：打回 G4。
- 规则、状态或反馈断链：打回 G4。
- 落地拆解暴露结构依据本身不成立：打回 G3。

## 禁止事项

- 禁止在 M3 重新定义目标。
- 禁止在 M3 重新定义玩法目的、设计对象或交付对象边界。
- 禁止把 UI 包装视为规则成立。
- 禁止放行把玩法目的拆成主体节点或把交付对象写成需求目的的落地结构。
- 禁止放行从设计意图、体验强度、风险高低、收益感知或策略卖点直接拆出的主体结构。
- 禁止放行由页面、配置、奖励表、状态枚举或指标拆出的主体结构。
- 禁止放行无法拆成开发/UE/数值/测试任务的抽象主体节点。
- 禁止把核心阻塞项降级成方向验证保留项。
