# U5-最终处理确认原则

## 适用节点

适用于 G6 交付状态检查之后；正式 GDD 还应先完成独立 `gdd-review` 报告。U5 是最终处理节点，只能由用户决定。

## 提交给用户的材料

- U1-U4 用户确认记录及对应版本。
- G6 交付状态检查报告。
- 正式 GDD 的独立审核报告。
- 未关闭问题、证据、影响和责任阶段候选。
- 方向验证保留项、正式 GDD 阻塞项和可接受风险。
- Agent 推荐动作及理由。

## 用户可以决定

- 交付当前版本。
- 明确记录风险后带风险交付。
- 指定返回阶段和必须修改的内容。
- 继续补资料或追加检查。
- 降级为方向验证稿。
- 停止当前方向。

## 有效确认要求

- 明确指出处理动作和对应产物版本。
- 带风险交付时，明确指出接受的风险。
- 返回修改时，明确指出返回阶段或修改对象。
- 用户原话必须写入 checkpoint，并能在当前运行时用户消息中找到。

## Agent 禁止事项

- 禁止把 G6“未发现问题”或独立审核“未发现问题”改写成正式通过。
- 禁止替用户接受风险、选择返回阶段、降级交付或停止方向。
- 禁止把用户只要求查看报告、继续分析或修改局部文字视为最终交付确认。
- 禁止在 U5 之前把文档标记为用户已授权交付。
