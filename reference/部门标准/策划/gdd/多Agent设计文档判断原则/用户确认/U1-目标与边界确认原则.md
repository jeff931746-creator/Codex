# U1-目标与边界确认原则

## 适用节点

适用于用户确认设计目的与探索边界。Agent 只整理 G1/G2 材料、指出冲突并给出推荐，不得替用户锁定目的或范围。

## 提交给用户的材料

```text
上级游戏框架 -> 相关循环 -> 当前缺口 -> 候选设计目的 -> 探索边界
```

材料必须包含：

- 上级游戏框架、相关循环和当前缺口及其证据状态。
- 候选设计目的，以及每个候选依赖的证据和前提。
- 非目的内容，防止功能、奖励、指标或包装回流为目的。
- 可选探索边界和明确不进入本轮的范围。
- 未解决问题、影响、选项和 Agent 推荐理由。

## 用户需要确认

- 本轮唯一设计目的，或明确要求继续保留哪些候选。
- 循环依据和当前缺口是否采用。
- 本轮探索边界与排除范围。
- 未确认事实是否允许作为风险继续，还是需要补资料。
- 下一步是进入 G3、返回 G1/G2 或停止。

## Agent 禁止事项

- 禁止替用户收敛候选目的、裁定范围或接受资料缺口。
- 禁止把推荐项记录为确认项。
- 禁止在用户确认前进入 G3。
- 禁止在 U1 预选手段、功能或正文结构。
