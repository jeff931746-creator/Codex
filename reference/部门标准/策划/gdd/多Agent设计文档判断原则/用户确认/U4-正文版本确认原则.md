# U4-正文版本确认原则

## 适用节点

适用于 Agent 完成 C4 一致性检查后，由用户选择和确认正文版本。C4 只报告差异、问题和风险；U4 只能由用户确认。

## C4 检查目标

- 正文是否忠实表达 U1 确认的设计目的、U2 选择的手段和结构、U3 确认的独立功能及规则归属。
- 是否新增未经用户确认的目的、结构、功能或核心规则。
- 主体章节是否以独立功能为单位，并保留触发、过程、状态变化和结果反馈。
- 权限、条件、次数、冷却、消耗、配置、反馈和异常是否归入实际生效功能。
- 正文是否以最少内容保留完整规则链；同一条件、资格、比例、结算或领取判断是否只在实际生效节点完整表达一次。
- 用户要求核心规则、简化版或精简版时，是否仍夹带概念解释、推导过程、重复示例或非关键异常。
- 是否混入内部判断语言、流程标签、验收依据或技术实现。
- 待确认项、阻塞项和模型优化差异是否清楚。

## C4 输出

C4 必须输出：

1. 与 U1-U3 一致的内容。
2. 新增、删失、错位、重复、结构污染和技术越界。
3. 每个问题的证据、影响和可选处理方式。
4. Agent 推荐版本及理由。
5. 明确标记“等待用户确认正文版本”。

C4 不得输出“通过”“打回”或替用户选择 G5 原稿、模型候选稿或修订稿。

## 用户需要确认

- 采用哪个正文版本，或需要哪些具体修改。
- 是否接受仍存在的非阻塞风险。
- 是否允许写入或覆盖用户指定的正式文档。
- 下一步进入 G6，还是返回 G5/G5-D/G4/U2/U1。

## 正文质量边界

- 正文只承载设计结论，不承载 U1-U4 记录、审核结论或流程状态。
- 功能完整不等于重复展开；G4 的完整性输入不得机械扩写成正文篇幅。
- 核心规则成立但正文重复、解释过量或信息层级失衡时，Agent 应建议返回 G5 压缩，不得擅自修改后代替用户确认。
- 过程关系应保留先后、分支、状态变化和角色交接；静态关系才使用表格。
- 正文只写设计层行为和功能级边界，不写接口字段、数据结构、日志、埋点、并发、存储、重试或监控。

## Agent 禁止事项

- 禁止替用户确认正文或覆盖正式文档。
- 禁止用“只是润色”绕过 U4。
- 禁止把 Agent 推荐版本标记为最终版。
- 禁止自行选择返回阶段或接受未关闭风险。
