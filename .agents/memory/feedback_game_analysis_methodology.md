# 游戏分析方法论短卡

用于游戏系统拆解、玩法方向判断、成熟产品新内容推导。

## 1. 系统拆解

不要先列功能。先问：**如果没有这个系统，游戏会在哪里出问题？**

每个功能按因果链分析：

`设计前提 -> 激活条件 -> 具体心理/行为机制 -> 玩家动作 -> 业务或体验结果 -> 失效条件 -> 相关系统耦合`

要求：

- 不用“归属感/竞争感”这类标签代替机制解释。
- 每个设计都要写失效条件：太弱坏在哪里，太强坏在哪里。
- 结论用 If-Then：适用前提、结论、反例或边界。

## 2. 独立玩法判断

判断一个玩法方向是否成立，过三层：

1. **独立性**：它能否单独成为一个成功玩法，而不是只服务别的系统？
2. **沉淀机制**：玩家投入沉淀在哪里？成果是否会永久积累，还是用完归零？
3. **验证闭环**：投入后是否能及时验证，验证结果是否指导下一次投入？

若核心需求互相冲突，方向可能不成立。例：要验证快就做消耗品，但消耗品没有沉淀；要沉淀就做装备，但验证周期变长。

## 3. 新方向推导

成熟产品的新方向必须从已有系统目的往外推，不从外部灵感硬塞。

步骤：

1. 列出已有系统，并标注资料是否完整。
2. 说明每个系统解决什么问题。
3. 找共同指向的底层逻辑。
4. 判断这条逻辑链走到哪了。
5. 推导下一步自然延伸，或判断需要开新轴。

区分：改变“玩家遇到什么”通常是已有变体；改变“玩家在做什么”才可能是新方向。

## 快速自检

- 是否从结构空洞出发，而不是功能清单？
- 是否写完整因果链和失效条件？
- 玩法是否通过独立性、沉淀、验证闭环三层？
- 新方向是否来自已有系统目的，而不是外部案例贴补？
