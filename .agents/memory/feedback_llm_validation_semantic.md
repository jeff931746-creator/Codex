# LLM 打标质量验证规则

## 背景

2026-05-18 验证 30 款任天堂游戏黄金标准时,用字面字符串匹配判分,得出命中率 50.6%,实际人类视角看 LLM 表现 80%+。

## 失败示例

| 黄金标准 | LLM 输出 | 字面判分 | 实际语义 |
|---|---|---|---|
| 战棋指挥+角色羁绊养成 | 战棋策略+角色养成 | ❌ 不匹配 | ✅ 同义 |
| 捕捉+培养+对战+探索 | 收集+回合制对战+开放世界探索 | ❌ 不匹配 | ✅ 同义 |
| 多人协作狩猎巨兽→拆解素材→锻造装备→挑战更强巨兽的循环 | 在奇幻生态中组队狩猎巨型怪物并用其素材锻造装备的共斗动作游戏 | ❌ 不匹配 | ✅ 描述同一件事 |
| 法庭推理+证物指认+辩护 | 证据收集+法庭辩论+证言质询 | ❌ 不匹配 | ✅ 同义 |

50.6% 的命中率被字面差异污染,误导后续 prompt 调优方向。

## 规则

**Why**: LLM 输出本质是自然语言,字面匹配把"同义不同字"误判为错,会让验证报告完全失真。

**How to apply**:

- 验证 LLM 打标质量时,**绝不用纯字符串匹配**判分
- 必须由独立 agent (主 agent 或 subagent) 做语义判分,逐条对比黄金标准与 LLM 输出,人类视角判断"实质是否一致"
- 判分维度: 是否描述同一件事/是否同一类游戏体验/关键概念是否对齐
- 字面差异(顺序/标点/句式/连接词)不应算错

## 例外

- 如果验证目标本身是"格式一致性"(比如要求 LLM 输出固定 JSON 字段顺序),才用字符串匹配
- 关键词数 ≥2 的 token 交集判分可作为粗筛,但不能作为最终判分
