# GDD 只写设计层、不写技术实现

GDD（需求功能文档）是**设计层**文档。写功能行为、玩家可见的系统响应、规则边界、委托的功能级契约；不写技术实现方案。

## 边界

**GDD 写（设计层）**：功能行为与流程；玩家可见响应（含离线/异常时玩家看到什么、能否继续、内容是否保留）；规则边界；委托的**功能级契约**（委托给哪个系统、传入什么意图/数据类别、期望什么类型结果、异常或对方未就绪时功能如何降级兜底）。

**GDD 不写（归开发文档）**：事务原子性/并发/锁；防重复或幂等机制；失败重试次数、补发队列、补偿流程；日志埋点；接口字段结构/数据类型/协议；存储/缓存/序列化。

**判断口径**：一条描述回答"玩家/系统在功能上发生什么"→ 写进 GDD；回答"工程上怎么保证它发生"→ 移出 GDD。

## 触发场景

写或审核任何 GDD 时：离线/断网只写玩家可见行为（重连后界面恢复、内容保留、能否继续），不写扣费原子性/重试/补发/日志；委托接口只写功能级契约，不写字段结构。
