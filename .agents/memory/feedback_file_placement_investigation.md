移动或判断文件归属前，必须完整调查文件的性质、创建背景和所有可能的目标目录，不能只基于文件名、日期或部分内容做判断。

**Why:** 2026-05-07 发生错误：将"养成培育方向_系统框架_2026-05-06.md"从 `research/` 根目录移动时，只看到 `research/资料/立项方法论/` 下有同日期文件，就假设它也属于那里。实际上该文件是立项预演阶段的系统框架设计，应该放在 `projects/10-立项预演/牧场收集/00-立项文档/`。

根本原因：
1. 没有追溯文件的创建背景和任务上下文
2. 没有检查 `projects/10-立项预演/` 下是否有对应项目
3. 只读了 `research/README.md`，没有全面调查所有可能的目标目录
4. 违反了"约束先行"和"调查优先"原则

**How to apply:**

移动文件前的完整调查清单：

1. **文件性质判断**：
   - 读取文件内容，判断它是方法论、立项文档、分析报告还是项目工作文件
   - 立项预演阶段的文档 → `projects/10-立项预演/{项目名}/00-立项文档/`
   - 可复用的方法论 → `research/资料/立项方法论/`
   - 完整立项提案 → `research/立项白皮书/`

2. **创建背景追溯**：
   - 查找同日期创建的相关文件
   - 检查是否有对应的项目目录
   - 确认文件是独立产物还是某个项目的一部分

3. **目标目录全面调查**：
   - 读取所有可能目标目录的 README
   - 查看实际目录结构和现有文件
   - 确认命名规范和组织方式

4. **验证判断**：
   - 如果文件内容提到具体项目名称或设计目标，优先放在项目目录
   - 如果是通用方法论或可复用结论，才放在 `research/资料/`

**禁止行为**：
- 只看文件名就判断归属
- 只看部分目录就做决定
- 基于"看起来相似"就放在一起
- 不调查就创建新目录
